# Architecture

## Kanban board

`.kanban/` in the project repo holds one markdown file per task, named `000001_nice_thing.md` (zero-padded number, slug capped at 4 words with the type word dropped). Flat YAML frontmatter (name, priority, state, worktree, issuer, complexity) plus # Summary, # Specs, # Notes sections. The complexity attribute (`trivial`, `simple`, `moderate` or `complex`) defaults to `moderate` and drives which per-complexity LLM config entry and reviewer-pass cap apply. The library writes files only; the orchestrator daemon is the sole git committer for `.kanban/` paths, at two points only: creation in backlog, and done. Edits in between stay uncommitted and land in the one done commit.

States: backlog, to-do, doing, to-review, reviewing, to-merge, merging, to-live-test, live-testing, done.

## Orchestrator

`src/orchestrator.ts` is a non-LLM daemon. Start it with the `orchestrator_start` tool (or `node src/orchestrator.ts --root <project>`). One daemon per project: the lockfile is `.kanban/.orchestrator.lock`.

- Watches `.kanban/` (fs.watch) and rescans every 10 s. The `orchestrator_poke` tool touches `.kanban/.poke` for an immediate scan and agent scheduling: the poke's scan bypasses the backlog quiet gate, because a poke is the PM's explicit "I am done editing, schedule now".
- backlog: promoted automatically, on every scan and poll: every backlog task whose blockedBy refs all point at satisfied blockers (done tasks, or tasks in the live test: to-live-test or live-testing), whose openQuestions section is empty and whose file has no conflict markers moves to to-do, all schedulable tasks at once (unchained tasks run as parallel lanes). A board-wide quiet gate (`backlogIdleMinutes`, default 1; 0 disables) defers all promotion until every task file on the board has sat untouched that many minutes: the PM may still be creating or chaining a batch of tasks (specs, blocker chains, open questions), so any fresh task-file mtime defers the whole promotion, except the daemon's own writes (state transitions, blocker drops), which do not count: a blocker reaching done still promotes its dependents in the same scan. When a blocker reaches done or enters the live test (to-live-test/live-testing), the daemon drops its ref from every task that listed it in the same scan or poll, so blockedBy always lists unsatisfied (to-merge/merging) blockers only.
- to-do: creates `.worktrees/<type>/<num>-<short-slug>` (e.g. feat/1-nice-thing) from the task, sets the worktree attribute, spawns a Developer, moves to doing. Unlimited lanes; the blockedBy chain serializes what must serialize.
- to-review: spawns a Reviewer in the worktree, moves to reviewing. After `reviewerCap.<complexity>` successful reviewer runs (0 for trivial, 1 for simple, 2 for moderate, 3 for complex by default) the task force-advances to to-merge. A trivial task (cap 0) advances on the first sweep without spawning a reviewer. The Reviewer keeps its own state decision: approval sets to-merge, fixes go back to to-review.
- to-merge: the orchestrator's merge queue. The merge waits while the task's own agent is still alive, and at most one merger runs project-wide. A failed merge writes an attempt marker and retries after the task sat idle in to-merge for `retryIdleMinutes` (default 1).
- merging: a merger is resolving a conflicted rebase. The orchestrator runs the merges itself: it rebases the task branch onto the base branch (the root checkout's current branch, resolved live per operation) in the worktree, and on a conflict spawns the merger there to resolve and conclude the replayed commit (`git rebase --continue`, then the merger runs the full test suite in the worktree and reports failures in the task's Notes; it makes no state moves); then it fast-forwards the base to the branch from the project root (`--ff-only`, so no merge commit is created and main history stays linear). The merger's successful finish moves the task back to to-merge and the next sweep retries. A failed fast-forward (the base moved, a dirty root checkout) requeues the task in to-merge; the retry re-runs a fresh rebase onto the moved base followed by the fast-forward.
- to-live-test: reached after the orchestrator fast-forwarded the base to the branch; the worktree branch head already is the merged commit. The daemon routes a task whose branch is not merged into the base, or that has no worktree, back to to-merge first. Otherwise it spawns a Live-tester in the task worktree and moves to live-testing.
- Liveness poll: each agent's exit code is recorded, and a successful finish (exit 0) moves the task forward: the orchestrator owns the move (doing to to-review, merging to to-merge, live-testing to done); only the Reviewer keeps its state decision, and an exit 0 with the task still in reviewing is left for the PM. A crash (non-zero or missing exit code) moves the task back one step (a dead Developer goes back to to-do for a fresh run, reviewing to to-review, live-testing to to-live-test, merging to to-merge). Capped at 5 respawns per task; past the cap the respawn waits for the retry idle cooldown (`retryIdleMinutes`, default 1; 0 disables) before the agent spawns again.
- done with a worktree: the orchestrator fast-forwarded the base to the branch before the live test set done. The worktree lives until done: the orchestrator removes the worktree (the only worktree deletion point), deletes the merged branch and commits the task file (the done commit). done without a worktree: the orchestrator commits the task file at the next rescan. The done commit is skipped when the file has nothing uncommitted.
- On the sweep that moves one or more tasks to done, the daemon queues ONE report for the PM session in `.kanban/.reports/<sortable-timestamp>.md` (atomic tmp+rename write): the done tasks (name and shortName), the tasks the sweep scheduled (the backlog promotions, with their new state), per finished task its live-test findings (the tasks whose issuer attribute is that task's number, each with its name and its # Open questions section), and instructions for the PM. Files older than the 1 h delivery cutoff are pruned on every sweep.
- Report delivery: the extension consumes the queue in the PM session. Every session watches `.kanban/.reports/` from session_start (same lifecycle as the done toasts), but only the session whose cwd is the repo root consumes reports (the git-topology gate of the hub-candidacy rule; a worktree session shares the board through the `.kanban` symlink and stays silent). Consumption claims the oldest report by rename to `<name>.claiming`, sends it to the chat as a `board-report` message (`triggerTurn` when the session is idle, `deliverAs: "followUp"` when busy) and deletes the claimed file; a second root session loses the rename and never double-sends. On session start at the repo root the queue is drained: reports younger than the cutoff are delivered oldest first, older ones are deleted. A process death between claim and send is cleaned by the orchestrator prune.
- A task file with unresolved merge conflict markers is left untouched: the daemon spawns no agents, rewrites no attribute, and commits nothing for it until the merger or the user resolves the conflict.

### Board mirror to origin

Every mirror commit is best-effort pushed to `origin` as `refs/heads/meta/kanban` (only that ref; failures are logged, never fatal). The push needs SSH access to origin for the daemon user (a known_hosts entry and a deploy key); without it the mirror stays local and a fresh-clone bootstrap on another machine cannot work. After 3 consecutive failed pushes the daemon logs one warning (repeated only after a push succeeds again), visible in `.kanban/.logs/orchestrator.log`.

## Web dashboard

With `webUi.enabled: true` in the global config (`$XDG_CONFIG_HOME/se-llm-team/se-llm-team.json`, or `~/.config/se-llm-team/se-llm-team.json` when `XDG_CONFIG_HOME` is unset; the legacy `~/.pi/agent/se-llm-team.json` is a read-only fallback when the neutral file is absent), the orchestrator daemon serves a read-only dashboard at `http://<host>:<port>` (default `http://localhost:4242`): one column per task state, cards with a priority chip, and a popup with the full task (attributes and rendered body). The board is re-read on every request and the page refreshes itself every 5 s. A failed start (port taken) is logged and the pipeline continues. The page footer shows the serving hub's identity (`pid`, code checkout, `commit`), so a stale-code hub or a failover is visible at a glance; the same payload is at `GET /api/hub`.

The hub registry (`se-llm-team-hub.json`) and the election lock (`se-llm-team-hub.lock`) live in the same neutral config directory. A registry left by old code under `~/.pi/agent/` copies to the neutral path once at hub start (best effort). The lock is taken only at the neutral path: when a live process holds the legacy lock, the daemon logs a warning that an old-code daemon may still serve the hub, then continues.

Only daemons rooted at a main checkout can win the hub election and bind the port: a linked git worktree checkout can hold old code, so its daemon registers with the hub and never serves the ui. Candidacy is git topology (the per-worktree git dir differs from the common dir), not a path rule, so a worktree created anywhere (not just under `.worktrees/`) stands down. During a production restart the dashboard is briefly down instead of being served by old code. A daemon rooted in a task worktree exits itself when its task reaches `done` or is gone (checked at startup and on every sweep), so no stale worktree daemon lingers to hold the lock or contest the port.

Both checks run inside each daemon's own code. A daemon started from a worktree checkout before this change does not run them, so it can still win the election and hold the port. After you upgrade, kill the old worktree daemons one time: run `pgrep -af orchestrator.ts` and kill each process whose `--root` contains `.worktrees` (for example: `pkill -f 'orchestrator.ts.*--root .*/\.worktrees'`; the pattern does not match a daemon at the project root). New worktree daemons run the current code and exclude themselves, so this residue does not come back.
