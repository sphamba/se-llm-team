# developer: append project-specific guidance for this role below (e.g. how to run the project, how to live-test) so future agents of your kind start faster.

- Tests are plain assert-style ESM scripts, no framework: `node tests/<file>.test.ts` per file, `npm test` for the suite.
- To intercept src module internals from a test (fs calls, hooks inside a function), spawn a child with `--require <preload.cjs>`: patches to `require("node:fs")` propagate to ESM named imports only when installed before the first import; an in-process patch never does (facade bindings resolve at first import).
- Deterministic interleaving control in orchestrator tests: drive `rescan(root, cfg)` and `poll(root, stallMinutes)` directly (import `rescan` from `../src/orchestrator/pipeline.ts`, `poll`/`loadConfig` from the facade; temp HOME via `mkdtempSync` + `loadConfig`; `cfg.agent = <stub>`), instead of relying on daemon timing races. A stub that `Atomics.wait`s ~1s keeps a spawned agent alive across the next synchronous call. Temp scripts outside a package need the `.mjs` extension; when a fixture file must keep a specific name (e.g. `orchestrator.ts` for cmdline matching), drop a `package.json` with `{"type": "module"}` next to it instead, else node loads the `.ts` as CJS and it dies at the first import.
- To tell a flake from a regression: `git stash push`, run the failing suite at HEAD, `git stash pop`. Fix test-race flakes at the root cause: gate the fixture write against the racing machinery (e.g. an openQuestions-backed task is never promoted).
- Comments in src avoid em/en-dashes; use colons, commas, parentheses, hyphens.
- Live-test artifacts: daemon log `.kanban/.logs/orchestrator.log` (also daemon stdout), PM reports `.kanban/.reports/*.md` (one per sweep with a done transition, oldest first by name).
