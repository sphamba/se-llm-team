# developer: role guidance

Durable, task-agnostic facts for the developer role. Task-specific findings belong in the task's `# Notes`.

## Settle once, then act

- Task text can quote stale numbers: trust on-disk state, confirm with one `wc`/`grep`, then act. Settle each design point in one ladder pass, record the decision in `# Notes`, re-open only on new evidence. When a second deliberation ends in the same open question as the first, stop thinking: take the cheapest reversible option, record it, act. A decision recorded in `# Notes` beats a trade-off re-derived from scratch.
- Do one recon pass, then stop: read each relevant function whole (size the range to the function; a truncated read that hides a tail forces a re-read), and record findings (state transitions, imports, helper signatures, commit semantics) in `# Notes` before writing code. Re-reading a settled function or re-grepping a settled name is waste: consult the note.
- Run every acceptance check once, batched into one command, before the commit. Copy the spec's grep/wc pipelines verbatim. Ground unfamiliar symbol names with one search from read output or import lines (a guessed name returns zero matches and, fed into sed as line numbers, a sed error); confirm a path exists before grepping it.

## Shared board files have concurrent writers

- `.kanban/` is live shared state: other pipelines' runs rewrite board files at any moment; a file that reads differently later is another writer's output, not your regression. Check for an active writer once, measure a live shared file once in the final settle batch, and never enter a wait-poll loop against a file another agent owns. Deleting a board file survives only after the `meta/kanban` mirror advances past it; when it must outlast a daemon restart, commit it out-of-band via the project's `commitKanban` from a `tests/` scratch script, then stop.

## Repo, build and orchestrator map

- No build, no typecheck: `.ts` runs directly through node's type stripping (Node >= 24); the assert suites are the only check. `npm test` (glob loop), `npm run test:changed`, or standalone `node tests/<area>/<file>.test.ts`. Inventory: `docs/development.md`. Never run two suites at once: shared `.pids`, ports, fixture HOMEs. pnpm on the read-only worktree mount prints `ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK` — benign.
- Orchestrator internals: task sweeps, the reviewer-run cap with its `.reviewer-armed` marker, and `doneCleanup` live in `src/orchestrator/pipeline.ts`; `poll()` lives in `src/orchestrator/liveness.ts`, not pipeline.ts; worktree/branch naming (`slugWorktree`) in `src/kanban.ts`; prompt rendering and spawn logging in `src/orchestrator/spawn.ts`. A reviewer exit-0-with-own-state-move consumes a reviewer run; when the cap is exhausted on a re-review arrival, the sweep force-merges. Read pipeline.ts once end to end and note the transitions before designing a daemon-path test.

## Suite layout and harness

- Helpers live in `tests/helpers.ts` (imported by `tests/orchestrator/*` and `tests/tools.test.ts`; webui and efficiency-analysis are standalone groups). In `tests/orchestrator/*`, HERE is that dir: src imports `../../src/*.ts`, helpers `../helpers.ts`, repo root `join(HERE, "../..")`. A `MODULE_NOT_FOUND` path is dead: never re-guess it. `src/webui/page.ts`'s PAGE is one template literal: a regex inside it loses its backslash; asserts on served text match the built PAGE, and a page.ts edit goes live only after a daemon restart.
- Model a new test on the nearest sibling part in the same file (locate parts by their `// --- part` marker, never by line number) and copy its setup line-for-line: `mkdirSync(kanbanDir(root), { recursive: true })` must precede any board JSON write, else the suite fails with ENOENT. Before adding a block, grep that file once for planned local names against its import lines; new module-level symbols tests import need `export` at declaration.
- Stub and pin discipline: a stub emits each snapshot exactly once — a snapshot in both branches of a conditional double-fires the count; expected multi-line strings use real `\n` escapes in the literal. Wording pins against `agents/*.md`: grep tests/ for the current phrases first (merge, spawn, split, promote and doctor tests pin prompt text), copy the prompt's exact casing, or normalize with `toLowerCase()` on both sides.
- Prefer deterministic interleaving over daemon races: drive `rescan`, `poll` and `promoteBacklog` directly with a temp-HOME config. Daemon sweeps are asynchronous: after a stub moves a task, gate downstream log-line asserts (for example the `merged` line from `doneCleanup`) on the suite's waitFor — an immediate assert after killing the daemon races the sweep. Side effects of spawned stubs are also written asynchronously: gate with waitFor. Wait loops over spawned processes must sleep (~50 ms) between checks, or a busy spin blocks the event loop and the SIGCHLD reaper never runs. Never probe a suite failure with a scratch `console.log` if a waitFor or the printed assert values can answer it; if forced, know daemon output has embedded newlines, so `grep -o` and `sed -n 's///p'` capture only the first line — extract the segment with a node one-liner.

## When a run goes red

- A test or helper written in this run is the first suspect when its suite fails: re-read it on disk and scratch-print the helper's return before any production-code theory. The first Error line names the assert file:line: read it and its printed values as data, then act. Grep production code only after the new test code is proven innocent. Run the owning scoped suite for red, fix the test first, then the code: every extra red run is a full suite pass.

## Shell, environment and fixture isolation

- Run discipline: redirect suite output to a file and capture the exit code in the same command (`setsid bash -c 'npm test > /tmp/o 2>&1; echo $? > /tmp/o.exit'`), never pipe through head/tail — the first Error line is the whole red diagnosis. `grep -c` exits 1 on zero matches (append `|| true` in chains, but never guard a check whose result you need). Verify a grep matched before feeding its line numbers to sed — an empty range is a sed error. Kill a fixture daemon by pid from ss/lsof, never `pkill -f` (it can match your own bash -c command line, exit 143).
- Fixture HOME is mandatory for global state: `~/.pi`, `~/.config` and `~/.gnupg` are read-only bind mounts, so run global-state tests and smoke daemons on a fixture HOME with `XDG_CONFIG_HOME` set or deleted, plus `--no-webui` — else the daemon reads the global config, binds the production webui port and holds the global hub lock. `process.env.X = undefined` sets the string "undefined" — use `delete process.env.X`. Keep fixture boards inert: long `--rescan-seconds`/`--poll-minutes`, probe tasks in done (backlog auto-promotes and spawns real agents).
- In a task worktree, `.kanban`, `SPECS.md` and `AGENTS.md` are symlinks into the main checkout: writing through them edits it. Never stage or commit board files (git calls these paths "beyond a symbolic link"); board history is `git log meta/kanban -- <file>`. Fixture repos need `git -c commit.gpgsign=false commit`.
- Shell traps: one argv over 131072 bytes fails with E2BIG; `ls -R` skips hidden dirs — use find; `find` does not traverse a symlinked dir — use a trailing slash or `-L`; never patch with sed (delimiter clashes leave broken syntax) — use the edit tool; temp scripts that import `../src` live under `tests/`, never /tmp; run `node --check` (unguarded) on a generated script before its first run.

## Edits and task-file bookkeeping

- edit calls take an array of `{oldText, newText}` hunks, never a JSON string; hunks must not overlap (a failed batch applies nothing — keep batches small); anchor each hunk on the shortest unique line copied verbatim from read output. End-of-file appends go through a heredoc, never a tail-anchored edit. When the spec asks for prose a sibling file already carries, mirror it verbatim with only names swapped.
- Task files carry `# Summary`, `# Specs`, `# Notes` (some add `# Acceptance`/`# Open questions`): append facts under the existing `# Notes` heading (never a second one), assumptions under `# Open questions`. Commit messages state only verified facts — diff old vs new before claiming parity. Board task files are `.kanban/<NNNNNN>_<slug>.md`, zero-padded to 6 digits: look them up by padded glob.

## Verification and blocked tasks

- Settle the whole verdict in one start batch, then never re-derive it: the landed-on-main pair, the blockers' board state read by zero-padded name, absence greps, one `pgrep -f analysis-run`, and the suite decision: no diff and HEAD unchanged from a green run means no suite run; HEAD moved means one scoped suite — a spec line naming the full suite never re-opens this decision, and mid-run deliberation about test scope is re-work. Match subtask commits by subject, not SHA: worktree SHAs can be rebased before merge.
- A recorded blocked verdict is final for the run: re-running ancestry checks, re-reading board files, or re-reading SPECS.md to re-confirm facts already in your `# Notes` is re-work; consult the note instead. No run-history forensics from pid files, mtimes or log ordering. If a concurrent run on your own task is alive (fresh pid, growing log), stop and report the conflict in `# Notes`; do not co-edit the task file.
- When an acceptance check fails on a file you are prohibited from editing (a doctor-owned notes file, a board file), decide once and report in `# Notes`, and stop; never hand-fix a prohibited file, never re-measure to see whether it healed. A broad acceptance grep matches prose as easily as code: read the matched line before rewording prose to dodge your own grep — a false positive is fixed by narrowing the grep, a real violation by one edit, then the grep runs once more in the final batch.
