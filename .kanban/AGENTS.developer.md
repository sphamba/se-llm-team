# developer: role guidance

Durable method for the developer role. The spawn prompt owns the numbered steps. `SPECS.md` in the cwd is a symlink to the task file in the main checkout. Put task findings in `# Notes`. Report durable method findings in `# Notes`, never in this file or `AGENTS.md`.

## Contract

- Read `SPECS.md` once, fully, and keep it. `# Specs` and `# Acceptance` are the contract. `# Context` is background. The Specs beat this file and the spawn prompt. Copy a Specs value verbatim into the code and the pins. Decide each open choice once, before the first edit. Change only what the Specs and Acceptance require. Update a comment that the change makes false in place, keep its task tag, and do not add a second comment. Work in the worktree and never change task states or edit the board.
- Test the premise in one bash call: `grep -rnF '<symbol>' src/ tests/`, `git rev-parse --short HEAD`, `git rev-parse --short main`, and `grep -H '^state:'` on the card files that a Specs line or `blockedBy` names. A Specs line that names another task is a dependency even when `blockedBy` is empty. Do not read card bodies, neighbouring cards, or git history.
- Dependency decision: if a named dependency is not `done`, or its change is absent from `main` after one `git merge --ff-only main`, the premise is false. If the missing dependency blocks your whole change, end the run with one `# Notes` line that names the card, its state, the shas, and the empty probe. If your own seam exists and the fix is independent, deliver the source fix and its pin, then name the missing dependency as the reason acceptance cannot run. Never implement, debug, or revert the dependency's work.
- When two Specs or Acceptance lines cannot both hold, stop. Prove it with the smallest probe, write one `# Notes` line that names both lines and the file that owns the conflict, and end the run.
- Never run `pnpm test` or `pnpm test:changed`, even when `# Acceptance` names `pnpm test`. Run the suites the Specs name and write one `# Notes` line that the full suite is the live tester's gate.

## Orientation

- Your worktree keeps the base it was created with, so it can predate a dependency that merged later. Compare the two shas once, with separate calls: `git rev-parse --short HEAD` and `git rev-parse --short main`. On a mismatch run `git merge --ff-only main`, and nothing else. Never inspect other branches, merge bases, `git log` history, or a `meta/kanban` ref.
- Budget 4 tool calls from the Specs read to the first edit: one `read` of the file you change, one `read` of the suite that pins it, one bash that greps the anchors. A no-edit run gets the same budget to its Notes write. At the budget, stop and write the smallest form that satisfies the Specs. `read` a whole file with a generous `limit`, and use `sed -n 'A,Bp'` only for a Specs-cited range. Never read a range twice. Never `cat` a whole file, and never run `pwd`, `git status` or `git diff`. `cd` only for the repo root or the board.
- Cap the design pass at one thought per branch point: if you reach the same answer twice, stop thinking and act. For a test harness, stub, fixture, daemon or spawn, copy the idiom from the nearest existing test that already does that job. Do not enumerate alternatives for a mechanism the repo has. A probe is only for a value the Specs do not give: one `node -e`, print every value, copy the output. If a probe and the Specs disagree, the Specs win. Hand a web question or a wide sweep to one subagent. Do not spawn one for a small, local change.
- Repo map: `src/orchestrator/pipeline.ts` (sweeps, caps, promotion, `doneCleanup`), `liveness.ts` (`poll()`, which also calls `promoteBacklog`), `src/kanban.ts` (task files, worktree naming, `PRIORITY_RANK`), `src/tools.ts` (registration), `spawn.ts` (prompt render, spawn log), `main.ts` (watch, timers), and `src/webui/{logpane,payload,page,board}.ts`. Tests import `../../src/*.ts` and `../helpers.ts`, with the repo root at `join(HERE, "../..")`. `tests/helpers.ts` exports `fixture()` (a git repo in a temp dir), `roleStub`, `runDaemon()`, `waitFor()`, `mirrorSubjects()`, `showTip()`, `cleanupAll()`, `daemons`, and `cleaned`. `grep -n 'export' tests/helpers.ts` lists them all. `PAGE` is one template literal, so a function interpolated into it must be self-contained: module constants and regexes do not travel in, and a regex literal written inside loses a backslash. For a page test, reuse the file's extraction idiom (`function name(...) { ... }` plus `new Function`) and assert the returned value. A page change needs a daemon restart for a visual check. There is no DOM library: extend the element stub in the file you touch and give it every property the code path reads (`tagName`, `style`, `innerHTML`, `appendChild`, `children`, both sibling getters). Do not add a dependency.

## Edits

- Split a rewrite across small `edit` calls, about four hunks each. A call applies all hunks or none, so one bad hunk discards the whole payload. Never put a hunk in a batch when an earlier hunk in that same batch creates its anchor. Never swap `oldText` and `newText`. When a hunk is rejected, cut the payload on the retry instead of resending the same shape, and narrow to one hunk per call until it lands.
- Anchor each hunk on the shortest unique line from your read. Whitespace must match exactly. Write every comment complete on the first pass. After a success result every hunk landed: do not re-read the file, do not run `git diff`, and do not re-grep a literal you just wrote. For a large insertion, append with `cat >> file <<'EOF'` and read the appended block back. When you add or remove a module-level symbol, grep the consumer import line in the same breath: `grep -rn 'from "./<module>.ts"' src/`.

## Tests

- Run a suite as `node tests/<area>/<file>.test.ts`. Areas: `tests/kanban`, `tests/orchestrator`, `tests/webui`, `tests/efficiency-analysis`, plus the loose `tests/*.test.ts` and `index.test.ts`. There is no build and no typecheck, and `node --check` cannot parse TypeScript. The pin's subject decides the order, not the task-type prefix: a pin for behavior that does not exist yet runs red first, even under a `refactor:` name, and a pin for output that must stay unchanged passes before the edit. `complexity: trivial` skips red-first but still adds any pin the Specs name.
- Run exactly the suites `# Acceptance` names plus the suite file you edited, in one foreground call. Capture the output in a variable and print `exit=`. Never pipe `node` through `tail` or `head`, because the pipe status hides a failing suite. Never `grep -m` the output. Read the first `AssertionError` line, implement to green, and do not re-run for the message. Green means done.

  ```
  fail=0
  for f in tests/a.test.ts tests/b.test.ts; do
    out=$(node "$f" 2>&1); c=$?
    printf '%s exit=%s\n' "$f" "$c"
    if [ $c -ne 0 ]; then printf '%s\n' "$out" | tail -n 25; fail=1; fi
  done
  exit $fail
  ```

- A suite that spawns daemons (`spawn`, `sweep`, `merge`, `daemon`, `hub`, `poll`) can fail at a wait or timeout that your edit cannot reach. At the first such failure, prove the base in the same call: stash your edit, run that suite, restore the stash. Still red at the same wait, with the same timeout line, means pre-existing. Write one `# Notes` line that names the suite and the wait. Do not re-run the same suite before the base proof, and do not read `pipeline.ts`, `liveness.ts`, `board.ts`, or `tests/helpers.ts` to explain it. Then finish the source fix and its pin. A pin placed after an earlier failing wait never runs. Do not move the suite's earlier wait. Prove the pin's value with a throwaway `tests/_scratch.test.ts` that copies the nearest daemon test setup and asserts the same seam, or state in one `# Notes` line that the pin is unreachable until the dependency lands.
- Scratch test recipe: copy `fixture()`, `runDaemon()`, `waitFor()`, `cleaned`, and `daemons` from the nearest daemon test. Keep the daemon in a `try` and call `daemon.kill("SIGTERM")` in `finally`, or the child keeps node alive and the run hangs. Run it as `timeout 140 node tests/_scratch.test.ts > /tmp/scratch.out 2>&1; echo exit=$?`, then read `/tmp/scratch.out`. Delete the scratch file in the same call as the last run. A running daemon buffers its log, so never poll that log or a temp directory from a background job.
- Run at most one suite at a time. A daemon test leaves detached `fake-agent.cjs` children behind when a run is killed or times out. Check with `pgrep -af '[f]ake-agent'`, kill each pid with `kill <pid>`, then run the suite once, serially, with a generous timeout. Never use `pkill -f`.
- A pin exists or it does not: `grep -rnF '<exact string>' tests/` answers it, and empty output is final. No pin and none named: no test edit. A shared literal ripples into every exact-output assert: count the sites with `grep -rn '<literal>' tests/ | wc -l`, replace all in one `perl -pi -e` pass, then count the new literal and compare.

## Shell traps

- Chain recon reads with `;`, not `&&`, or put the step that can fail last. End a recon call with `; true`. A bare `grep` with no match exits 1 and fails the whole call. Grep the bare symbol name, not a guessed declaration form: `grep -n 'export const fixture'` misses `export function fixture`, so use `grep -n 'fixture'`. An empty variable silently removes its argument, so `git -C "$dir"` with an empty `dir` runs in the cwd and `ls "$dir"/x` lists `/x`: assert the variable is non-empty, or set it with a literal fallback. Never truncate the only useful output with `head`. Escape a literal dot in `grep` (`\.`), or it matches unrelated text. One argv over 131072 bytes fails with E2BIG. `ls -R` skips hidden directories, so use `find`, and `find` does not follow a symlinked directory, so add a trailing slash. A running daemon buffers its log, so `grep` and `tail` on it return nothing until the process exits. Never background a suite to poll its log or its temp directory: capture with `> file 2>&1` in one foreground call and read the file after it exits. Never run `pkill -f <pattern>`: the pattern matches your own `bash -c` command line and kills the call with exit 143. Use `pgrep -af` and `kill <pid>`.

## Delivery and board

- Write `# Notes` before the commit, then make one commit so the notes and the code land together. Stage only source, test, and doc files, never the board or `AGENTS.md`. Refer to the commit by subject, not by SHA. End the same call with `git show --stat --oneline HEAD`, then stop. No source or test diff means no commit: the `# Notes` write is the deliverable. Do not make an empty commit. The final chat message is one short line with the outcome and the next action, not a second copy of the notes.
- Resolve the board from the symlink: `board=$(dirname "$(readlink -f SPECS.md)")`. `.kanban`, `SPECS.md`, and `AGENTS.md` are gitignored symlinks into the main checkout. Append `# Notes` through `SPECS.md` with `cat >>`, under the existing `# Notes` heading. One `##` subheading there is enough. Never write `AGENTS.md`, and never stage board files. `.kanban/` is live shared state with concurrent writers, so read a file once and do not poll it. Fixture HOME is required for global state: `~/.pi`, `~/.config`, and `~/.gnupg` are read-only, delete with `delete process.env.X` and never `= undefined`, and drop `XDG_CONFIG_HOME` too so the hub lock resolves inside the temp HOME. Keep fixture daemons inert with long rescan and poll intervals and `--no-webui`, and use `git -c commit.gpgsign=false commit` in fixture repos.
