# developer: role guidance

Durable, task-agnostic facts for the developer role. Task-specific findings belong in the task's `# Notes`, not here.

## Repo, build and checks

- No build step, no dependencies, no typecheck: sources are `.ts` run directly through node's type stripping (Node >= 24 required); the assert suites are the only check. `npm test` (glob loop over `index.test.ts`, `tests/*.test.ts`, `tests/*/*.test.ts`), `npm run test:changed` (change-mapped scoped run), or one suite standalone: `node tests/<area>/<file>.test.ts`. Inventory and commands: `docs/development.md`. Never run two suites at once — they share `.pids`, ports and fixture HOMEs.
- pnpm is pinned via the `packageManager` field (corepack resolves it); there is no committed lockfile. pnpm on the read-only worktree mount prints `ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK` — benign noise, the suite still runs and passes.

## Suite layout and harness

- Shared helpers live in `tests/helpers.ts` (imported by `tests/orchestrator/*` and `tests/efficiency-analysis/*` only; the webui and kanban group files are standalone, and efficiency-analysis has its own local `helpers.ts`). In `tests/orchestrator/*` and `tests/webui/*`, HERE is that dir: src imports are `../../src/*.ts`, shared helpers `../helpers.ts`, repo-root paths `join(HERE, "../..")`.
- The webui suite is the group files under `tests/webui/` (board, logpane, agentlog, page, hub); there is no `tests/webui.test.ts`. Extend the group file whose scenario block covers the change; grep for anchors, line numbers drift.
- `src/webui/page.ts`'s PAGE is one template literal served as the whole client: a regex written inside it loses its backslash (write `\\.` where the served string must hold `.`), and asserts on served text match the built PAGE string, not source bytes. The daemon serves the PAGE built at startup, so a page.ts edit goes live only after a daemon restart.
- Before adding a test block to an existing suite, grep that file once (fixed-string) for every planned local name and helper use against its import lines: a reused name or missing import costs a red run and a rename round. New module-level symbols that tests import need `export` at declaration. Re-locate test parts by their `// --- part` marker, never by line number.
- Prefer deterministic interleaving over daemon timing races: import and drive `rescan(root, cfg)`, `poll(root, stallMinutes)` and `promoteBacklog(...)` directly from an area file, with a temp-HOME config (`mkdtempSync`; set or delete `XDG_CONFIG_HOME` in the test env). Free a concurrency-cap slot by setting a holder task to a non-counted state, not by removing it.
- Order a new test's steps so each assert that reads state comes before the call that mutates or clears that state. Asserts on the meta/kanban mirror right after a done transition race the sweep (the fold-in commit can land one sweep later): gate the mirror read with the suite's existing waitFor.
- A wait loop over spawned processes must sleep between checks (about 50 ms): a synchronous busy spin blocks node's event loop, the SIGCHLD reaper never runs, and a zombie's `/proc` entry keeps pidAlive true forever. Wait for the exit file AND a dead pid, both.

## Shell and environment traps

- Run suites with output redirected to a file and the exit code captured in the launch command (`setsid bash -c 'npm test > /tmp/o 2>&1; echo $? > /tmp/o.exit'`); never pipe a live run through head or tail. The first Error line in the redirected log is the whole red diagnosis. `grep -c` exits 1 on zero matches: a 0 count from a failure-shaped grep is a pass — append `|| true` in chained commands.
- Background runs give no completion notification: sleep between log polls and do other work meanwhile. Kill a fixture daemon by pid taken from ss/lsof, never `$!`; `pkill -f` can match your own bash -c command line and kill the shell (exit 143).
- `~/.pi`, `~/.config` and `~/.gnupg` are read-only bind mounts on this machine: keep global-state tests on a fixture HOME, and always set or delete `XDG_CONFIG_HOME` in the test env or the production config leaks in. `process.env.X = undefined` sets the string "undefined" — use `delete process.env.X`.
- In a task worktree, `.kanban` is a symlink to the main checkout's board, `SPECS.md` a symlink to your task file, and `AGENTS.md` a symlink to this role-notes file: writing through them edits the main checkout. git calls `.kanban/...` paths "beyond a symbolic link" — never stage or commit board files; the daemon mirrors `.kanban/` onto `refs/heads/meta/kanban` via git plumbing, so `git log -- .kanban/` prints nothing and board history is `git log meta/kanban -- <file>`.
- The global `~/.gitconfig` forces `commit.gpgsign=true` (this checkout's `.git/config` opts out, and worktrees share it); any fresh fixture repo needs `git -c commit.gpgsign=false commit` or signing fails with "gpg failed to sign the data". Stage first: a bare commit with unstaged edits fails.
- The kernel rejects a single argv over 131,072 bytes with E2BIG (node reports a child 'error' event and the child never starts). `ls -R` skips hidden dirs — use find. Never patch files with sed (delimiter clashes leave broken syntax): use the edit tool. Temp scripts that import `../src` live under `tests/`, never /tmp; a name-critical `.ts` fixture outside a package needs a `{"type":"module"}` package.json next to it; run `node --check` on a generated script before the first execution.
- Smoke daemons must be isolated: fixture HOME, deleted or isolated `XDG_CONFIG_HOME`, plus `--no-webui` (or `SE_LLM_TEAM_NO_WEBUI=1`) — otherwise the smoke daemon reads the global config, binds the production webui port and holds the global hub lock. Keep fixture boards inert with long `--rescan-seconds`/`--poll-minutes` and seed probe tasks in state done (a backlog task auto-promotes and spawns real agents).

## Edits and task-file bookkeeping

- edit calls take an array of `{oldText, newText}` objects, never a JSON string; hunks must not overlap (a failed batch applies nothing — keep batches small); anchor each hunk on the shortest unique line copied verbatim from read output, grepped for uniqueness (0 or 1 hits) before the call. A long truncated line is never an anchor. End-of-file appends go through bash (`cat >>`/heredoc), never a tail-anchored edit.
- Task files carry `# Summary`, `# Specs`, `# Notes` (some add `# Acceptance` or `# Open questions`): completed-work facts append under the existing `# Notes` heading (never a second one), assumptions and open points under `# Open questions`. Commit messages state only verified facts — diff old vs new output before claiming byte-identity or behavior parity.
