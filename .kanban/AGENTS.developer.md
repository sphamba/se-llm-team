# developer: role guidance

Durable method for the developer role. The spawn prompt owns the numbered steps. `SPECS.md` in the cwd is a symlink to the task file in the main checkout. Put task findings in `# Notes`. Report durable method findings in `# Notes`, never in this file or `AGENTS.md`. The Specs beat this file and the spawn prompt.

## Contract

- Read `SPECS.md` once, fully, and keep it. `# Specs` and `# Acceptance` are the contract, `# Context` is background. Decide each open choice once, before the first edit. Change only what the Specs and Acceptance require. Work in the worktree, and never change task states or edit the board.
- Test the premise in one bash call: `grep -rnF '<symbol>' src/ tests/`, `git rev-parse --short HEAD`, `git rev-parse --short main`, and `grep -H '^state:'` on the card files a Specs line or `blockedBy` names. A Specs line that names another task is a dependency even when `blockedBy` is empty. Do not read card bodies, neighbouring cards, or git history.
- Dependency decision: a named dependency that is not `done`, or whose change is absent from `main` after one `git merge --ff-only main`, makes the premise false. If it blocks your whole change, end with one `# Notes` line that names the card, its state, the two shas, and the empty probe. If your own seam exists and the fix is independent, deliver the source fix and its pin, then name the dependency as the reason acceptance cannot run. Never implement, debug, or revert the dependency's work. When two Specs or Acceptance lines cannot both hold, stop, prove it with the smallest probe, write one `# Notes` line that names both lines and the file that owns the conflict, and end the run.
- Never run the full suite. `pnpm test`, `pnpm test:changed`, and `node scripts/test-changed.mjs` are the same full run even when `# Acceptance` names one: the script expands `src/kanban.ts`, `src/orchestrator.ts`, and `agents/*.md` to whole areas and falls back to every suite on an unknown path. Run the suites you edited plus the suites the Specs name, and write one `# Notes` line that the full suite is the live tester's gate.

## Worktree and branch

- Compare the two shas once: `git rev-parse --short HEAD` and `git rev-parse --short main`. On a mismatch run `git merge --ff-only main`, and nothing else. When it refuses because local changes would be overwritten, run `git stash push -u; git merge --ff-only main; git stash pop` in one call. Never inspect other branches, merge bases, `git log`, or a `meta/kanban` ref.
- A worktree can ship uncommitted test files: those are the task's pins. Read them before the first source edit, one `read` with a generous limit, or `git diff -- <path>` once for a long file to see only the new cases. They name the seams and the expected values, so do not delete, rewrite, or re-derive them. Keep them, run them, and ship them in your commit.

## Design

- Source map: `src/orchestrator/pipeline.ts` (sweeps, caps, promotion, `doneCleanup`), `liveness.ts` (`poll()`, `promoteBacklog`, the `LANES` table), `src/kanban.ts` (task files, worktree naming, `PRIORITY_RANK`, `blockedBy` parse and cycle guard), `src/tools.ts` (registration), `spawn.ts` (prompt render, spawn log), `main.ts` (watch, timers), `src/webui.ts` and `src/webui/{index,logpane,payload,page,board}.ts`. The `merging` and `integration-testing` states are project-wide single lanes with one pid entry each, not one per task. `src/webui/page.ts` is one template literal, so an interpolated function must be self-contained; there is no DOM library, so extend the element stub in the file you touch and add no dependency.
- A gate on task eligibility is the first statement of the per-task block in the sweep that selects the candidate: before `ensureWorktree`, any state write, any spawn, and any run bookkeeping such as `consumeReviewerRun`. One gate per entry point that can start work, never a patch downstream. Put the shared predicate in `src/kanban.ts` next to the field parser, export it, and import it in the pipeline.
- `blockedBy` is a comma string of `#<n>` refs plus literal tokens that name no card. `blockedNums` parses each part with `parseInt` and drops `NaN`, so a literal token vanishes from every number-based check: a hold or gate rule must test the tokens, and a cycle guard over numbers must ignore literals on purpose.
- Cap the design pass at one thought per branch point: if you reach the same answer twice, act. Copy the idiom from the nearest existing test, stub, fixture, daemon or spawn that already does the job. A probe is only for a value the Specs do not give: one `node -e`, print every value, copy the output; on a disagreement the Specs win. Hand a web question or a wide sweep to one subagent, never a small local change. Budget about four tool calls from the Specs read to the first edit, and anchor every read on a name, not a line number: `grep -n 'function sweepToMerge' <file>`, then `read` from that offset, because a merge shifts every line and a Specs range is a hint, not a coordinate.

## Edits

- Split a rewrite into small `edit` calls, about four hunks each: a call applies all hunks or none. Before the call, `grep -cF '<anchor>'` on each anchor; a count above 1 means add the line above it. Never batch a hunk when an earlier hunk in that batch creates its anchor, and never swap `oldText` and `newText`. Whitespace must match exactly. On rejection, cut the payload to one hunk per call instead of resending the same shape. After a success result every hunk landed: do not re-read the file, diff it, or re-grep a literal you just wrote. For a large insertion, append with `cat >> file <<'EOF'` and read the block back. When you add or remove a module-level symbol, grep the consumer import line in the same breath: `grep -rn 'from "./<module>.ts"' src/`. Update a comment that the change makes false in place, keep its tag, and do not add a second comment.
- Four canonical sites carry behavior: `skills/se-llm-team/SKILL.md` (the PM's view), `docs/architecture.md`, `docs/agents-and-tools.md`, and `agents/<role>.md` (the role prompt). Grep the sentence the change makes false and edit it with one hunk per file. Never count line numbers from the Specs, and never state one rule twice in one file. Tests assert substrings of the rendered role prompt, so a pure addition to `agents/*.md` breaks no pin: `grep -rn '<phrase>' tests/` coming back empty is the proof.

## Tests

- Run a suite as `node tests/<area>/<file>.test.ts`. Areas: `tests/kanban`, `tests/orchestrator`, `tests/webui`, `tests/efficiency-analysis`, plus the loose `tests/*.test.ts` and `index.test.ts`. There is no build and no typecheck, and `node --check` cannot parse TypeScript. `tests/helpers.ts` exports `fixture()`, `runDaemon()`, `waitFor()`, `roleStub`, `argvStub`, `deadStub`, `cleaned`, `daemons` and `cleanupAll()`; `grep -n 'export' tests/helpers.ts` lists them all. `tests/orchestrator/integration.test.ts` is one numbered part list: read its argv/import header and its tail once, append the next `// --- part N:` block, and reuse its local `configFor(root, agent, maxParallel)` and `stopLane(root)`. The pin's subject decides the order, not the task-type prefix: behavior that does not exist yet runs red first, even under a `refactor:` name; output that must stay unchanged passes before the edit. `complexity: trivial` skips red-first but still adds any pin the Specs name.
- Prove your own pin red before the source edit, in one call: `git stash push -- <the source paths you edited>`, run that one suite, expect the new assertion to fail, then `git stash pop`. Run the pin's own suite, not its whole area. Then run the named suites in one foreground call, never piping `node` through `tail` or `head`, because the pipe status hides a failing suite:

  ```bash
  fail=0
  for f in tests/a.test.ts tests/b.test.ts; do
    out=$(node "$f" 2>&1); c=$?
    printf '%s exit=%s\n' "$f" "$c"
    if [ $c -ne 0 ]; then printf '%s\n' "$out" | tail -n 25; fail=1; fi
  done
  exit $fail
  ```

- A suite that spawns daemons (`spawn`, `sweep`, `merge`, `daemon`, `hub`, `poll`, `integration`) can fail at a wait or timeout your edit cannot reach. At the first such failure, prove the base in the same call: stash your source edit, run that suite, restore the stash. The same wait with the same timeout line means pre-existing: write one `# Notes` line that names the suite and the wait, and do not read `pipeline.ts`, `liveness.ts`, `board.ts` or `tests/helpers.ts` to explain it. A pin placed after an earlier failing wait never runs, and you must not move that wait.
- Run at most one suite at a time. A killed or timed-out run leaves detached `fake-agent.cjs` children: `pgrep -af '[f]ake-agent'`, then `kill <pid>` for each; never `pkill -f`. Scratch test: copy `fixture()`, `runDaemon()`, `waitFor()`, `cleaned` and `daemons` from the nearest daemon test, keep the daemon in `try`/`finally` with `daemon.kill("SIGTERM")`, run `timeout 140 node tests/_scratch.test.ts > /tmp/scratch.out 2>&1`, read the file after it exits, and delete the scratch file in the last run call. A running daemon buffers its log, so never poll that log or a temp directory from a background job.
- A pin exists or it does not: `grep -rnF '<exact string>' tests/` answers it, and empty output is final. Read the first `AssertionError` line, implement to green, and do not re-run for the message. No pin and none named: no test edit. A shared literal ripples into every exact-output assert: count the sites with `grep -rn '<literal>' tests/ | wc -l`, replace them in one `perl -pi -e` pass, then count the new literal and compare.

## Shell traps

- Chain recon reads with `;`, not `&&`, or put the step that can fail last, and end a recon call with `; true`; a bare `grep` with no match exits 1 and fails the call. Grep the bare symbol, not a guessed declaration: `grep -n 'fixture'` finds `export function fixture`. An empty variable silently removes its argument, so `git -C "$dir"` with an empty `dir` runs in the cwd and `ls "$dir"/x` lists `/x`: assert it is non-empty or set a literal fallback. Never truncate the only useful output with `head`, escape a literal dot in `grep`, and never `grep -m` a test run. One argv over 131072 bytes fails with E2BIG. `ls -R` skips hidden directories, so use `find`; `find` does not follow a symlinked directory, so add a trailing slash.

## Delivery and board

- Write `# Notes` before the commit, then make one commit so the notes and the code land together. Stage only source, test and doc files, never the board or `AGENTS.md`. Refer to the commit by subject, not by SHA. End the same call with `git show --stat --oneline HEAD`, then stop. No source or test diff means no commit: the `# Notes` write is the deliverable, and you never make an empty commit. The final chat message is one short line with the outcome and the next action.
- Resolve the board from the symlink: `board=$(dirname "$(readlink -f SPECS.md)")`. `.kanban`, `SPECS.md` and `AGENTS.md` are gitignored symlinks into the main checkout. Append `# Notes` through `SPECS.md` with `cat >>`, under the existing heading, and one `##` subheading is enough. Never write `AGENTS.md` and never stage board files. `.kanban/` is live shared state with concurrent writers: read a file once, do not poll it. Fixture HOME: `~/.pi`, `~/.config` and `~/.gnupg` are read-only, so `delete process.env.X` and never `= undefined`, drop `XDG_CONFIG_HOME` too, keep fixture daemons inert with long rescan and poll intervals and `--no-webui`, and use `git -c commit.gpgsign=false commit` in fixture repos.
