# developer: role guidance

Durable method for the developer role. The spawn prompt owns the numbered steps. `SPECS.md` in the cwd is a symlink to the task file in the main checkout. Put task findings in `# Notes`. Report durable method findings in `# Notes`, never in this file or `AGENTS.md`. The Specs beat this file and the spawn prompt.

## Contract

- Read `SPECS.md` once, fully, and keep it. `# Specs` and `# Acceptance` are the contract, `# Context` is background. Decide each open choice once, before the first edit. Change only what the Specs and Acceptance require. Work in the worktree, and never change task states or edit the board.
- One tool call is one full model turn, and a thinking turn often costs a minute. Batch the recon into 2 or 3 bash calls that end with `; true`. Aim for the first edit by turn 8, and never pass turn 15 with no edit. When you reach the same answer twice, act: write the pin or the edit and let the suite answer. A probe is only for a value the Specs do not give: one `node -e`, print every value, copy the output. On a disagreement the Specs win.
- Test the premise in one bash call: `grep -rnF '<symbol>' src/ tests/`, `git rev-parse --short HEAD`, `git rev-parse --short main`, and `grep -H '^state:'` on the card files a Specs line or `blockedBy` names. A Specs line that names another task is a dependency even when `blockedBy` is empty. Do not read card bodies, neighbouring cards, or git history.
- Decide the dependency once, then never revisit it. A named dependency that is not `done`, or whose change is absent from `main` after one `git merge --ff-only main`, makes the premise false. If it blocks your whole change, end with one `# Notes` line that names the card, its state, the two shas, and the empty probe. If the Change names a file you can edit without the dependency's work, your seam exists: deliver the source fix and its pin, then write one `# Notes` line that names the dependency as the reason acceptance cannot run. Never implement, debug, or revert the dependency's work, and never re-derive this decision from a later suite failure. When two Specs or Acceptance lines cannot both hold, stop, prove it with the smallest probe, write one `# Notes` line that names both lines and the file that owns the conflict, and end the run.

## Worktree

- On a sha mismatch run `git merge --ff-only main`, and nothing else. When it refuses because local changes would be overwritten, run `git stash push -u; git merge --ff-only main; git stash pop` in one call. Never inspect other branches, merge bases, `git log`, or a `meta/kanban` ref. A worktree can also ship uncommitted test files: those are the task's pins, so read them before the first source edit (`git diff -- <path>` once for a long file), keep them, run them, and ship them in your commit.

## Design

- Source map: `src/orchestrator/pipeline.ts` (sweeps, caps, promotion, `ensureIntegrationTask`, `doneCleanup`), `liveness.ts` (`poll()`, `promoteBacklog`, the `LANES` table), `src/kanban.ts` (task files, worktree naming, `PRIORITY_RANK`, `blockedBy` parse and cycle guard), `src/tools.ts` (registration), `spawn.ts` (prompt render, spawn log), `src/orchestrator/main.ts` (watch, timers), `src/pid.ts` (`pidPath`, `pidEntry`, `pidAlive`, `killTree`), `src/orchestrator/log.ts` (`log`, `logPath`), `src/webui.ts` and `src/webui/{index,logpane,payload,page,board}.ts`. The `merging` and `integration-testing` states are project-wide single lanes with one pid entry each, not one per task. `src/webui/board.ts` holds the renderer helpers that `page.ts` composes, so extend the nearest helper and add no dependency.
- A gate on task eligibility is the first statement of the per-task block in the sweep that selects the candidate: before `ensureWorktree`, any state write, any spawn, and any run bookkeeping such as `consumeReviewerRun`. One gate per entry point that can start work, never a patch downstream. Put the shared predicate in `src/kanban.ts` next to the field parser, export it, and import it in the pipeline.
- `blockedBy` is a comma string of `#<n>` refs plus literal tokens that name no card, such as `user`. `hasUserHold` tests the token, and `blockedNums` drops every non-numeric part, so a hold or gate rule must test the tokens and a cycle guard over numbers must ignore them on purpose.
- A location in the Specs is a hint about the seam, not a coordinate. When the named part, file or line cannot hold the assertion, put it at the nearest seam that can, do not ask the user, and state the deviation in one `# Notes` line. Anchor every read on a name, not a line number: `grep -n 'function sweepToMerge' <file>`, then `read` from that offset, because a merge shifts every line. Copy the idiom from the nearest existing test, stub, fixture or spawn that already does the job. Hand a web question or a wide sweep to one subagent, never a small local change.
- To make a task-file write throw on purpose, `chmodSync` that file to `0o444` before the sweep and restore `0o644` after it. Tests run as a non-root user here, so the write fails with `EACCES`. If `id -u` is 0, use another trigger. Assert the hook's log line and the state that must survive, then run the pin. Do not trace the mirror, commit or board code to validate the trick: the suite answers it.

## Edits

- Split a rewrite into small `edit` calls, about four hunks each: a call applies all hunks or none. Before the call, `grep -cF '<anchor>'` on each anchor; a count above 1 means add the line above it. Never batch a hunk when an earlier hunk in that batch creates its anchor, and never swap `oldText` and `newText`. Whitespace must match exactly. On rejection, cut the payload to one hunk per call instead of resending the same shape. After a success result every hunk landed: do not re-read the file, diff it, or re-grep a literal you just wrote. For a large insertion, append with `cat >> file <<'EOF'` and read the block back. When you add or remove a module-level symbol, grep the consumer import line in the same breath: `grep -rn 'from "./<module>.ts"' src/`. A shared literal ripples into every exact-output assert: count the sites with `grep -rn '<literal>' tests/ | wc -l`, replace them in one `perl -pi -e` pass, then count the new literal and compare.
- Four canonical sites carry behavior: `skills/se-llm-team/SKILL.md` (the PM's view), `docs/architecture.md`, `docs/agents-and-tools.md`, and `agents/<role>.md` (the role prompt). Grep the sentence the change makes false and edit it with one hunk per file. Never count line numbers from the Specs, and never state one rule twice in one file. Tests assert substrings of the rendered role prompt, so a pure addition to `agents/*.md` breaks no pin: `grep -rn '<phrase>' tests/` coming back empty is the proof.

## Tests

- Run a suite as `node tests/<area>/<file>.test.ts`. Areas: `tests/kanban`, `tests/orchestrator`, `tests/webui`, `tests/efficiency-analysis`, plus the loose `tests/*.test.ts` and `index.test.ts`. There is no build and no typecheck, and `node --check` cannot parse TypeScript. `tests/helpers.ts` exports `fixture()`, `runDaemon()`, `waitFor()`, `roleStub`, `argvStub`, `deadStub`, `cleaned`, `daemons` and `cleanupAll()`; `grep -n 'export' tests/helpers.ts` lists them all. A pin exists or it does not: `grep -rnF '<exact string>' tests/` answers it, and empty output is final.
- Never run the full suite. `pnpm test`, `pnpm test:changed`, and `node scripts/test-changed.mjs` are the same full run even when `# Acceptance` names one: the script expands `src/kanban.ts`, `src/orchestrator.ts`, and `agents/*.md` to whole areas and falls back to every suite on an unknown path. Run the suites you edited plus the suites the Specs name, and write one `# Notes` line that the full suite is the live tester's gate. Run the cheapest suite that can show the pin: a spawn or daemon suite waits on poll cycles and is much slower than the integration suite.
- `tests/orchestrator/integration.test.ts` is one numbered part list: read its argv/import header and its tail once, append the next `// --- part N:` block, and reuse its local `configFor(root, agent, maxParallel)` and `stopLane(root)`. Assert a daemon log line by reading `<root>/.kanban/.logs/orchestrator.log` with `readFileSync`, as the spawn and merge suites do. Assert a live run with `pidEntry(root, name)` plus `pidAlive(pid, disc)` from `src/pid.ts`, sampled once after `waitFor` records the spawn, never by timing.
- The pin's subject decides the order, not the task-type prefix: behavior that does not exist yet runs red first, even under a `refactor:` name; output that must stay unchanged passes before the edit. `complexity: trivial` skips red-first but still adds any pin the Specs name. A coverage pin must pass at once, because the behavior already exists and the Acceptance allows it: prove it non-vacuous with one source mutation. Patch one line with `python3` and `assert s.count(old) == 1`, run the pin's suite, expect the new assertion to fail, then `git checkout -- <file>` in the same call. Never `git stash push -- <test file>` to prove a test-only pin red, because the stash removes the pin.
- A suite that spawns daemons (`spawn`, `sweep`, `merge`, `daemon`, `hub`, `poll`, `integration`) can fail at a wait or timeout your edit cannot reach. Prove the base only when you edited source that suite loads: stash that source, run the suite, restore the stash. A suite you did not edit cannot fail because of you, so no base proof is necessary there. The same wait with the same timeout line means pre-existing: write one `# Notes` line that names the suite and the wait, and do not read `pipeline.ts`, `liveness.ts`, `board.ts` or `tests/helpers.ts` to explain it. A wait failure prints its reason line first, so read the head of the dump, not the tail. A pin placed after an earlier failing wait never runs, and you must not move that wait. Run one suite at a time, because a killed or timed-out run leaves detached `fake-agent.cjs` children: `pgrep -af '[f]ake-agent'`, then `kill <pid>` for each, never `pkill -f`.

## Shell traps

- Chain recon reads with `;`, not `&&`, or put the step that can fail last, and end a recon call with `; true`; a bare `grep` with no match exits 1 and fails the call. Grep the bare symbol, not a guessed declaration: `grep -n 'fixture'` finds `export function fixture`. An empty variable silently removes its argument, so `git -C "$dir"` with an empty `dir` runs in the cwd and `ls "$dir"/x` lists `/x`: assert it is non-empty or set a literal fallback. Never truncate the only useful output with `head` or `tail`, escape a literal dot in `grep`, and never `grep -m` a test run. One argv over 131072 bytes fails with E2BIG. `ls -R` skips hidden directories, so use `find`; `find` does not follow a symlinked directory, so add a trailing slash.

## Delivery and board

- Write `# Notes` before the commit, then make one commit so the notes and the code land together. Stage only source, test and doc files, never the board or `AGENTS.md`. Refer to the commit by subject, not by SHA. End the same call with `git show --stat --oneline HEAD`, then stop. No source or test diff means no commit: the `# Notes` write is the deliverable, and you never make an empty commit. The final chat message is one short line with the outcome and the next action.
- Resolve the board from the symlink: `board=$(dirname "$(readlink -f SPECS.md)")`. `.kanban`, `SPECS.md` and `AGENTS.md` are gitignored symlinks into the main checkout. Append `# Notes` through `SPECS.md` with `cat >>`, under the existing heading, and one `##` subheading is enough. Never write `AGENTS.md` and never stage board files. `.kanban/` is live shared state with concurrent writers: read a file once, do not poll it. Fixture HOME: `~/.pi`, `~/.config` and `~/.gnupg` are read-only, so `delete process.env.X` and never `= undefined`, drop `XDG_CONFIG_HOME` too, keep fixture daemons inert with long rescan and poll intervals and `--no-webui`, and use `git -c commit.gpgsign=false commit` in fixture repos.
