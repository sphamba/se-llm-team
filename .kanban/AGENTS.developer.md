# developer

Project-specific guidance for the developer role. Facts here are verified: trust them without re-probing (#226).

## Task start

- Judge the diff size before the read set. For a one-line or small fix (a label, a color, a chip, a condition), the read set is the one helper and its test, plus one `cat` of the task file (no head-then-cat re-read of it: #239 blocks 1-2). No knowledge-base search, no extra source files, no caller sweeps beyond the grep that names the helper (#227, #226). For colors, mirror the nearest existing pattern and go straight to the test edit, then the source edit (#226, #240 ran this recipe clean). One grep for the old value across src and docs is the allowed extra sweep for a color pin (#240 block 8). Comments fall under "add nothing unrequested": no deliberation block over updating unrelated comments (#239 block 17).
- Locate before you read. In a long file (page.ts, a big test file), grep the selector, assert text, or function name for offsets first, then one read per hit. No blind offset slices: #238 blocks 4-7 read four guessed slices before the block 9 grep found the same anchors.
- A formula or geometry change (scale factor, cap, clamp) gets its constants in one pass (factor, cap, floor), written once. Compute expected test strings with one node one-liner that replicates the formula, never repeated hand arithmetic in thinking: #238 blocks 12, 14 spent two thinking blocks re-deriving one clamp and recomputing the same path strings.
- Add the failing assertion first for behavior changes, run the suite once, then fix. The failing run is the before-proof: never re-verify pre-fix behavior by hand or live afterwards (#227).
- Exemption: alignment tasks that pin already-shipped wording or bytes. "Pin the shipped X" in a spec means a literal expected string, never a file read inside the test (that is circular). No source edit, no failing run: extract the rendered text, embed it as a literal, assert equal, run the suite once (#228).
- Make each decision once, in the thinking block where it first arises, and plan the whole run in one pass (read list, edit list, check command), then act: an intention-only thinking block with no command is wasted budget (#228). Never open a second design pass: #230, #232, #237, and #239 blocks 8+11 re-drafted the same assertion, placement and regex in two consecutive thinking blocks before the first edit, and #240 block 7 re-weighed regex extraction against a literal match before the first edit. If you catch yourself re-weighing two approaches, take the simpler one and edit. For a value pin whose exact value the spec decides, the default is a literal `includes` of that value with the spec's channels, no regex and no extraction one-liner (#240 blocks 7, 9). No thinking block for basic language semantics (a for-of `const` binding is loop-scoped, #239 block 22) or for acceptance-criteria boilerplate (see the scoped-suite rule): the passing suite and the recipe settle them.
- Design a new orchestrator smoke part from the nearest existing part: copy its harness, note the sweep order and log-index rules once from the pipeline read, then write the test (#229: six thinking blocks before the first edit).
- Budget your own test harness like product code. #234 spent 60 of 155 blocks (39%) debugging the new test file's wait helpers, against about 10 for the fix itself. A probe beats a guess: after two failed hypotheses, write the minimal isolated script instead of re-reading the same code (see Test-harness waits).

## Scope and process discipline

- Read each target file once, then edit. One read pass plus greps covers a sweep. Do not re-scan or re-derive findings for files already read (#225). #234 read tests/orchestrator.test.ts in six passes before writing one test. Edit anchors are built from read output already in context: do not re-read lines you hold to rebuild an anchor (#237).
- Build an edit anchor as an exact copy of the read output, leading whitespace included, and start it at a non-whitespace character when the target lines are indented. On a match failure, one byte check of the exact lines (`cat -A`), then one retry. Never re-read the whole file (#231).
- edit tool calls take edits as an array of {oldText, newText} objects, never a JSON string: a stringified array is rejected and costs a retry (#237 block 192).
- An ambiguous or contradictory spec point gets one reading: the simplest one that satisfies the acceptance criteria (for a contradiction, read the callers first). Decide once, implement, and record the choice as an assumption under # Open questions in SPECS.md (#224, #228).
- Settle placement in one decision, then edit. A repo-specific sentence removed from agents/*.md or SKILL.md goes as one bullet into .kanban/AGENTS.<role>.md in the main checkout, under the closest section (#225).
- SPECS.md bookkeeping is fixed: completed-work facts go under the task's # Notes; assumptions and open points under # Open questions. If the task body has no # Open questions heading, add it with the assumptions in one edit; never re-read the task body to check for the heading first (#230). Task-body edits: the deviation note goes under the affected requirement, delete answered open questions, mark confirmed assumptions, one edit call (#228).
- Anchor every SPECS.md edit with unique surrounding sentence text, never a bare heading: "# Notes" can occur more than once in SPECS.md (#238 block 26 re-derived this). If unsure, one grep to confirm uniqueness, then edit in the next call (#225, #227). An end-of-file append may anchor on the trailing "# Notes" only when a full read of the file proved it unique (#239 block 25); draft the notes text once, no wording pass.
- Verification budget: the scoped suite plus one git diff prove an edit. Do not re-read the edited region, re-grep your own notes, or re-run a suite that already passed (#228). An edit call that returns success matched, and a passing suite stays passed (#231). A comment-only edit does not void a passing suite: at most one `node --check` (#229). To check something you wrote, one grep or read of the file settles it; never re-parse your own escaped tool-call output in thinking, and never re-trace the braces of a script you just wrote (#232). One exception: a batch that hooks one new call at several integration points gets one grep of the call name to count hooks before the suite run (a missed fetchSubs hook cost a red run, #237).
- The scoped suite is the whole test scope: do not grep other suites for imports of the changed file or weigh suite coverage in thinking (#238 blocks 20-22, #239 block 20). An acceptance-criteria line "pnpm test passes" is boilerplate: the scoped suite satisfies it, run no full suite (the role prompt forbids it), and state the deviation once in # Notes (#239 block 20 spent a thinking block on this).
- After the commit, one git log plus one git status is the whole wrap-up. No suite rerun, no .kanban symlink re-derivation or ls verification (Environment and safety records it), no /tmp cleanup loop: /tmp fixtures need no cleanup, the machine cleans /tmp (#231). The same holds before the commit: one git status is the commit step's own check, with no thinking block and no symlink re-derivation around it (#240 blocks 13-14).
- Keep each bash call single-purpose and small; one oversized call truncates, hides the result, and forces a rerun (#225, #228).
- Fix the acceptance battery before editing: the greps plus the one suite that reads the real files (plugin.test.ts for SKILL.md changes). Run it once before commit and once at the end. No mid-check re-derivations of match counts.
- Keep the todo list at one item per requirement, not per edit.
- An untracked file in git status is usually not yours. Check mtime or git log once, then move on (#226).

## Running and testing

- Tests are plain assert-style ESM scripts, no framework: `node tests/<file>.test.ts` per file, `npm test` for the suite. There is no typecheck: `npx tsc` prints "This is not the tsc command you are looking for". The repo runs `.ts` directly through node (24), so the suites are the only check.
- Run suites separately, redirect full output to a file in the same command (`node tests/x.test.ts > /tmp/o 2>&1`), and slice the file afterwards (grep AssertionError with context, then the summary line). Never pipe the live run through head or tail: a cut hides the summary line or the failing assert and forces a second full run (#229, #232, #237). A red-phase run may fail at import time on a missing export instead of on the new asserts; that still proves the tests are new, so do not add stub exports to reshape the red run (#230).
- PAGE (src/webui/page.ts) is one template literal served as the whole client. A regex written inside it loses its backslash: write `\\.` where the served string must hold `\.` (#237: a `replace(/\.doctor$/)` pin failed because the served page held `/.doctor$/`). Asserts on served text match the built PAGE string, never the source-file bytes. Any new assert that regex-extracts a value (capture groups, a CSS var's rgba alpha) gets one extraction printed with a node one-liner against the real string before the first suite run (#237). NaN in a failure message is the regex-missed signature: one node one-liner against the real string finds the fix; never hand-trace the regex in thinking (#239 blocks 12-15: a two-group rgba regex cost a wasted red run plus a diagnosis block).
- tests/webui.test.ts is the only suite that pins page.ts; no other test file imports webui/page, and the page CSS and SVG facts live there (verified by grep, #238). Do not re-check this per run.
- log() (src/orchestrator/log.ts) echoes to stdout unless fd 1 is the log file itself (dev+ino check, #233). The daemon harnesses (runDaemon, sEnv/sFlag, the hub and worktree parts) assert log() lines from the daemon's piped stdout, so never drop the non-TTY echo without moving those harnesses to read the log file first.
- The .pids janitor (janitorPids in src/orchestrator/pipeline.ts) sweeps .exit files by name shape: a new marker file in .pids must be added to its keep rules or the sweep deletes it within one sweep (#229). The paired guard: spawnRunAnalysis (src/orchestrator/spawn.ts) skips when the per-run `<slug>.<role>.<n>.analysis.exit` marker exists, so a failed analysis spawns once. The to-merge sweep fires the per-run analysis before the merge pass.
- To make a spawned analysis fail deterministically end to end, hand-write the finished run's log as a corrupt .log.gz (the compactor pattern skips .gz and the runner's gunzip throws); chmod 000 on the plain log races the sweep's retro-compact, a corrupt .log.gz does not.
- Commit messages state only verified facts. Diff old vs new output before claiming byte-identity or behavior parity. An overclaim forces a soft-reset re-commit (#224).
- Analysis prompt builders live in src/efficiency-analysis.ts (splitAnswer, doctorPrompt). There is no src/orchestrator/prompts.ts (#228).

## Test-harness waits

- A wait loop over spawned processes must sleep between checks: a synchronous busy spin blocks node's event loop, the SIGCHLD reaper never runs, and the exited sh wrapper lingers as a zombie whose /proc entry keeps pidAlive true forever (#234). Make the helper async, sleep about 50 ms per check, and wait for the exit file AND a dead pid. Both conditions, not one: the wrapper writes the exit file about 35 ms after spawn but can still be alive across the test's next synchronous call, so poll takes the live path and defers the transition (#234).
- When such a wait misbehaves, suspect the reaper before the spawn. Confirm with one minimal isolated probe (spawn a stub, loop, watch /proc/<pid>/stat and cmdline), never by re-reading the spawn and pid code: #234 cycled recycled-pid, node-cold-start and sh-behavior hypotheses, and every one was wrong.

## Temp fixture scripts

- A temp orchestrator part lives in tests/ from the first write, never /tmp: relative `../src` imports break from /tmp with ERR_MODULE_NOT_FOUND (#229).
- Write a temp fixture script complete on the first write. Copy call shapes from the tests (setState takes a Task from getTask(root, file), not a file reference) and JSONL record shapes from the fixtures the tests build. A wrong call costs a TypeError, a signature grep, and a rerun (#226).
- Never patch temp scripts with sed. Use the edit tool: sed clashes on `|` and `/` delimiters and can leave broken syntax that kills node (#226).
- Verify a new fixture with find, not ls -R: ls -R does not list hidden dirs and triggers false alarms (#227).
- chmod 555 on a directory does not block writes to a file that already exists inside it. To make a create-or-write fail in a test, delete the file first, then lock the directory (#234).
- To settle worktree fixture doubts (index flags, history), one command pair: `git -C <wt> ls-files -v` (S marks skip-worktree) plus `git -C <wt> log --oneline` (#234).

## Stale-test triage

- When a suite fails on prompt text, do not build a harness first. Read the assertion, then grep the prompt source (agents/*.md) for the asserted phrase. If the phrase is absent at HEAD, the test is stale: `git log -S'<phrase>' -- <file>` names the commit that dropped it. A one-line assertion fix ends it (#224: a stale agents/merger.md assertion cost 40% of a developer run).
- Flake vs regression: `git stash push`, run the failing suite at HEAD, `git stash pop`. Fix test-race flakes at the root cause: gate the fixture write against the racing machinery (an openQuestions-backed task is never promoted).

## Test recipes

- To intercept src module internals from a test (fs calls, hooks inside a function), spawn a child with `--require <preload.cjs>`: patches to `require("node:fs")` propagate to ESM named imports only when installed before the first import; an in-process patch never does (facade bindings resolve at first import).
- Deterministic interleaving in orchestrator tests: drive `rescan(root, cfg)` and `poll(root, stallMinutes)` directly (import `rescan` from `../src/orchestrator/pipeline.ts`, `poll`/`loadConfig` from the facade; temp HOME via `mkdtempSync` + `loadConfig`; `cfg.agent = <stub>`), instead of daemon timing races. A stub that `Atomics.wait`s ~1s keeps a spawned agent alive across the next synchronous call. Temp scripts outside a package need the `.mjs` extension; when a fixture must keep a specific name (e.g. `orchestrator.ts` for cmdline matching), drop a `package.json` with `{"type": "module"}` next to it, else node loads the `.ts` as CJS.
- Asserts on end-of-run state go before the call that clears that state: symlink/readlink asserts come before poll (clearContextSymlinks runs at run end); file-restored asserts after it (#234).
- Idle-gate tests: drive `promoteBacklog(root, listAll(root), windowMinutes)` directly and age a file with `utimesSync(path, new Date(Date.now() - 10_000), ...)` (0.05 min window = 3 s). The quiet window is board-wide but only over real task files: `ROLE_NOTES_RE` names (AGENTS*.md) do not count (#212).
- Hub election runs unexported inside `joinHub` (src/hub.ts), so test it by spawning `src/orchestrator.ts` with an isolated HOME plus XDG_CONFIG_HOME and the webUi block in the legacy HOME config (tests/orchestrator.test.ts parts U-Z). The election must degrade, never throw: an unwritable neutral dir must log the real error code and path and leave the daemon sweeping (part Z2: mkdir EACCES and lock EACCES with a chmod 555 dir; restore 0755 in a finally or the exit cleanup cannot remove the fixture).
- To iterate on one late part of tests/orchestrator.test.ts without the full multi-minute suite, extract the file preamble plus the definitions of every identifier the part references into a temp `tests/*.ts` file, run it, fix ReferenceErrors from the top, then delete it. Re-locate the part by its `// --- part` marker, not by line number (#229).
- Prompt byte pins (tests/efficiency-analysis.test.ts): `analyseLog` reads `agents/*.md` from the package root by default, so an equality against a literal helper pins the shipped wording per the Exemption rule (never read the template in the test, that is circular). Get the exact literal from a temp `tests/tmp-*.ts` that calls `analyseLog` with stub runners and prints `JSON.stringify(prompt)`, then delete the temp script (#228). A stub answer `"S: x\nStruggle: none"` renders summary `"S: x"`, because splitAnswer strips only a literal `summary:` prefix.

## Environment and safety

- In a task worktree, `.kanban` is a symlink to the main checkout's board: writing SPECS.md or AGENTS.md here edits the main checkout file, and git in the worktree reports `.kanban/...` as "beyond a symbolic link" (never stage or commit those). The daemon commits board changes itself.
- Read-only HOME mounts: on this machine ~/.pi and ~/.config are read-only bind mounts, so any test or close() flush that touches the real user config dir crashes (or, on normal machines, pollutes it). Close in-process hubs before restoring the real HOME, and keep global-state tests on fixture HOMEs (#215).
- A worktree commit needs `git -c commit.gpgsign=false commit`: ~/.gnupg is a read-only mount here, so plain `git commit` fails with "gpg failed to sign the data" and "failed to write commit object".
- `process.env.X = undefined` sets the env to the string "undefined" in node; use `delete process.env.X` when restoring an unset variable, else later code resolves paths like undefined/se-llm-team and litters the cwd (#215).
- Neutral shared paths (#215): the global config, hub registry and hub lock live at $XDG_CONFIG_HOME/se-llm-team/ (else ~/.config/se-llm-team/), with the legacy ~/.pi/agent paths as read-only fallbacks; every temp-HOME test env must also set or delete XDG_CONFIG_HOME, since the real environment may set it and leak the production config into tests.
- Large argv: the kernel rejects a single argument over 131,072 bytes with E2BIG (MAX_ARG_STRLEN); node spawn reports it as a child 'error' event and the child never starts (#213). The AGENTS.md injection cap (PROJECT_PROMPT_CAP, src/orchestrator/spawn.ts) is 131,000, covered by a real stub spawn in tests/orchestrator.test.ts (#214).
- Smoke-testing the pipeline (a daemon run against a temp root) must not touch the production webui: start smoke daemons with `--no-webui` (or `SE_LLM_TEAM_NO_WEBUI=1`), because a smoke daemon reads the global config and binds the production webui port, wedging the real UI.

## Live webui checks

- Fixture (reusable recipe, #205/#206): temp root `/tmp/<name>/root` with `.kanban/000001_probe.md` (long body) and `.kanban/se-llm-team.json` `{"webUi":{"enabled":true,"host":"127.0.0.1","port":4321}}` (project config overrides the global port). Seed the probe task in state `done`: a `backlog` task auto-promotes to `to-do` at the first sweep and the daemon spawns a real agent for it; `done` renders the popup and spawns nothing.
- Daemon: `node src/orchestrator.ts --root <tmp> --rescan-seconds 30 --poll-minutes 5 &` (the CLI entry is src/orchestrator.ts; src/orchestrator/main.ts has no self-call and exits silently). Run it with an isolated HOME (`HOME=/tmp/<name>/home`) and an isolated or deleted XDG_CONFIG_HOME (the real environment may set it and leak the production config): the production daemon holds the global hub lock, so under the real HOME the probe logs "hub lock held by another daemon, standing down" and serves no UI. Never run a live-check daemon without the per-root port override: it reads the global config and binds the production webui port (global config: 4242 on 0.0.0.0, held by a long-running daemon under the real HOME; never signal that one).
- Page staleness (#237): the daemon serves the PAGE constant built at startup (`res.end(webui.PAGE)`; the no-cache header only stops browser caching), so a page.ts edit does not go live until the daemon restarts. Restart the check daemon after every page.ts edit, or the check runs old code.
- Playwright script: module at `/home/phamba/repos/paseo/node_modules/playwright/index.mjs`. Write a fresh `/tmp/<name>/check.mjs` each run; old check scripts under /tmp do not survive cleanup (#226, #227). Health-probe with `curl -sf http://127.0.0.1:4321/` (`/api/board` is 404 in this build, only `GET /` serves).
- Relation-line checks (#237): relation paths (`#relations path`, `#agent-relations path`) are stroked with fill:none and have a zero-height box, so default Playwright visibility waits time out: wait with `state: "attached"`. The modal entry animation ends with a redraw about 300 ms after open that rewrites the SVG innerHTML: sample classes and hover state after that redraw (the redraw is HTML-gated and re-applies the hovered handle). Hovering a run highlights only the paths that touch it, other chain legs stay dim: assert the hot/dim split, never all paths hot.
- Wrap geometry (#237, #238): curve() reverses the sides when the target card sits left of the source (to.x < from.x): the line leaves the source LEFT edge and enters the target RIGHT edge. Derive wrapped-column asserts from that branch, not right-out/left-in. dropCurve (src/webui/page.ts) scales the horizontal run-in to 0.35 of the span, clamped to 60 px max and 8 px min against the card's x offset to the canvas left edge (assumption recorded under #238 Open questions). Modal agent columns shrink to the viewport (about 105 px per card at 375 px, the board 300 px floor does not apply): probe computed widths in page once before writing wrap asserts. One modal per script: an Escape pressed for an earlier assert closes it, and every later rect read returns 0, so reopen the task before measuring after a resize.
- Link bindings: makeCard in src/webui/page.ts sets `dataset.file` and `onclick = openTask(file)` on the card element, cardBaseHtml in src/webui/board.ts renders the card innards (name, priority, complexity, issuer chips) with no data-file of its own. In the modal, writeHead rewrites `#m-attrs` on open and on every 5 s refresh, then binds every `#m-attrs .num-link` to `openTask(a.dataset.task)`: a linked attribute row needs only `data-task` on a `.num-link`, no new binding code (#231).
- Selector trap: `#m-attrs .num-link` always matches the number-row link first (attrsHtml puts one on the number row). Target one attribute row by `data-task` (`.num-link[data-task="..."]`) or the row's label span, never a bare `#m-attrs .num-link` (#231).
- Kill the daemon with one command, pid taken from ss, never from `$!`: `pid=$(ss -ltnp | grep :4321 | grep -oP 'pid=\K[0-9]+' | head -1) && tr '\0' ' ' < /proc/$pid/cmdline && kill $pid`. The tr output must name `--root /tmp/<name>/root`. `$!` after `nohup ... &` can be a wrapper subshell one pid off from the real node process, and grep on `/proc/<pid>/cmdline` fails on its null bytes, so a $!-based check reports a false mismatch and the daemon stays up (#230). `pkill -f "<pattern>"` matches your own bash -c command line and kills the shell (exit 143).
- Synthetic visibilitychange for wake checks: dispatch `new Event("visibilitychange", { bubbles: true })` on `document` (or dispatch on `window`). A plain `new Event("visibilitychange")` has bubbles false, so a window listener never runs and the Playwright check times out with no visible page error (#235).
- Popup gotchas: `#modal` is `position: fixed; inset: 0; z-index: 3`, so while a popup is open every card click is intercepted. Close with Escape and wait for `#modal.hidden` before the next card click, or call `window.openTask(file)` via `page.evaluate` to bypass hit-testing. `#modal.hidden` is `display: none`, so a `scrollTop` write on `#m-box` while hidden is discarded and the browser restores the stored offset on the next show; any open-time scroll reset must run after the un-hide (#209).
- Doctor-card fixture, one pass from this recipe (#226, #230, #232): write the fixture and the check script with no thinking pass over rendering, naming or slug rules, all answered here. Task file `.kanban/<slug>.md`, config JSON with the port override, run log `.kanban/.logs/<slug>.developer.0.log` (a `session` plus a `turn_end` JSONL record), doctor log `.kanban/.logs/<slug>.developer.9.doctor.log`. doctorHistory (src/webui/payload.ts) filters doctor logs on the task slug and builds the parent run handle from the file name, so the slug must match the task, and an unused run number (9 with no matching run log) makes the card unmatched and past (no `.analysis` process, spawns nothing). renderDoctor (src/webui/page.ts) appends the card to the parent handle's column. A sub card additionally needs a `tool_execution_end` record in the run log holding `Agent ID: x` and `Output file: /tmp/pi-subagents-1000/x.output` (SUB_ROOT is hard-coded) plus that file on disk.
- Doctor-card CSS (after #238): at rest the card is a plain card with blue text only (`.agent-doctor` sets `color: var(--doctor-fg)`, the `.check` stays blue, no own background, outline or hover override, the plain `.agent-card` hover applies); since #238 the shared `.agent-card` rest background is a translucent color-mix, so relation lines show through it faintly. The active card keeps the blue pair: `.agent-doctor.agent-card-active` gets `border-color: var(--doctor-fg)` and `background: var(--doctor-bg-strong)`. Click the card to set `.agent-card-active`; `openTask` is a window global, so `page.evaluate(() => window.openTask(file))` bypasses popup hit-testing. Read colors off `#m-doctor .agent-card`, `#m-agent-btns .agent-card` and `.agent-subs .agent-card` with one fresh Playwright context per scheme (`newContext({ colorScheme: "dark" | "light" })`), because a fresh context stores no theme in localStorage and matchMedia then decides.
- Live-test artifacts: daemon log `.kanban/.logs/orchestrator.log` (also daemon stdout), PM reports `.kanban/.reports/*.md` (one per sweep with a done transition, oldest first by name).
