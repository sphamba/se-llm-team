# developer

Project-specific guidance for the developer role. Facts here are verified: trust them without re-probing (#226; #245 blocks 26, 33, 60 re-read package.json, scripts/test-changed.mjs and the SPECS.md symlink; #247 blocks 85, 89 re-derived the symlink again).

## Task start

- Judge the diff size before the read set. For a one-line or small fix (a label, a color, a chip, a condition), the read set is the one helper and its test, plus one `cat` of the task file (no head-then-cat re-read: #239). No knowledge-base search, no extra source files, no caller sweeps beyond the grep that names the helper (#227, #226). For colors, mirror the nearest existing pattern and edit the test first, then the source (#226, #240). One grep for the old value across src, tests and docs is the allowed extra sweep for any changed pin (#240 block 8, #244 blocks 50-55: a self-decided label fallback broke the assert at tests/webui.test.ts:829 and cost a second round). Comments fall under "add nothing unrequested": no deliberation block over unrelated comments (#239 block 17).
- Plan the whole run in one pass: read list, edit list, check command, in the first thinking block. Fire independent reads and greps in parallel in one block; #245 and #247 (blocks 2-14) read payload.ts, board.ts and page.ts one per block with a plan-only thinking block between each (blocks 2, 6, 13, 18, 20 are five intention-only thinking blocks with no command, #228), and exploration took about half the run. Locate before you read: grep the selector, assert text, or function name for offsets first, then one read per hit. No blind offset slices (#238 blocks 4-7). No greps for names you invented (#243: `logFixups`, `logUrl`; #244 block 34: `beforeRows`/`afterRows`) or for markers that live in another suite (#245 block 15: `// --- part` exists in orchestrator.test.ts only). One grep per symbol, no re-greps of the same symbol with a narrower scope (#245 blocks 9-10).
- Decide once, then act. Make each decision in the thinking block where it first arises. Never open a second design pass: re-drafting the same shape, assertion, placement, or open question in later thinking blocks is the top budget sink (#230, #232, #237, #243 blocks 9-16, #244 blocks 12-21, #245 blocks 24, 30, 32: three of fourteen thinking blocks re-drafted the payload shape, the cache invalidation and the test placement, one reached no conclusion; #247 blocks 27-38 re-drafted the test placement, the mtime ordering and the LOG_ROLES assert placement in four thinking blocks after the facts were in hand). An ambiguous or contradictory spec point gets one reading: the simplest one that satisfies the acceptance criteria (for a contradiction, read the callers first), then implement and record the choice as an assumption under # Open questions (#224, #228). A mechanism the spec names (ordering is chronological, stats sum automatically) is a fact: implement against it, never re-derive it from source (#247 blocks 27-33 re-derived the newest-first sort three times). Persistence questions settle in one step: client-side change with no endpoint allowed means localStorage keyed like the existing precedent (grep `localStorage`/`theme`); a config key with no write path loads as a default only, and the write endpoint is the recorded assumption (#244).
- Pin shipped wording or bytes as a literal expected string, never a file read inside the test (that is circular), and never a regex where a literal `includes` of the spec's value works (#240 blocks 7, 9). Extract the rendered text once with a node one-liner, embed it as a literal, run the suite once (#228). A formula or geometry change (scale factor, cap, clamp) gets its constants in one pass, written once, with expected test strings from one node one-liner that replicates the formula, never repeated hand arithmetic in thinking (#238 blocks 12, 14).
- Add the failing assertion first for behavior changes, run the suite once, then fix. The failing run is the before-proof: never re-verify pre-fix behavior by hand afterwards (#227). A red run may fail at import or syntax time (a missing export, a duplicate declaration); that still proves the tests are new: fix the error, do not add stub exports to reshape the red run (#230, #243 block 19).
- Design a new orchestrator smoke part from the nearest existing part: copy its harness, note the sweep order and log-index rules once, then write the test (#229).
- Budget your own test harness like product code: #234 spent 60 of 155 blocks debugging new wait helpers against about 10 for the fix; #244 spent 17 of 98 blocks (57-73) on one live check against about 15 for the whole feature. A probe beats a guess: after one failed full check run, write the minimal isolated probe that varies every hypothesis in one script (see Live webui checks), never one check run per hypothesis.

## Scope and process discipline

- Read each target file once, then edit. One read pass plus greps covers a sweep; do not re-scan or re-derive findings for files already read (#225). Edit anchors come from read output already in context: an exact copy of the lines, leading whitespace included. Never re-read lines you hold to rebuild an anchor (#237, #242 blocks 47-48). On a match failure, one byte check of the exact lines (`cat -A`), then one retry; never re-read the whole file (#231, #242 blocks 65-81). An anchor goes stale when your own edits shifted the lines: grep the enclosing symbol for the current line, read the small slice, copy it verbatim; never assemble oldText from memory or from strings built in thinking, and trust the grep answer over a remembered offset (#247 blocks 54-62: four failed edit attempts on renderAgent from a memory-built anchor with 3 tabs over the file's 2, plus a byte check of stale offset 778 after grep had answered 830).
- edit calls take edits as an array of {oldText, newText} objects, never a JSON string (#237 block 192). A failed batch applies nothing, so keep batches small (#242 blocks 65-78). When appending to an existing list (a role-file bullet, SPECS notes), oldText ends at the last line you keep and newText repeats it unchanged before the addition; never drop existing lines (#244 blocks 87-89: one append replaced an existing fact and needed a corrective edit). An edit whose oldText equals its newText is a skip: you already hold the target (#244 block 49).
- Sweep completeness before an edit batch: one grep per field read, per old symbol, and per changed user-visible string across the whole target file, and fix every hit in the first batch. A missed site fails the green run and costs a second round (#242 blocks 99-106, #244 blocks 50-55).
- A repo-specific sentence removed from agents/*.md or SKILL.md goes as one bullet into .kanban/AGENTS.<role>.md in the main checkout, under the closest section (#225).
- SPECS.md bookkeeping is fixed: completed-work facts under the task's # Notes; assumptions and open points under # Open questions (if the body has no # Open questions heading, add it with the assumptions in one edit; never re-read the body to check first, #230). Task-body edits: deviation note under the affected requirement, delete answered open questions, mark confirmed assumptions, one edit call (#228). Anchor every SPECS.md edit with unique surrounding sentence text, never a bare heading ("# Notes" can occur twice, #238 block 26); an end-of-file append may anchor on the trailing "# Notes" only when a full read proved it unique (#239 block 25). Draft the notes text once, no wording pass (#243 block 62, #244 block 84; #245 block 58 re-deliberated the Open questions placement and the symlink before one edit).
- Verification budget: the scoped suite plus one git diff prove an edit. Do not re-read the edited region, re-grep your own notes, re-check your own wording or indentation, or re-run a suite that already passed (#228, #231). To check something you wrote, one grep or read settles it; never re-parse your own escaped tool-call output in thinking, never re-trace the braces of a script you just wrote (#232, #243 block 40, #244 block 84). One exception: a batch that hooks one new call at several integration points gets one grep of the call name to count hooks before the suite run (#237).
- The scoped suite is the whole test scope: do not grep other suites for imports of the changed file or weigh suite coverage in thinking (#238 blocks 20-22). "pnpm test passes" is boilerplate: the scoped suite satisfies it, run no full suite, state the deviation once in # Notes (#239 block 20). A live check is not boilerplate: run one only when the criteria name behavior the scoped suite cannot pin, and build its fixture from the recipes below, never by reading payload.ts or logpane.ts first (#243 blocks 28-35). scripts/test-changed.mjs maps changed files to suites; a shared file (src/hub.ts) also pulls the multi-minute orchestrator suite (#242 blocks 109-111).
- Skip hindsight_reflect and similar long remote calls mid-task: it timed out at 300 s with a 504 and no results (#244 block 18). A remote call that times out is never retried; the verified facts live in this file.
- After the commit, one git log plus one git status is the whole wrap-up. No suite rerun, no .kanban symlink re-derivation or ls verification (Environment and safety records the symlink facts; #243 block 59, #244 block 93, #245 block 60 re-derived the symlink target and block 63 re-checked the finished wrap-up in thinking); /tmp fixtures need no cleanup (#231). One git status is the commit step's own check, with no thinking block around it (#240 blocks 13-14).
- Keep each bash call single-purpose and small; one oversized call truncates, hides the result, and forces a rerun (#225, #228).
- Fix the acceptance battery before editing: the greps plus the one suite that reads the real files (plugin.test.ts for SKILL.md changes). Run it once before commit and once at the end. No mid-check re-derivations of match counts.
- Keep the todo list at one item per requirement, not per edit. todo calls take the action field; one #245 call failed schema validation without it.
- An untracked file in git status is usually not yours. Check mtime or git log once, then move on (#226).

## Running and testing

- Tests are plain assert-style ESM scripts, no framework: `node tests/<file>.test.ts` per file, `pnpm test` for the suite, `pnpm test:changed` for the scoped run. There is no typecheck: `npx tsc` prints "This is not the tsc command you are looking for". The repo runs `.ts` directly through node (24), so the suites are the only check.
- Before you add a test block to an existing suite, grep that file for every planned local name (stubs, variables, helpers): #243 reused `logText` and `openInit`, which cost a SyntaxError red run, a collision grep and two renames.
- A new fixture log in an existing suite: grep the suite once for full-enumeration asserts (a deepEqual over an agents array) and place the new test after them, then write once (#247 blocks 31-38 re-placed the splitter tests in four thinking blocks). Runs sort newest-first by log mtime, so the fixture log written last lands first: no utimesSync backdate (#247 blocks 27-33 re-derived the sort three times).
- A fixture rewrite that must invalidate a cache changes the cache key, not just the value: logStats (src/webui/payload.ts) keys on file size, so a 300 → 500 rewrite is byte-identical in length and serves the stale parse, while the staleness assertion passes for the wrong reason (#245 blocks 47-51: one wasted green round, a diagnosis grep and a fixture retoken). Pick rewrite values with different byte lengths and check the cache key once before writing the test.
- Run suites separately, redirect full output to a file in the same command (`node tests/x.test.ts > /tmp/o 2>&1`), and slice the file afterwards (grep AssertionError with context, then the summary line). Never pipe the live run through head or tail: a cut hides the summary line and forces a second full run (#229, #232, #237). The first Error line in the redirected log is the whole red diagnosis: one grep (#242 blocks 82-83).
- PAGE (src/webui/page.ts) is one template literal served as the whole client. A regex written inside it loses its backslash: write `\\.` where the served string must hold `\.` (#237). Asserts on served text match the built PAGE string, never the source-file bytes. Any assert that regex-extracts a value gets one extraction printed with a node one-liner against the real string before the first suite run; NaN in a failure message is the regex-missed signature (#237, #239 blocks 12-15). Exported helpers interpolate with `${fn}`: Function.prototype.toString strips the `export` keyword, so the served string stays valid (#244).
- tests/webui.test.ts is the only suite that pins page.ts; the page CSS and SVG facts live there (verified by grep, #238). Do not re-check this per run.
- log() (src/orchestrator/log.ts) echoes to stdout unless fd 1 is the log file itself (dev+ino check, #233). The daemon harnesses (runDaemon, sEnv/sFlag, the hub and worktree parts) assert log() lines from the daemon's piped stdout, so never drop the non-TTY echo without moving those harnesses to read the log file first.
- The .pids janitor (janitorPids in src/orchestrator/pipeline.ts) sweeps .exit files by name shape: a new marker file in .pids must join its keep rules or the sweep deletes it within one sweep (#229). Paired guard: spawnRunAnalysis (src/orchestrator/spawn.ts) skips when the per-run `<slug>.<role>.<n>.analysis.exit` marker exists, so a failed analysis spawns once; the to-merge sweep fires the per-run analysis before the merge pass.
- To make a spawned analysis fail deterministically end to end, hand-write the finished run's log as a corrupt .log.gz (the compactor pattern skips .gz and the runner's gunzip throws); chmod 000 on the plain log races the sweep's retro-compact.
- Commit messages state only verified facts. Diff old vs new output before claiming byte-identity or behavior parity. An overclaim forces a soft-reset re-commit (#224).
- Analysis prompt builders live in src/efficiency-analysis.ts (splitAnswer, doctorPrompt). There is no src/orchestrator/prompts.ts (#228).

## Test-harness waits

- A wait loop over spawned processes must sleep between checks: a synchronous busy spin blocks node's event loop, the SIGCHLD reaper never runs, and the exited sh wrapper lingers as a zombie whose /proc entry keeps pidAlive true forever (#234). Make the helper async, sleep about 50 ms per check, and wait for the exit file AND a dead pid (both, not one: the wrapper writes the exit file about 35 ms after spawn but can still be alive across the test's next synchronous call).
- When such a wait misbehaves, suspect the reaper before the spawn. Confirm with one minimal isolated probe (spawn a stub, loop, watch /proc/<pid>/stat and cmdline), never by re-reading the spawn and pid code: #234 cycled three hypotheses and every one was wrong.

## Temp fixture scripts

- A temp orchestrator part lives in tests/ from the first write, never /tmp: relative `../src` imports break from /tmp with ERR_MODULE_NOT_FOUND (#229). Temp scripts outside a package need the `.mjs` extension; when a fixture must keep a specific name (e.g. `orchestrator.ts` for cmdline matching), drop a `package.json` with `{"type": "module"}` next to it, else node loads the `.ts` as CJS.
- Write a temp fixture script complete on the first write. Copy call shapes from the tests (setState takes a Task from getTask(root, file), not a file reference) and JSONL record shapes from the fixtures the tests build. A wrong call costs a TypeError, a signature grep, and a rerun (#226).
- Never patch temp scripts with sed. Use the edit tool: sed clashes on `|` and `/` delimiters and can leave broken syntax that kills node (#226).
- Verify a new fixture with find, not ls -R: ls -R does not list hidden dirs (#227).
- chmod 555 on a directory does not block writes to a file that already exists inside it. To make a create-or-write fail in a test, delete the file first, then lock the directory (#234).
- To settle worktree fixture doubts (index flags, history), one command pair: `git -C <wt> ls-files -v` (S marks skip-worktree) plus `git -C <wt> log --oneline` (#234).

## Stale-test triage

- When a suite fails on prompt text, do not build a harness first. Read the assertion, then grep the prompt source (agents/*.md) for the asserted phrase. If the phrase is absent at HEAD, the test is stale: `git log -S'<phrase>' -- <file>` names the commit that dropped it. A one-line assertion fix ends it (#224: a stale agents/merger.md assertion cost 40% of a developer run).
- Flake vs regression: `git stash push`, run the failing suite at HEAD, `git stash pop`, before any hypothesis work. A failing orchestrator part with no plausible link to the diff is a timing flake until HEAD proves otherwise; #242 spent about 10 blocks on import-chain and showTip hypotheses before the stash check settled it. One rerun closes a confirmed flake. Fix real test-race flakes at the root cause: gate the fixture write against the racing machinery (an openQuestions-backed task is never promoted).

## Test recipes

- To intercept src module internals from a test (fs calls, hooks inside a function), spawn a child with `--require <preload.cjs>`: patches to `require("node:fs")` propagate to ESM named imports only when installed before the first import; an in-process patch never does (facade bindings resolve at first import).
- Deterministic interleaving in orchestrator tests: drive `rescan(root, cfg)` and `poll(root, stallMinutes)` directly (import `rescan` from `../src/orchestrator/pipeline.ts`, `poll`/`loadConfig` from the facade; temp HOME via mkdtempSync + loadConfig; `cfg.agent = <stub>`), instead of daemon timing races. A stub that Atomics.waits ~1 s keeps a spawned agent alive across the next synchronous call.
- Asserts on end-of-run state go before the call that clears that state: symlink/readlink asserts come before poll (clearContextSymlinks runs at run end); file-restored asserts after it (#234).
- Idle-gate tests: drive `promoteBacklog(root, listAll(root), windowMinutes)` directly and age a file with `utimesSync(path, new Date(Date.now() - 10_000), ...)` (0.05 min window = 3 s). The quiet window is board-wide but only over real task files: ROLE_NOTES_RE names (AGENTS*.md) do not count (#212).
- Hub election runs unexported inside `joinHub` (src/hub.ts), so test it by spawning `src/orchestrator.ts` with an isolated HOME plus XDG_CONFIG_HOME and the webUi block in the legacy HOME config (tests/orchestrator.test.ts parts U-Z). The election must degrade, never throw: an unwritable neutral dir must log the real error code and path and leave the daemon sweeping (part Z2: mkdir EACCES and lock EACCES with a chmod 555 dir; restore 0755 in a finally or the exit cleanup cannot remove the fixture).
- To iterate on one late part of tests/orchestrator.test.ts without the full multi-minute suite, extract the file preamble plus the definitions of every identifier the part references into a temp `tests/*.ts` file, run it, fix ReferenceErrors from the top, then delete it. Re-locate the part by its `// --- part` marker, not by line number (#229).
- Prompt byte pins (tests/efficiency-analysis.test.ts): `analyseLog` reads `agents/*.md` from the package root by default, so an equality against a literal helper pins the shipped wording per the pin rule. Get the exact literal from a temp `tests/tmp-*.ts` that calls analyseLog with stub runners and prints JSON.stringify(prompt), then delete the temp script (#228). A stub answer `"S: x\nStruggle: none"` renders summary `"S: x"`, because splitAnswer strips only a literal `summary:` prefix.

## Environment and safety

- In a task worktree, `.kanban` is a symlink to the main checkout's board: writing SPECS.md or AGENTS.md here edits the main checkout file, and git in the worktree reports `.kanban/...` as "beyond a symbolic link" (never stage or commit those). The daemon commits board changes itself.
- Read-only HOME mounts: ~/.pi and ~/.config are read-only bind mounts on this machine, so any test or close() flush that touches the real user config dir crashes (or pollutes it on normal machines). Close in-process hubs before restoring the real HOME, and keep global-state tests on fixture HOMEs (#215).
- A worktree commit needs `git -c commit.gpgsign=false commit`: ~/.gnupg is a read-only mount here, so plain `git commit` fails with "gpg failed to sign the data" (#215, #244 block 80).
- `process.env.X = undefined` sets the env to the string "undefined" in node; use `delete process.env.X` when restoring an unset variable, else later code resolves paths like undefined/se-llm-team and litters the cwd (#215).
- Neutral shared paths (#215): the global config, hub registry and hub lock live at $XDG_CONFIG_HOME/se-llm-team/ (else ~/.config/se-llm-team/), with the legacy ~/.pi/agent paths as read-only fallbacks; every temp-HOME test env must also set or delete XDG_CONFIG_HOME, since the real environment may set it and leak the production config into tests.
- Large argv: the kernel rejects a single argument over 131,072 bytes with E2BIG (MAX_ARG_STRLEN); node spawn reports it as a child 'error' event and the child never starts (#213). The AGENTS.md injection cap (PROJECT_PROMPT_CAP, src/orchestrator/spawn.ts) is 131,000, covered by a real stub spawn in tests/orchestrator.test.ts (#214).
- Daemons under test never touch the production webui. Smoke daemons: start with `--no-webui` (or SE_LLM_TEAM_NO_WEBUI=1), because a smoke daemon reads the global config and binds the production webui port, wedging the real UI. Live-check daemons: give the fixture its own per-root port in the project config (see Live webui checks), never the global one.

## Live webui checks

- Fixture (reusable recipe, #205/#206, #243): temp root `/tmp/<name>/root` with `.kanban/000001_probe.md` (long body) and `.kanban/se-llm-team.json` `{"webUi":{"enabled":true,"host":"127.0.0.1","port":4399}}`. 4399 works; a leftover check daemon from an earlier session can hold a port (#243 blocks 41-51). `/api/tasks` serving a board you did not seed means a foreign daemon holds the port: switch ports, do not hunt its pid. Seed the probe task in state `done`: a `backlog` task auto-promotes to `to-do` at the first sweep and the daemon spawns a real agent for it.
- Daemon: `node src/orchestrator.ts --root <tmp> --rescan-seconds 30 --poll-minutes 5 &` (the CLI entry is src/orchestrator.ts; src/orchestrator/main.ts has no self-call and exits silently). Run it with an isolated HOME and an isolated or deleted XDG_CONFIG_HOME: under the real HOME the production daemon holds the global hub lock, and the probe logs "hub lock held by another daemon, standing down" with no UI. The up check is the curl of `/` plus `/api/tasks` returning your seeded board; the daemon may log no webUi or listen line at all (a grep over daemon.log and orchestrator.log found nothing, #247 blocks 76-77), so do not hunt for one.
- Page staleness (#237): the daemon serves the PAGE constant built at startup, so a page.ts edit does not go live until the daemon restarts. Restart the check daemon after every page.ts edit, or the check runs old code.
- Playwright script: module at `/home/phamba/repos/paseo/node_modules/playwright/index.mjs`. Write a fresh `/tmp/<name>/check.mjs` each run. Health-probe with `curl -sf http://127.0.0.1:<port>/`; `/api/tasks` returns light rows, with the `agents` stats only on the visible first-five-per-column cards (#242, #245); `/api/task-detail?num=N` returns the per-task detail (full agent history, log content, doctors; 404 JSON on an unknown num), so live checks that read log content or full history must fetch the detail. `/api/board` is 404 in this build.
- Browser-API probes: when a browser API blocks a live check, write one probe script that varies every launch configuration in one run (plain headless, `--headless=new`, `channel: "chrome"`) instead of one full check per hypothesis (#244 blocks 62-66: two failed check runs and one single-config probe before the three-config probe settled it). Pin the API seam in the page (a stub or Object.defineProperty) instead of fighting the environment.
- Agent-log live check (#243): run logs `.kanban/.logs/<slug>.developer.0.log` and `.developer.1.log`, each with a `session` record plus `message_end` records; `message_end` records with text or thinking content blocks render as text in the log pane (the claude stream-json branch renders assistant text/thinking and user prompt/tool_result blocks). Give the two runs distinguishable text to test agent switching; an aborted init fetch (page route interception) tests the failure state. Write fixture and script in one pass from this recipe.
- Relation-line checks (#237): relation paths (`#relations path`, `#agent-relations path`) are stroked with fill:none and have a zero-height box, so default Playwright visibility waits time out: wait with `state: "attached"`. The modal entry animation ends with a redraw about 300 ms after open that rewrites the SVG innerHTML: sample classes and hover state after that redraw. Hovering a run highlights only the paths that touch it: assert the hot/dim split, never all paths hot.
- Wrap geometry (#237, #238): curve() reverses the sides when the target card sits left of the source (to.x < from.x): the line leaves the source LEFT edge and enters the target RIGHT edge. dropCurve scales the horizontal run-in to 0.35 of the span, clamped to 60 px max and 8 px min (assumption recorded under #238 Open questions). Modal agent columns shrink to the viewport (about 105 px per card at 375 px, the board 300 px floor does not apply): probe computed widths in page once before writing wrap asserts. One modal per script: an Escape pressed for an earlier assert closes it, and every later rect read returns 0, so reopen the task before measuring after a resize.
- Link bindings and selector trap (#231): makeCard sets `dataset.file` and `onclick = openTask(file)` on the card element; cardBaseHtml (src/webui/board.ts) renders the card innards (name, priority, complexity, issuer chips) with no data-file of its own. In the modal, writeHead rewrites `#m-attrs` on open and on every 5 s refresh, then binds every `#m-attrs .num-link` to `openTask(a.dataset.task)`. `#m-attrs .num-link` always matches the number-row link first: target one attribute row by `data-task` (`.num-link[data-task="..."]`) or the row's label span, never a bare `#m-attrs .num-link`.
- Kill the daemon with one command, pid taken from ss, never from `$!`: `pid=$(ss -ltnp | grep :<port> | grep -oP 'pid=\K[0-9]+' | head -1) && tr '\0' ' ' < /proc/$pid/cmdline && kill $pid`. The tr output must name `--root /tmp/<name>/root`. If ss shows no pid for the port, the listener is invisible to you: switch ports, never guess a pid. `pkill -f "<pattern>"` matches your own bash -c command line and kills the shell (exit 143) (#230, #244 block 74).
- Synthetic visibilitychange for wake checks: dispatch `new Event("visibilitychange", { bubbles: true })` on `document`. A plain `new Event("visibilitychange")` has bubbles false, so a window listener never runs and the Playwright check times out with no visible page error (#235).
- Browser-notification checks (#244): the headless Chromium shell reports `Notification.permission` denied even after `context.grantPermissions`; only `channel: "chrome"` grants it (see Browser-API probes). Headless Chrome keeps background tabs visible (`bringToFront` never sets `document.hidden`), so pin the client's hidden gate with `Object.defineProperty(document, "hidden", { configurable: true, get: () => true })` in the page. Record notifications with a stub that wraps the real API (a `permission` getter over the real value, `requestPermission` calling `Real.requestPermission.call(Real)`), and reset the fixture state before each run (a prior run leaves state at `doing`, which makes the focused no-notify check trivial).
- Popup gotchas: `#modal` is `position: fixed; inset: 0; z-index: 3`, so while a popup is open every card click is intercepted. Close with Escape and wait for `#modal.hidden` before the next card click, or call `window.openTask(file)` via page.evaluate to bypass hit-testing. `#modal.hidden` is `display: none`, so a scrollTop write on `#m-box` while hidden is discarded and the browser restores the stored offset on the next show; any open-time scroll reset must run after the un-hide (#209).
- Doctor-card fixture, one pass from this recipe (#226, #230, #232): task file `.kanban/<slug>.md`, config JSON with the port override, run log `.kanban/.logs/<slug>.developer.0.log` (a `session` plus a `turn_end` JSONL record), doctor log `.kanban/.logs/<slug>.developer.9.log`. doctorHistory (src/webui/payload.ts) filters runs by slug and builds the parent run handle from the file name, so the slug must match the task; an unused run number makes the card unmatched and past (no `.analysis` process, spawns nothing). renderDoctor (src/webui/page.ts) appends the card to the parent handle's column.
- Doctor-card CSS (after #238): at rest the card is a plain card with blue text only (`.agent-doctor` sets `color: var(--doctor-fg)`, the `.check` stays blue, no own background, outline or hover override, the plain `.agent-card` hover applies); the shared `.agent-card` rest background is a translucent color-mix, so relation lines show through it faintly. The active card keeps the blue pair: `.agent-doctor.agent-card-active` gets `border-color: var(--doctor-fg)` and `background: var(--doctor-bg-strong)`. Click the card to set `.agent-card-active` (the openTask bypass in Popup gotchas works in the modal). Read colors off `#m-doctor .agent-card`, `#m-agent-btns .agent-card` and `.agent-subs .agent-card` with one fresh Playwright context per scheme (`newContext({ colorScheme: "dark" | "light" })`), because a fresh context stores no theme in localStorage and matchMedia then decides.
- Live-test artifacts: daemon log `.kanban/.logs/orchestrator.log` (also daemon stdout), PM reports `.kanban/.reports/*.md` (one per sweep with a done transition, oldest first by name).

## Project facts
