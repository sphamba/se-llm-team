# developer: role guidance

Durable, task-agnostic facts for the developer role. Task-specific findings belong in the task's `# Notes`, not here.

## Settle once, then act

- Injected task text can quote stale numbers (file sizes, line counts, board state): trust on-disk state, confirm with one `wc`/`grep`, then act. A deliverable whose on-disk checks pass is confirmed: never redone, never re-counted.
- Settle each design point in one pass of the ladder (skip, reuse, stdlib, platform, installed dep, one line, minimum), write the decision and its reason into `# Notes`, and re-open it only on new evidence — never to re-argue a recorded decision.
- Run every acceptance check once, batched into a single command (all greps, counts and `git status` together) before the commit; a check that passed is not re-run. Ground unfamiliar names with one search: take symbol names from read output or import lines (a guessed name returns zero matches), and a knowledge page that reads "No content yet." ends that thread.

## Repo, build and checks

- No build step, no dependencies, no typecheck: sources are `.ts` run directly through node's type stripping (Node >= 24 required); the assert suites are the only check. `npm test` (glob loop over `index.test.ts`, `tests/*.test.ts`, `tests/*/*.test.ts`), `npm run test:changed` (change-mapped scoped run), or one suite standalone: `node tests/<area>/<file>.test.ts`. Inventory and commands: `docs/development.md`. Never run two suites at once — they share `.pids`, ports and fixture HOMEs.
- pnpm is pinned via the `packageManager` field (corepack resolves it); there is no committed lockfile. pnpm on the read-only worktree mount prints `ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK` — benign noise, the suite still runs and passes.

## Suite layout and harness

- Shared helpers live in `tests/helpers.ts` (imported by `tests/orchestrator/*` and `tests/tools.test.ts`; the efficiency-analysis, webui and kanban group files are standalone, and efficiency-analysis has its own local `helpers.ts`). In `tests/orchestrator/*` and `tests/webui/*`, HERE is that dir: src imports are `../../src/*.ts`, shared helpers `../helpers.ts`, repo-root paths `join(HERE, "../..")`.
- The webui suite is the group files under `tests/webui/`; there is no `tests/webui.test.ts`. Extend the group file whose scenario block covers the change; grep for anchors, line numbers drift.
- The efficiency-analysis suite is the group files under `tests/efficiency-analysis/`; `tests/efficiency-analysis.test.ts` is deleted. Doctor-prompt pins live in `doctor.test.ts`, prompt-file pins in `prompts.test.ts`. A `MODULE_NOT_FOUND` path is dead: never re-run it, and never re-guess it inside a directory your own `ls` just listed — run one of the listed files.
- `src/webui/page.ts`'s PAGE is one template literal served as the whole client: a regex written inside it loses its backslash (write `\\.` where the served string must hold `.`), and asserts on served text match the built PAGE string, not source bytes. The daemon serves the PAGE built at startup, so a page.ts edit goes live only after a daemon restart.
- Before adding a test block to an existing suite, grep that file once (fixed-string) for every planned local name and helper use against its import lines: a reused name or missing import costs a red run and a rename round. New module-level symbols that tests import need `export` at declaration. Re-locate test parts by their `// --- part` marker, never by line number.
- Prefer deterministic interleaving over daemon timing races: import and drive `rescan(root, cfg)`, `poll(root, stallMinutes)` and `promoteBacklog(...)` directly from an area file, with a temp-HOME config (`mkdtempSync`). Free a concurrency-cap slot by setting a holder task to a non-counted state, not by removing it. Order a test's steps so each assert that reads state precedes the call that mutates it, and gate meta/kanban mirror asserts with the suite's existing waitFor (the fold-in commit can land one sweep after the done transition).
- A wait loop over spawned processes must sleep between checks (about 50 ms): a synchronous busy spin blocks node's event loop, the SIGCHLD reaper never runs, and a zombie's `/proc` entry keeps pidAlive true forever. Wait for the exit file AND a dead pid, both.

## When a run goes red

- A test or helper written in this run is the first suspect when its own suite fails: re-read the new part and its helpers on disk, and probe the helper's return value with a scratch print before any production-code theory. An assert message that shows a comma-joined argv, a `[`-list or CLI flags where a prompt string was expected means the helper returned the wrong nesting level (`.at(-1)` grabbed the outer array, not its last element).
- The first Error line names the assert file:line; read that assert and the values it prints as data about what was compared, one pass, then act. Grep production code (env vars, flag builders, parsers) only after the new test code is proven innocent.

## Shell, environment and fixture isolation

- Run discipline: launch suites with output redirected to a file and the exit code captured in the same command (`setsid bash -c 'npm test > /tmp/o 2>&1; echo $? > /tmp/o.exit'`), never piped through head/tail — the first Error line in the log is the whole red diagnosis. `grep -c` exits 1 on zero matches (a 0 count from a failure-shaped grep is a pass: append `|| true` in chained commands — but never guard a check whose result you need, such as `node --check` or the suite itself: a guarded check hides its own failure). An exit code 0 from a suite file is proof every part ran (asserts and crashes exit non-zero): at most one `grep -c` of the suite's own pass labels against the log, never a diff round. Kill a fixture daemon by pid taken from ss/lsof, never `$!` or `pkill -f` (it can match your own bash -c command line and kill the shell, exit 143).
- Fixture HOME is mandatory for anything touching global state: `~/.pi`, `~/.config` and `~/.gnupg` are read-only bind mounts on this machine, so keep global-state tests and every smoke daemon on a fixture HOME with `XDG_CONFIG_HOME` set or deleted in the test env, plus `--no-webui` (or `SE_LLM_TEAM_NO_WEBUI=1`) — otherwise the smoke daemon reads the global config, binds the production webui port and holds the global hub lock. `process.env.X = undefined` sets the string "undefined" — use `delete process.env.X`. Keep fixture boards inert with long `--rescan-seconds`/`--poll-minutes` and seed probe tasks in state done (a backlog task auto-promotes and spawns real agents).
- In a task worktree, `.kanban` is a symlink to the main checkout's board, `SPECS.md` a symlink to your task file, and `AGENTS.md` a symlink to this role-notes file: writing through them edits the main checkout. git calls `.kanban/...` paths "beyond a symbolic link" — never stage or commit board files; the daemon mirrors `.kanban/` onto `refs/heads/meta/kanban` via git plumbing, so `git log -- .kanban/` prints nothing and board history is `git log meta/kanban -- <file>`.
- The global `~/.gitconfig` forces `commit.gpgsign=true` (this checkout's `.git/config` opts out, and worktrees share it); any fresh fixture repo needs `git -c commit.gpgsign=false commit` or signing fails with "gpg failed to sign the data". Stage first: a bare commit with unstaged edits fails.
- Shell traps: one argv over 131072 bytes fails with E2BIG (child 'error' event, never starts); `ls -R` skips hidden dirs — use find; never patch with sed (delimiter clashes leave broken syntax) — use the edit tool; temp scripts that import `../src` live under `tests/`, never /tmp; a name-critical `.ts` fixture outside a package needs a `{"type":"module"}` package.json next to it; run `node --check` (unguarded) on a generated script before its first run.

## Edits and task-file bookkeeping

- edit calls take an array of `{oldText, newText}` objects, never a JSON string; hunks must not overlap (a failed batch applies nothing — keep batches small); anchor each hunk on the shortest unique line copied verbatim from read output, grepped for uniqueness (0 or 1 hits) before the call. A long truncated line is never an anchor. End-of-file appends go through bash (`cat >>`/heredoc), never a tail-anchored edit. When the spec asks for prose a sibling file already carries (an `agents/*.md` paragraph, a contract clause), mirror it verbatim with only the path or name swapped.
- Task files carry `# Summary`, `# Specs`, `# Notes` (some add `# Acceptance` or `# Open questions`): completed-work facts append under the existing `# Notes` heading (never a second one), assumptions and open points under `# Open questions`. Commit messages state only verified facts — diff old vs new output before claiming byte-identity or behavior parity.
- Board task files are `.kanban/<NNNNNN>_<slug>.md`, the number zero-padded to 6 digits (`padStart(6)` in `src/kanban.ts`): look one up by padded glob (`ls .kanban/000281_*.md`). An unpadded number pattern (`280_`, `^(280|281)_`) matches nothing and costs only re-guess rounds.

## Blocked and verification tasks

- Settle a blocked or verification-only verdict from evidence in hand, in one start batch: the landed-on-main pair (`git log --oneline HEAD..main` plus merge-base), the blockers' board state read by zero-padded file name, and the absence greps for the expected contract across src, tests and docs (empty results are the expected evidence). The deliverable is one baseline suite run or assert count plus the blocker note under `# Notes`, then stop: a no-diff verification makes no commit (the daemon commits board files itself).
