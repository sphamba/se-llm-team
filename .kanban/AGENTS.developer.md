# developer

Project-specific guidance for the developer role. Facts here are verified: trust them without re-probing. At wrap-up, record each durable lesson as one Project-facts bullet; editing this file is the recorded way to keep lessons.

## Task start

- Plan the whole run in one pass: read list, edit list, check command, in the first thinking block. Fire independent reads and greps in parallel in one block; never one read per block with a plan-only thinking block between (#245, #247, #248). Locate before you read: grep the selector, assert text, or function name for offsets first, then one read per hit; no blind offset slices (#238). One grep per symbol or topic, no re-greps with a narrower scope, even when a later block re-raises the question (#245, #249, #260; #252 re-ran the cardStats grep and the git status twice).
- Judge the diff size before the read set. A one-line or small fix (label, color, chip, condition) reads the one helper and its test plus one `cat` of the task file: no knowledge-base search, no extra source files, no caller sweeps beyond the grep that names the helper (#227, #226, #239). Colors: mirror the nearest existing pattern, edit the test first, then the source (#226, #240). One grep for the old value across src, tests and docs is the allowed extra sweep for any changed pin (#240, #244). Comments fall under "add nothing unrequested" (#239).
- Decide once, then act, in the thinking block where the question first arises. Never open a second design pass: re-drafting the same shape, assertion, placement, or open question in later thinking blocks is the top budget sink (#230, #232, #237, #243, #244, #250, #251). A settled verdict stays closed: board history, scheduler races or other irrelevant evidence never re-open it (#252). On a big task the design lives in the todo list, written once; later thinking blocks diagnose red runs only (the first Error line), never re-design. An ambiguous or contradictory spec point gets one reading, the simplest that satisfies the acceptance criteria: implement, then record the choice as an assumption under # Open questions (#224, #228). A mechanism the spec or Project facts names (payload split, alive semantics, stats summing) is a fact: implement against it, never re-derive it from source (#247, #251); an import list or a boot shape gets one decision too, never include-then-drop reversals across later blocks (#261 blocks 25-32).
- A blocked or verification-only task (blockedBy subtasks not landed, the pinned contract absent from the base): the deliverable is the blocker note. Evidence is one grep for the named endpoint or export in src, plus one baseline suite run or assert count for the note; append it under # Notes and stop. The scheduler race that spawned you early is not your scope: no pipeline.ts reading, no blockedBy greps, no board-repo history, no worktree timeline reconstruction, no implement-vs-report re-litigation, and never implement a sibling subtask's scope in the parent worktree (#252: about 20 of 49 blocks went to root-causing the promotion race).
- A revert-style removal (drop a feature) plans the inverse of the adding commit in the first pass: one full `git show` of that commit (never `--stat` plus a second full show, #249), one grep per removed symbol across src, tests and docs, then one edit batch that removes the source, its test pins and its incidental touches (a label fallback goes back with its test pin). The scoped red-then-green run is the whole proof: no live check, no daemon, no Playwright unless the criteria explicitly demand one (#249). Removal adds exactly one fact bullet under Project facts ("dropped in #NNN, do not reintroduce"): requested cleanup, not an addition.
- Pin shipped wording or bytes as a literal expected string, never a file read inside the test (circular), and never a regex where a literal `includes` of the spec's value works (#240). Derive every expected literal with a node one-liner that prints the transformed content; never hand-write it (#250). A formula or geometry change gets its constants in one pass, expected test strings from the same one-liner, rendered text extracted once, then one suite run; no repeated hand arithmetic in thinking (#228, #238).
- Test-first: add the failing assertion first for behavior changes, run the suite once, then fix. The failing run is the before-proof; never re-verify pre-fix behavior by hand afterwards (#227). A red run may fail at import or syntax time (missing export, missing import, duplicate declaration); that still proves the tests are new: fix the error, do not add stub exports to reshape the run (#230, #243).
- A new orchestrator smoke part copies the nearest existing part's harness and notes the sweep order and log-index rules once (#229). After one failed full check run, write one minimal probe that varies every hypothesis in one script (see Live webui checks); never one check run per hypothesis or a hypothesis chain in thinking (#234, #247, #250, #251). Keep harness time small: #234 spent 60 of 155 blocks on new wait helpers and #251 about 50 of 95 on one live check.
- When spec numbers (line counts, ranges, a referenced file) disagree with the worktree, one validation closes it: confirm the spec's named anchors and one `grep -c "assert\."` over the extracted slice, implement with the worktree's numbers, and record the shift under # Open questions. Never re-probe git history for the mismatch or re-check the same numbers in a later block (#261 blocks 9-13).

## Scope and process discipline

- Read each target file once, then edit. Edit anchors come from read output already in context, an exact copy of the lines, leading whitespace included. Never re-read lines you hold (#237, #242). On a match failure: one byte check of the exact lines (`cat -A`), then one retry; never re-read the whole file (#231, #242). An anchor goes stale when your own edits shifted the lines: grep the enclosing symbol, read the small slice, copy it verbatim; never assemble oldText from memory, from strings built in thinking, or from a stale in-context copy (#247, #250, #260 blocks 45-53).
- edit calls take edits as an array of {oldText, newText} objects, never a JSON string (#237). A failed batch applies nothing: keep batches small (#242) and re-apply every edit of the batch on the retry, or the loss surfaces as a swallowed error and a long hunt (#250). An empty newText deletes the match (#249). An edit whose oldText equals its newText is a skip (#244).
- Appends and SPECS.md bookkeeping: an end-of-file append (role-file bullet, SPECS notes, task body) goes through bash (`cat >> file`, heredoc or printf), never an edit anchored at the tail; this removes the anchor-mismatch class entirely (#260 blocks 44-53). Inside a list you hold from a fresh read, oldText ends at the last line you keep and newText repeats it unchanged before the addition; never drop existing lines (#244). Completed-work facts go under the task's # Notes; assumptions and open points under # Open questions (a missing heading gets added with the assumptions in one edit; never re-read the body to check first, #230). Draft the notes text once, append once: no wording pass, no placement re-work, no pre-append heading or tail check (#261 blocks 47, 53-54; #252 added a heading count, a byte dump and two note re-reads for one append that landed first try). Task-body edits: deviation note under the affected requirement, delete answered open questions, mark confirmed assumptions, one edit call (#228). Anchor every mid-file SPECS.md edit with unique surrounding sentence text, never a bare heading.
- Sweep completeness before an edit batch: one grep per field read, per old symbol, and per changed user-visible string across the whole target file, and fix every hit in the first batch. When a change makes the daemon mutate existing files (gzip, sweep, rename, compact), the same sweep covers every suite pin of the old path or extension (#250). When a function turns async or splits into light + heavy, the same sweep covers every field of the old return shape and every old-name call site: convert all callers to await in one batch (#248, #242, #244).
- New-code plumbing is checked in the pass that writes it: new module-level symbols that tests import get `export` at declaration, and a new test part's fs and symbol uses are grepped against the suite's import lines before the run (#250).
- A repo-specific sentence removed from agents/*.md or SKILL.md goes as one bullet into .kanban/AGENTS.<role>.md in the main checkout, under the closest section (#225).
- Verification budget: the scoped suite plus one git diff prove an edit. Do not re-read the edited region, re-grep your own notes, re-check your own wording, or re-run a suite that already passed (#228, #231). To check something you wrote, one grep or read settles it; never re-parse your own escaped tool-call output in thinking (#232, #243, #244). A temp file you wrote this session is trusted content: analyze it with one grep batch, never re-read it slice by slice (#260 blocks 13, 19, 21). One exception: a batch that hooks one new call at several integration points gets one hook-count grep before the suite run (#237).
- The scoped suite is the whole test scope: do not grep other suites for imports of the changed file (#238); a barrel re-export edit pulls no other suite (#249); "pnpm test passes" is boilerplate: the scoped suite satisfies it, run no full suite, state the deviation once in # Notes (#239). A live check is not boilerplate: run one only when the criteria name behavior the scoped suite cannot pin (removal chores never do), and build its fixture from the recipes below (#243, #251). scripts/test-changed.mjs maps changed files to suites; a shared file (src/hub.ts) also pulls the multi-minute orchestrator suite (#242).
- Skip hindsight_reflect and similar long remote calls mid-task: it timed out at 300 s with a 504 and no results (#244). A remote call that times out is never retried; the verified facts live in this file.
- Wrap-up: one git log plus one git status is the whole wrap-up. No suite rerun, no .kanban symlink re-derivation or ls verification; /tmp fixtures need no cleanup (#231, #243, #244, #245). One git status is the commit step's own check, with no thinking block around it (#240).
- Keep each bash call single-purpose and small; one oversized call truncates, hides the result, and forces a rerun (#225, #228, #251). An untracked file in git status is usually not yours: check mtime or git log once, then move on (#226).
- Fix the acceptance battery before editing: the greps plus the one suite that reads the real files (plugin.test.ts for SKILL.md changes). Run it once before commit and once at the end. No mid-check re-derivations of match counts.
- Todo list: one item per requirement, not per edit. todo calls take the action field (#245).

## Running and testing

- Tests are plain assert-style ESM scripts, no framework: `node tests/<file>.test.ts` per file, `pnpm test` for the suite, `pnpm test:changed` for the scoped run. There is no typecheck: `npx tsc` prints "This is not the tsc command you are looking for". The repo runs `.ts` directly through node, so the suites are the only check.
- Before you add a test block to an existing suite, grep that file once for every planned local name (stubs, variables, helpers) and every fs or helper use against the import lines, before the first write: a reused name or a missing import each cost a red run, a diagnostic round and a rename (#243, #248, #250).
- A new fixture log in an existing suite: grep the suite once for full-enumeration asserts (a deepEqual over an agents array) and place the new test after them (#247). Runs sort newest-first by log mtime, so the fixture log written last lands first: no utimesSync backdate (#247).
- A fixture rewrite that must invalidate a cache changes what the cache keys on, not just the value: logStats and subagentLogs (src/webui/payload.ts) key on path + size + a head fingerprint of the first 4 KB (#250). Pick rewrite values that change the head bytes or the byte length; check the cache key once before writing the test (#245, #251).
- Run suites separately, redirect full output to a file in the same command (`node tests/x.test.ts > /tmp/o 2>&1`), and slice the file afterwards (grep "Error" with context, then the summary line; a grep narrowed to AssertionError misses crash types like ENOENT, #250). Never pipe the live run through head or tail: a cut hides the summary line and forces a second full run (#229, #232, #237). The first Error line in the redirected log is the whole red diagnosis (#242).
- A failure whose output ends parsing "hub error" as JSON means a hub route's handler threw: src/hub.ts:324 swallows every handler exception into that plain string. Write the minimal node probe of the payload functions first (see Live webui checks), never a hypothesis chain in thinking (#250).
- PAGE (src/webui/page.ts) is one template literal served as the whole client. A regex written inside it loses its backslash: write `\\.` where the served string must hold `\.`, and asserts on served text match the built PAGE string, never the source-file bytes. Any assert that regex-extracts a value gets one node one-liner print against the real string before the first suite run; NaN in a failure message is the regex-missed signature (#237, #239). Exported helpers interpolate with `${fn}`: Function.prototype.toString strips the `export` keyword, so the served string stays valid (#244).
- Webui suite split (#254-262): all five groups are on main (tests/webui/hub, board, logpane, agentlog and page.test.ts; the page split landed as e5d7d1a). Parent #256 deletes tests/webui.test.ts and retargets the test script after the split chores land, so tests/webui.test.ts coexisting with the group files is expected: do not investigate it (#261 blocks 50-51). The page CSS and SVG facts live in the webui tests (verified by grep, #238). In tests/webui/ group files HERE is tests/webui: repo-root paths need join(HERE, "../.."), a src probe join(HERE, "../../src"), and src imports are ../../src/*.ts (#259). src/webui.ts is a re-export shim for ./webui/index.ts and does not re-export PRIORITY_RANK: import it from src/kanban.ts.
- Verbatim test lift (the suite-split recipe): trust the spec's line ranges, never hand-count them. One pass: extract each range once with `sed -n '<a>,<b>p' <old> > /tmp/range`, then the dependency checks in the same block: one identifier-count loop over the slice, each planned symbol against import lines and module exports, one grep per ambiguous hit (string literal vs real use), line-number greps for out-of-range identifiers the slice reads (copy their definitions in with the header), and one grep of src/hub.ts for unref/close when the boot starts a hub. For a standalone group file, copy the nearest existing group's boot plus the spec's boot lines; boot guards are plain `if (!x) throw`, never assert.*, when the count is pinned. Append with `cat`, close with the boot's process.on cleanup or the group's trailing teardown, then verify once: `grep -c "assert\."`, one run, and one byte-identity diff per slice (`diff <(sed -n '<a>,<b>p' old) <(sed -n '<c>,<d>p' new)`); never grep-derived line variables in shell arithmetic (an empty match builds a broken sed) and never hand-counted offsets (#261). A referenced sibling group file may sit on an unmerged task branch: if its read fails with ENOENT, pull it with `git show <commit>:<path>` (hash from one `git log --all --oneline -- <path>`), never a second path guess (#261 block 16).
- log() (src/orchestrator/log.ts) echoes to stdout unless fd 1 is the log file itself (dev+ino check, #233). The daemon harnesses (runDaemon, sEnv/sFlag, the hub and worktree parts) assert log() lines from the daemon's piped stdout, so never drop the non-TTY echo without moving those harnesses to read the log file first.
- The .pids janitor (janitorPids in src/orchestrator/pipeline.ts) sweeps .exit files by name shape: a new marker file in .pids must join its keep rules or the sweep deletes it within one sweep (#229). Paired guard: spawnRunAnalysis (src/orchestrator/spawn.ts) skips when the per-run `<slug>.<role>.<n>.analysis.exit` marker exists, or when the run already has its report or its doctor log, plain or gzipped (#250), so a failed analysis spawns once; the to-merge sweep fires the per-run analysis before the merge pass.
- To make a spawned analysis fail deterministically end to end, hand-write the finished run's log as a corrupt .log.gz (the compactor pattern skips .gz and the runner's gunzip throws); chmod 000 on the plain log races the sweep's retro-compact.
- Commit messages state only verified facts. Diff old vs new output before claiming byte-identity or behavior parity; an overclaim forces a soft-reset re-commit (#224).
- Analysis prompt builders live in src/efficiency-analysis.ts (splitAnswer, doctorPrompt). There is no src/orchestrator/prompts.ts (#228).

## Test-harness waits

- A wait loop over spawned processes must sleep between checks (about 50 ms): a synchronous busy spin blocks node's event loop, the SIGCHLD reaper never runs, and the exited sh wrapper lingers as a zombie whose /proc entry keeps pidAlive true forever (#234). Make the helper async and wait for the exit file AND a dead pid (both, not one: the wrapper writes the exit file about 35 ms after spawn but can still be alive across the test's next synchronous call).
- When such a wait misbehaves, suspect the reaper before the spawn. Confirm with one minimal isolated probe (spawn a stub, loop, watch /proc/<pid>/stat and cmdline), never by re-reading the spawn and pid code (#234 cycled three hypotheses and every one was wrong).

## Temp fixture scripts

- A temp orchestrator part lives in tests/ from the first write, never /tmp: relative `../src` imports break from /tmp with ERR_MODULE_NOT_FOUND (#229). Temp scripts outside a package need the `.mjs` extension; when a fixture must keep a specific name (e.g. `orchestrator.ts` for cmdline matching), drop a `package.json` with `{"type": "module"}` next to it, else node loads the `.ts` as CJS.
- Write a temp fixture script complete on the first write: call shapes from the tests (setState takes a Task from getTask(root, file), not a file reference) and JSONL record shapes from the fixtures the tests build. A wrong call costs a TypeError, a signature grep, and a rerun (#226).
- Never patch temp scripts with sed. Use the edit tool: sed clashes on `|` and `/` delimiters and can leave broken syntax that kills node (#226).
- Verify a new fixture with find, not ls -R: ls -R does not list hidden dirs (#227).
- chmod 555 on a directory does not block writes to a file that already exists inside it: to make a create-or-write fail in a test, delete the file first, then lock the directory (#234).
- Worktree fixture doubts (index flags, history) settle with one command pair: `git -C <wt> ls-files -v` (S marks skip-worktree) plus `git -C <wt> log --oneline` (#234).

## Stale-test triage

- A suite failure on prompt text: do not build a harness first. Read the assertion, then grep the prompt source (agents/*.md) for the asserted phrase. If the phrase is absent at HEAD, the test is stale: `git log -S'<phrase>' -- <file>` names the commit that dropped it; a one-line assertion fix ends it (#224: a stale agents/merger.md assertion cost 40% of a developer run).
- Flake vs regression: `git stash push`, run the failing suite at HEAD, `git stash pop`, before any hypothesis work. An orchestrator part with no plausible link to the diff is a timing flake until HEAD proves otherwise (#242). One rerun closes a confirmed flake. Fix real test-race flakes at the root cause: gate the fixture write against the racing machinery (an openQuestions-backed task is never promoted).

## Test recipes

- To intercept src module internals from a test (fs calls, hooks inside a function), spawn a child with `--require <preload.cjs>`: patches to `require("node:fs")` propagate to ESM named imports only when installed before the first import; an in-process patch never does (facade bindings resolve at first import). Patch the fs call the reader actually uses: payload.ts reads plain logs through openSync/readSync byte windows since #250 (a readFileSync stub no longer intercepts them; the webui order part had to switch), and readFileSync before it.
- Deterministic interleaving in orchestrator tests: drive `rescan(root, cfg)` and `poll(root, stallMinutes)` directly (import `rescan` from `../src/orchestrator/pipeline.ts`, `poll`/`loadConfig` from the facade; temp HOME via mkdtempSync + loadConfig; `cfg.agent = <stub>`), instead of daemon timing races. A stub that Atomics.waits ~1 s keeps a spawned agent alive across the next synchronous call.
- Asserts on end-of-run state go before the call that clears that state: symlink/readlink asserts come before poll (clearContextSymlinks runs at run end); file-restored asserts after it (#234).
- Idle-gate tests: drive `promoteBacklog(root, listAll(root), windowMinutes)` directly and age a file with `utimesSync(path, new Date(Date.now() - 10_000), ...)` (0.05 min window = 3 s). The quiet window is board-wide but only over real task files: ROLE_NOTES_RE names (AGENTS*.md) do not count (#212).
- Hub election runs unexported inside `joinHub` (src/hub.ts), so test it by spawning `src/orchestrator.ts` with an isolated HOME plus XDG_CONFIG_HOME and the webUi block in the legacy HOME config (tests/orchestrator.test.ts parts U-Z). The election must degrade, never throw: an unwritable neutral dir must log the real error code and path and leave the daemon sweeping (part Z2: mkdir EACCES and lock EACCES with a chmod 555 dir; restore 0755 in a finally or the exit cleanup cannot remove the fixture).
- To iterate on one late part of tests/orchestrator.test.ts without the full multi-minute suite, extract the file preamble plus the definitions of every identifier the part references into a temp `tests/*.ts`, run it, then delete it. Re-locate the part by its `// --- part` marker, not by line number (#229).
- Prompt byte pins (tests/efficiency-analysis.test.ts): `analyseLog` reads `agents/*.md` from the package root by default, so an equality against a literal helper pins the shipped wording per the pin rule. Get the exact literal from a temp `tests/tmp-*.ts` that calls analyseLog with stub runners and prints JSON.stringify(prompt), then delete the temp script (#228). A stub answer `"S: x\nStruggle: none"` renders summary `"S: x"`, because splitAnswer strips only a literal `summary:` prefix.

## Environment and safety

- In a task worktree, `.kanban` is a symlink to the main checkout's board and SPECS.md is a symlink to `.kanban/<NNN>_<slug>.md`, your task's file: writing either edits the main checkout, and git in the worktree reports `.kanban/...` as "beyond a symbolic link" (never stage or commit those). The daemon commits board changes itself. Board files are untracked in the checked-out branch: the daemon mirrors them onto refs/heads/meta/kanban via git plumbing and pushes, so `git log -- .kanban/` prints nothing and board history is `git log meta/kanban --oneline -- <file>` (or `git log --all -- <file>`) (#252: three hypothesis cycles around the empty log). The main checkout root also carries a SPECS.md symlink that rotates to the current active task's file; greps or tails on SPECS.md fail from any cwd other than a root (there is none inside .kanban or .kanban/.logs), so run them from a root or through the resolved numbered path (#252: a grep and a tail failed on the name).
- Read-only HOME mounts: ~/.pi and ~/.config are read-only bind mounts on this machine, so any test or close() flush that touches the real user config dir crashes (or pollutes it on normal machines). Close in-process hubs before restoring the real HOME, and keep global-state tests on fixture HOMEs (#215).
- A worktree commit needs `git -c commit.gpgsign=false commit`: ~/.gnupg is a read-only mount here, so plain `git commit` fails with "gpg failed to sign the data" (#215, #244). Stage first: a bare commit with unstaged edits fails with "no changes added to commit" (#248).
- `process.env.X = undefined` sets the env to the string "undefined" in node: use `delete process.env.X` when restoring an unset variable, else later code resolves paths like undefined/se-llm-team and litters the cwd (#215).
- Neutral shared paths (#215): the global config, hub registry and hub lock live at $XDG_CONFIG_HOME/se-llm-team/ (else ~/.config/se-llm-team/), with the legacy ~/.pi/agent paths as read-only fallbacks; every temp-HOME test env must also set or delete XDG_CONFIG_HOME, since the real environment may set it and leak the production config into tests.
- Large argv: the kernel rejects a single argument over 131,072 bytes with E2BIG (MAX_ARG_STRLEN); node spawn reports it as a child 'error' event and the child never starts (#213). The AGENTS.md injection cap (PROJECT_PROMPT_CAP, src/orchestrator/spawn.ts) is 131,000, covered by a real stub spawn in tests/orchestrator.test.ts (#214).
- Daemons under test never touch the production webui. Smoke daemons start with `--no-webui` (or SE_LLM_TEAM_NO_WEBUI=1), because a smoke daemon reads the global config and binds the production webui port, wedging the real UI. Live-check daemons get the fixture its own per-root port in the project config (see Live webui checks), never the global one.

## Live webui checks

- Fixture (reusable recipe, #205/#206, #243, #250): temp root `/tmp/<name>/root` with `.kanban/000001_probe.md` (long body) and `.kanban/se-llm-team.json` `{"webUi":{"enabled":true,"host":"127.0.0.1","port":4399}}`. 4399 works; a leftover check daemon from an earlier session can hold a port. `/api/tasks` serving a board you did not seed means a foreign daemon holds the port: switch ports, do not hunt its pid. Seed the probe task in state `done`: a `backlog` task auto-promotes to `to-do` at the first sweep and the daemon spawns a real agent for it. Build the fixture in one pass straight from these recipes; no source reads of payload.ts or logpane.ts first (#248, #251).
- Daemon: `node src/orchestrator.ts --root <tmp> --rescan-seconds 30 --poll-minutes 5 &` (the CLI entry is src/orchestrator.ts; src/orchestrator/main.ts has no self-call and exits silently). Run it with an isolated HOME and an isolated or deleted XDG_CONFIG_HOME: under the real HOME the production daemon holds the global hub lock, and the probe logs "hub lock held by another daemon, standing down" with no UI. The up check is the curl of `/` plus `/api/tasks` returning your seeded board; the daemon may log no webUi or listen line at all (#247), so do not hunt for one. The daemon serves the PAGE constant built at startup, so a page.ts edit does not go live until the daemon restarts (#237): restart the check daemon after every page.ts edit.
- Playwright script: module at `/home/phamba/repos/paseo/node_modules/playwright/index.mjs`. Write a fresh `/tmp/<name>/check.mjs` each run. Health-probe with `curl -sf http://127.0.0.1:<port>/`; `/api/task-detail?num=N` is light task text only; `/api/task-history?num=N` carries agents, doctors, log stats and sub lists (payload split v2, #248); `/api/board` is 404 in this build. Cadence (#251): the log pane text polls every 1 s (pollLog); detail stats, subs and doctor cards refresh on 1 s while any card is alive, else 5 s (pollDetail). Wait for a 5 s tick before a stats assertion, and for a 1 s tick before a log-growth assertion.
- Script hygiene (#251): a Node-side constant does not exist inside a page.evaluate callback: inline the selector string, never reference the script's own const (a ReferenceError kills the check mid-run). Script-scoped `let`s are invisible to a second probe: export them on `window` if a probe must read them. Pane-growth order: an idle doctor log renders an empty pane at open, so click, wait for the pane to unhide, capture the pre-growth text, then append and wait for growth; waiting for text before the append times out.
- Measurement validity (#248, #251): a timing test that returns an impossible number (a 37 MB cold parse in 1.8 ms) means the harness is invalid, not that the code is fast. Suspect, in order: a backgrounded setup step (shell precedence: `A && B & C` backgrounds the whole AND-list, so group it `{ A && B; } & C` or run setup in the foreground), a cache hit (path + size + head keys since #250; a done task also hits the doneAgents memo), a foreign daemon, a cold parse mid-flight (after a daemon restart the first history fetch cold-parses: one warm request before counting cards). One check each; the probe rule covers the rest.
- Browser-API probes: when a browser API blocks a live check, write one probe script that varies every launch configuration in one run (plain headless, `--headless=new`, `channel: "chrome"`) instead of one full check per hypothesis (#244). Pin the API seam in the page (a stub or Object.defineProperty) instead of fighting the environment.
- Agent-log live check (#243): run logs `.kanban/.logs/<slug>.developer.0.log` and `.developer.1.log`, each with a `session` record plus `message_end` records; `message_end` records with text or thinking content blocks render as text in the log pane (the claude stream-json branch renders assistant text/thinking and user prompt/tool_result blocks). Give the two runs distinguishable text to test agent switching; an aborted init fetch (page route interception) tests the failure state.
- Sub-card fixture (#251): subagentLogs (src/webui/payload.ts) parses only `tool_execution_end` JSONL records in the run log whose result text holds `Agent ID: <id>` and `Output file: <path>`; the resolved path must start with SUB_ROOT (`/tmp/pi-subagents-1000/`) and end with `.output`, else the record is dropped. Seed one such record in the run log plus a real output file under that root; rewrite so the head bytes or the byte length change, to beat the path/size/head cache (#250). Write the run log and output file right before the check: the daemon compacts finished plain run logs to .log.gz within minutes.
- Relation-line checks (#237): relation paths (`#relations path`, `#agent-relations path`) are stroked with fill:none and have a zero-height box, so default Playwright visibility waits time out: wait with `state: "attached"`.
