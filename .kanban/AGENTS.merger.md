# merger: append project-specific guidance for this role below (e.g. how to run the project, how to live-test) so future agents of your kind start faster.

- SPECS.md in the worktree is a symlink to .kanban/<NNN>_<slug>.md, and .kanban itself symlinks to the main checkout's .kanban dir. Edits through SPECS.md already land on the main checkout's task file. Do not copy the file.
- Inspect once, then resolve. One `git status` plus one full `git diff` (never piped through `head` or `tail`) shows every conflict with both sides. Resolve straight from that diff. Do not re-read whole files, grep for conflict markers, or rebuild the branch history first. Decide each hunk from the two sides, the Specs, and the rule below. Read one hunk only if the diff side alone is unclear.
- Conflicts usually hit import/export lines in test files of merged feature commits replaying over a newer base. Base branch wins unless the task Specs mention the file. If the base removed a feature, take the replayed side minus the removed symbols. One grep for a removed symbol in the staged files confirms the removal stands. Then one edit per hunk, then one chained command: a marker grep (hits inside test fixtures are not real conflicts), `git add <files> && GIT_EDITOR=true git rebase --continue && git log --oneline -3 && git status`.
- This environment may fail to GPG-sign commits. Symptom: a `rebase --continue` that stops at the commit step while the pick is listed in both done and todo and HEAD still sits at the base. Fix for each such pick: commit the staged changes manually with the original message, author and date plus `--no-gpg-sign`, then `GIT_EDITOR=true git rebase --continue`. The rescheduled duplicate then drops as "patch contents already upstream". Never amend in this state, it would fold the task changes into the base commit. Expect one stop per remaining pick.
- Tests: run `npm test 2>&1; echo EXIT=$?` directly. Do not read package.json first, it is a hardcoded chain. Only if the replayed commit adds new tests/*.ts files, also run those directly: `node tests/<name>.test.ts`. Do not truncate test output with `tail`. Grep for FAIL or Error instead.
