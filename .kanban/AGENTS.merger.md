# merger: append project-specific guidance for this role below (e.g. how to run the project, how to live-test) so future agents of your kind start faster.

- SPECS.md in the worktree is a symlink to .kanban/<NNN>_<slug>.md, and .kanban itself symlinks to the main checkout's .kanban dir. Edits through SPECS.md already land on the main checkout's task file. Do not copy the file.
- Conflicts usually hit test files from merged feature commits replaying over a newer base. Base branch wins unless the task Specs mention the file. One edit per conflict hunk, then `git add <file> && GIT_EDITOR=true git rebase --continue`. Grep hits for conflict markers inside test fixtures are not real conflicts.
- This environment cannot GPG-sign commits (commit.gpgsign=true, ~/.gnupg is read-only). Symptom: a `rebase --continue` that stops at the commit step while the pick is listed in both done and todo and HEAD still sits at the base. Fix for each such pick: commit the staged changes manually with the original message, author and date plus `--no-gpg-sign`, then `GIT_EDITOR=true git rebase --continue`. The rescheduled duplicate then drops as "patch contents already upstream". Never amend in this state, it would fold the task changes into the base commit. Expect one stop per remaining pick.
- `npm test` is a hardcoded chain in package.json, so new tests/*.ts files from the feature branch are not in it. Run those directly: `node tests/<name>.test.ts`. Do not truncate test output with `tail`. Grep for FAIL or Error instead.
