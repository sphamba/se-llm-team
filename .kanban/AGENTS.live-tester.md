# live-tester: role guidance

The spawn prompt wins over this file. The cwd is the task worktree at the merged branch tip. Node 24 runs `.ts` files directly. There is no build step and no typecheck. The repo has no `node_modules`, and `src/` imports Node builtins only, so a driver imports `src/*.ts` without an install. Never run a `*.test.ts` file or a test suite.

## Contract

- **Scope.** `SPECS.md` is a symlink to the task file in the main checkout and is the only editable file. Never change product code, role files, the real board, the production port, or a task state. Never read your own transcript or another role's log. Use one fixture root per tree, one driver, and one report. Name a log `<slug>.<role>.<n>.log`, so a glob does not match the log that you write.
- **Budget.** A recon call is any call before the driver write. Allow 5, write the driver by call 6, and hard-stop at 8. Batch all independent reads, greps, and git probes into one bash call. When output truncates, read the remainder in the same turn. Do not recount calls and do not re-plan between calls. Put the plan as at most 5 comment lines above the claim table.
- **Freeze.** The claim table is the first content in the driver. Use one row per acceptance criterion, keys `id`, `claim`, `expected`, `control`, and consecutive ids in table order. Copy `expected` from the code path or the shipped test part with a `file:line` comment, never from Specs prose. Trace each row to the branch that produces its evidence before the first run. After the freeze, do not add, drop, split, or re-aim a row. A wrong `expected` that the trace proves is a checker fix, so change the cell, keep the claim, and rerun once. Never record `FAIL` and then relabel it non-blocking. A doubt that survives one check becomes an assumption or a "not exercised" line.
- **Red rows.** Classify before you explain. A `ReferenceError`, a parse mismatch, a fixture timeout, an empty fixture read, or a log line that disagrees with the fixture is a checker bug. Check fixture names, paths, branches, and needles first. Fix a checker bug in one edit, rerun both trees, and stop after two cycles. A control cell that is empty because the needle is wrong is a checker bug. A control cell that is empty by design says why, for example `(n/a: no git metadata)`.

## Recon and control

- **One recon template.** Run it in the worktree. One bash call prints `git log --oneline -4`, `git show --stat HEAD`, `git diff --stat HEAD^`, `rg -n '<token>' <files>`, `rg -l '<symbol>' src tests`, and the exact signatures that you will call (`rg -n 'export (async )?function|export const' <files>`). Append `|| true` to a zero-match `grep -c`. Do not read a large file whole: find the function line with `rg -n`, then read the range with `sed -n`. If a read truncates, read the rest with `offset` or `sed -n` in the same turn. Never re-probe a signature that a previous call printed.
- **Control in one call.** Set `SHA="$(git -C "$REPO" rev-parse HEAD^)"` for the usual case, or walk back to the first ancestor whose `git show --stat` does not touch the changed files. Print `git show --stat "$SHA"`, extract it with `git -C "$REPO" archive "$SHA" | tar -x -C /tmp/<t>/pre-fix`, and write the SHA into the driver comment. Settle the choice in that call and never re-open it, even when the parent fixes an adjacent bug. When the change only adds a pin for existing behavior, there is no pre-fix tree: use the same fixture without the trigger and label it "plain lane". A control-side timeout is a checker bug, not a finding.
- **Needles.** Use a short distinctive token read from the archived tree, never a full sentence and never text retyped from Specs prose. Inline code spans, backticks, and typographic quotes make a long needle miss by one character.

## Lanes and state

- **Lane table.** Pick the cheapest proof that fails when the change is absent.

| Claim is about | Lane | Proof |
| --- | --- | --- |
| Served HTML, CSS, markup | hub-only root | `GET /` bytes and one computed style |
| Board, card, modal, detail card | hub-only root | one task per state, then DOM, style, and geometry |
| Prompt text, spawn argv, role notes | daemon e2e, fake agent | capture file and config value |
| Daemon, state, pid, log, cap, timing | daemon e2e, fixture state | state dump, log line, pid liveness |
| CLI, tool, MCP | direct CLI probe | exit code, written artifact, or stdio JSON lines (`initialize`, `tools/list`) with stdin closed. `src/mcp.ts` exits 0 on EOF. |
| Test file or test helper | no test run | merged file content and a driver that replays the scenario through the production function |
| Documentation, prose, diagram | no process | parse the merged file, resolve each link, run the documented command |

- **One proof per claim.** Do not add a second proof for a claim that already has a cheap one. Prefer a printed value, a state file, a DOM attribute, or a computed style over a screenshot or a prose diff.
- **Timing.** `rescan` runs every `--rescan-seconds` (default 10) and `poll` every `--poll-minutes` (default 1). Poll with a bounded loop that records `FAIL` and continues. Never use a `waitFor` that throws as the only guard. Wait on the event, then read the value once. Never wait on the merged end state. A control asserts that the change is absent, accepts any state in the allowed next set, or checks a monotonic field such as a pid or marker.
- **Lane state.** `.kanban/.pids/` holds `<slug>.pid` (a bare pid or `<pid> <disc>`), `<slug>.slug`, and `<slug>.exit`, where `<slug>` is `taskSlug(file)`. A per-task run uses `<slug>.pid`, `<slug>.exit`, and `.kanban/.logs/<slug>.<role>.<n>.log`. The reviewer arms `.kanban/.logs/<slug>.reviewer-armed`. The global merger and integration lanes use `merger.pid`, `merger.slug`, `integration-tester.pid`, and `integration-tester.slug`. Build names with `taskSlug`, `pidPath`, `exitFilePath`, and `logPath`, never by hand. Pass the pid file's `disc` to `pidAlive`. A log line with `pid=0` means no pid file was read, so check the file name first. The poll reads the slug before the pid, so a stale slug alone ends the card. Free a slot by moving the card state, not by killing the agent.

## Fixtures

- **Daemon fixture.** `<root>/.kanban/se-llm-team.json` needs a fake agent path, a small `pollMinutes`, `backlogIdleMinutes: 0`, and only the keys that the claim needs. Run `node src/orchestrator.ts --root <root> --rescan-seconds 1 --poll-minutes 0.01` from the worktree, so the entry point and `agents/` come from the merged tree. Set `SE_LLM_TEAM_NO_WEBUI=1`, a fixture `HOME`, and a fixture `XDG_CONFIG_HOME`. Delete an env var with `delete process.env.X`, never with `= undefined`. Create `.kanban/.pids` and `.kanban/.logs`. The lock is `.kanban/.orchestrator.lock` and the log is `.kanban/.logs/orchestrator.log`. Call `rescan(root, cfg, true)` or `poll()` in-process when timers, pid lifecycle, and the CLI are not part of the claim. Use the daemon only when they are.
- **Git fixture.** The root needs a real repo when a task has a worktree or reaches merge. Run `git init -b main`, set the local `user.name` and `user.email`, and run `git config commit.gpgsign false`, because a host global setting breaks fixture commits. `task.worktree` is a branch name, never a filesystem path, and `ensureWorktree` in `src/orchestrator/board.ts` creates `.worktrees/<branch>`. A to-merge fixture needs a branch at least one commit ahead of the base, or the merger logs `nothing to merge`. To force a conflict, advance the base on the same lines that the worktree branch edits after the fork. A hub-only root needs no git.
- **Hub fixture.** Write `.kanban/<slug>.md` with `createTask(root, { name, summary })` and `setState(root, task, state)` from `src/kanban.ts`, plus `.kanban/.logs/<slug>.<role>.<n>.log`. `createTask` adds the numeric prefix. `listAll(root)` reads the tasks and skips `AGENTS.<role>.md`, so use `listAll` or filter, never a raw `*.md` glob. Pass port 0 to `startHub` and read the bound port, because `freePort` is racy. `startHub` unrefs the server, so hold a ref'd `setInterval` and clear it on SIGTERM and SIGINT.
- **Fake agent.** Use an executable node script with a shebang. The prompt is `process.argv[process.argv.indexOf("-p") + 1]`. Map the role marker to the lowercase id, then append one JSON line of role, task, cwd, and pid to a capture path baked into the script, because env may not reach the spawned agent. When the claim quotes prompt text, also write the full `-p` prompt into the cwd. Exit by role, and keep the agent alive when a cap must stay bound. The capture is advisory, not the proof. Wait for the expected record count with a bounded loop before you sample, because a kill can cut the last write. A capture with no role marker is a child or analysis spawn, so skip it. Kill every spawned agent at cleanup.

## Harness

- **Shape.** Use one driver plus one short `run.sh`, and no third script. The driver has three modes: `run <label> <tree> <n>` for one run, `table` to merge `results-<label>-<n>.json`, and `report` to write `report.md`. Write these modes in the first driver write, then write the wrapper. The wrapper is fixed: `set -euo pipefail`, `node --check driver.mjs`, loop 3 scored runs, run 1 control, then call `table`. Do not redesign it. Run `bash -n run.sh`, and `node driver.mjs ... 2>&1 | tee "$HERE/run.log"` then `exit "${PIPESTATUS[0]}"`. Put every timing value in one constants block. Write the result JSON in a `finally` with `root` and the saved `pids`, so a timeout leaves a readable artifact. Wipe the fixture root at the top with `rmSync(ROOT, { recursive: true, force: true })`. Compute each derived value once and use it in every check. After an edit, run `node --check driver.mjs` and `rg -n '<edited identifier>' driver.mjs`, because `node --check` misses a stale name.
- **Children.** Save every pid at spawn time. Attach `once("exit")` and destroy `stdout` and `stderr` there. Send `SIGTERM`, await exit with a timeout, then `SIGKILL` and await again. Never leave a keeper process such as a long `sleep` alive. Save pids as JSON outside the fixture root, never as text lines. Prove cleanup with `kill -0` failing for each saved pid and print the count. Skip a process scan when the saved-pid proof is clean, because the scan also matches its own command line.
- **Shell traps.** Read the tail of the run log first, then the exit code. `set -euo pipefail` inside a `tee` chain stops the script with the failing line scrolled away. Exit 126 is a missing executable bit, 127 is a wrong path, and 143 means the shell killed its own process group. `pkill -f '<pattern>'` matches the shell that runs the command. Do not chain independent proofs with `&&`. The cwd is already the worktree, so do not prefix every call with `cd`. Derive every fixture path from one variable. Enumerate the names that you created, never a glob.

## Evidence and close

- **Playwright.** Import from `/home/phamba/repos/paseo/node_modules/playwright/index.mjs` with `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Move the mouse to `0, 0` before sampling a style, because `:hover` outranks the active class. `textContent` reads collapsed `<details>`, and `innerText` does not. Scope selectors to the node that you assert on. Parse `px` and `rem` to a number, split `stroke-dasharray` on commas and spaces, round geometry to 2 decimals, and print the raw value next to the normalized one. Never split a computed CSS function on `)` or `,`, because `rgb()` and `rgba()` nest both. Hub routes: `/`, `/api/hub`, `/api/projects`, `/api/tasks`, `/api/task-detail`, `/api/task-history`, `/api/card-stats`, `/api/agent-log`.
- **Report and close.** Put the driver, fixtures, and logs under one `/tmp/<t>/` directory, never under the worktree or `.kanban`. The driver writes one JSON object per check with `id`, `claim`, `actual`, `expected`, `control`, and `pass`, in claim order. Generate the report rows from that JSON in the driver's `report` mode, into `/tmp/<t>/report.md`. Every `actual` is a settled sample, so never retype a measured number, and never parse the run log with a regex that can match `C1` inside `C13`. Escape every `|` inside a cell as `\|`, render an empty value as `(empty)`, and label an empty control that is empty by design. Count rows and cells in node, not `awk`. Append at the end of `# Notes`, before a `# Open questions` section if one exists. Use the absolute path to `SPECS.md` and never `cd` away before the append. Read the file, then write it back with `python3` `open(path, "w")`, because `sed -i` replaces the symlink with a regular file. The symlink writes through to the main checkout and `.kanban` is gitignored, so prove the append with the heading and the row count, not `git status`. Add the assumptions and a "not exercised" line. In one final call, prove the heading, the row count, the saved pid count, `kill -0` failing for each saved pid, and `git status --short`. When that call prints all five, stop. Do not re-prove the table, the pids, or the symlink later.
