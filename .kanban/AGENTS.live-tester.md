# live-tester: role guidance

Live-test the merged diff as a user would: real usage paths against an isolated fixture, never the unit-test suites (they are the developer/reviewer gates — an acceptance naming a suite does not lift the ban; live-test the behavior the test pins), never the real board.

## Run order

- Plan once, then write the fixture: read the task file, take the merge hashes from its Notes and verify with ONE `git show --stat <h1> <h2>`; if the Notes name no hash or it is absent from the log (a rebased fix), HEAD at task start IS the merge (`git show --stat HEAD`), no git-log archaeology. For a removal or refactor the diff IS the surface spec: derive old-behavior assertions from the removed hunk. Resolve the task file with `ls .kanban | grep <num>`. Wrap up in one pass — report, kill recorded pids — and run the final placement grep in a LATER turn than the edit (a same-turn bash can read the file before the edit lands).
- Ledger each verified fact once in `/tmp/<t>/LEDGER.md` as it lands. Every check script prints its own tally (`N checks, M failed`); quote script tallies verbatim, never hand-sum, and judge this run by this run's tallies. On FAIL, diagnose the check script first — a script bug is not a product finding; a FAIL with correct DOM but an empty/offset measurement is a read-timing race, patch the read. Self-doubt about a file you just wrote is `node --check` (+ `wc -l`) in the next bash, never re-reads or deliberation.

## Codebase map (grep the named symbol; trust listed names)

- All `/api/*` routes register in `src/hub.ts` (never grep `src/webui*` for routes). `src/webui/page.ts` serves the whole client (PAGE template, all CSS); `board.ts` cards/chips/relations; `logpane.ts` log rendering; `payload.ts` serves /api/tasks, /api/task-detail (light), /api/task-history (heavy: agents, doctors, log stats), /api/agent-log; `src/pid.ts` has pidAlive/agentAlive. `index.ts` registers every TOOLS entry and needs a LABELS entry per new tool; `src/webui.ts` is a symbol-free re-export shim.
- `src/orchestrator.ts` is a facade (`main()` in `main.ts`; sweep every `--rescan-seconds`, poll every `--poll-minutes`, debounced fs.watch). STATES sit at the top of `src/kanban.ts`; `to-live-test` and `live-testing` are separate — a merge sets `to-live-test` and the sweep immediately spawns you, so the settled state is `live-testing`. Merge lane: rebase in the worktree (conflict spawns a merger), then `merge --ff-only` at the root. There is no `baseBranch`/`defaultBranch` symbol: branches resolve at runtime from the root checkout's current branch.
- Artifacts: run log `.kanban/.logs/<slug>.<role>.<n>.log` (`.gz` when finished — every sweep compacts finished logs), per-task pid `.kanban/.pids/<slug>.pid`, analysis wrapper `.pids/<slug>.<role>.<n>.analysis(.pid/.exit)`, PM reports `.kanban/.reports/<ts>.md` (oldest first, 1 h cutoff).

## Canonical fixtures

- Hub-only (webui/CSS/log/modal checks): the fixture root needs only `.kanban` files, no git repo. Launch via a launcher FILE that writes its own pidfile (`setsid nohup node /tmp/<t>/hub.mjs >… 2>&1 &`) importing `startHub` from the merged checkout. Isolated HOME is mandatory (hub lock/registry are per-HOME) plus `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Never the production port 4242: pick the first free port above 4349 from one `ss -ltn` scan, and if a concurrent live-tester takes it, use the next from the same scan. Make `/api/hub` (match pid + commit) the FIRST preflight call, before any data curl. The registry prunes curl-registered projects after ~15 s: pass `staleMs` or register the second project via `/register`.
- Daemon e2e (pipeline/transitions): scratch origin = bare clone with BOTH `meta/kanban` refs deleted before every re-clone; fresh clone with `git config commit.gpgsign false`. Root config `{"agent": "<fake-pi>", "pollMinutes": 0.05, "autoScheduleMinutes": 0.05}`; the fake agent is an executable node script (shebang + `chmod +x`) that appends argv+cwd to a log and acts the role keyed on the prompt's first line (the `-p` payload is `agents/<role>.md` byte for byte). Start the merged code with `SE_LLM_TEAM_NO_WEBUI=1` (else it binds production 4242) and an isolated HOME. Run the whole lifecycle (cleanup → setup → waits → checks) from ONE run.sh in ONE bash call, teed, under the tool timeout. Scope checks to fixture slugs; pair state checks with pid-alive checks (the daemon sets state before spawning, so a broken agent path still passes state asserts). Leave fixture task files UNTRACKED so the to-merge rebase never refuses.
- Differential control (old vs merged over the SAME fixture): `git archive <parent-commit> | tar -x -C /tmp/<t>/oldcode`, symlink node_modules when src has external imports, second hub on a second port with its own isolated HOME. Required for negative assertions and no-behavior refactors; skip when the acceptance names only merged behavior.
- pi session probes need the REAL HOME (an isolated HOME has no API key and no extension symlink); always prefix `SE_LLM_TEAM_NO_WEBUI=1`. JSONL recipe: `pi -p --no-session --no-context-files --approve --no-mcp --mode json "<prompt>"` with cwd = a fixture git root; the extension loads from the main checkout, which must be at the merged commit. `tool_execution_start` carries args; `tool_execution_end` carries `result.content[0].text` and `durationMs`; filter tool records by name prefix, never by count or index.
- Synthetic run logs: one JSON record per line with the real shapes. pi: `session` (ISO timestamp), `turn_end` (numeric ms timestamp, `message.usage`), `message_update.assistantMessageEvent.text_start`/`text_delta` (top-level `text_start`/`text_delta` render nothing), `tool_execution_start`/`end` pairs. Claude: system init, assistant thinking/text/tool_use, user tool_result, result record; tool records need a non-empty `toolCallId` on BOTH start and end. A live card needs state `doing` plus a live sleep pid in `.kanban/.pids/<slug>.pid` (SIGKILL and reap your own child — a zombie answers `kill(pid,0)` too).

## Playwright discipline

- `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"`; browsers live in `~/.cache/ms-playwright`.
- The modal overlay intercepts clicks: close with `#m-close`, wait for `#modal.hidden` via waitForFunction on classList (`waitForSelector` on hidden elements times out on visibility). A `:hover` rule outranks `.active` classes: `page.mouse.move(0,0)` before sampling computed styles. Board cadence 5 s, modal cadence 1 s: skip ~5.6 s before measuring any tick or duration delta; wait ~300 ms after open (entrance fade) and ~500 ms after content lands before geometry reads (in-flight transforms).
- `:visible` must sit in the SAME selector string; hidden-by-default content needs `waitForSelector(..., {state:"attached"})`; collapsed `<details>` content is invisible to `innerText` (use `textContent` or expand). Computed `color-mix()` backgrounds come back as `color(srgb r g b / a)` with 8-bit quantized alpha: parse channels with tolerance, never string-equal. Reduced-motion needs a `reducedMotion:"reduce"` context plus computed `animationName`, never a rule-text pin.
- Hold route responses to sample spinners/animations mid-flight; abort AFTER the sample point; a route-interception mode flag left in hold hangs every later fetch (reset it per phase). Wrap per-element samples in try/catch; one probe per question, output teed to a file.
- Headless Chromium cannot model a hidden/backgrounded tab (`visibilityState` stays "visible"); simulate with an `addInitScript` `Date.now()` offset plus a dispatched `visibilitychange` event with `bubbles: true`.

## Shell traps

- Never kill by pattern: `pkill -f` matches your own shell (exit 143), `pgrep -x node` finds nothing here, and a machine-wide `pkill -f orchestrator` kills the project's own daemon. Cleanup: kill pidfile pids, then `pgrep -af /tmp/<t>` from a script file (abort on any pid outside your fixture), then verify with `ps -p` and `ss -ltn`. A daemon's `sh -c` wrapper can reparent children to PID 1: read `ps --ppid <wrapper>` before killing.
- Launch background helpers with `setsid nohup <launcher> &` and let the launcher write its own pidfile with a trailing newline (`$!` after nohup records the subshell); kill pidfiles individually. Redirect every background helper's stdout or the `| tee` pipe hangs until the tool timeout.
- Write node helpers as standalone `.mjs` files (no single quotes inside a single-quoted `node -e`; EPIPE when the reader closes). Recursive search is `rg -n` (`rg -r` is REPLACE). Never nest a grep inside a sed expression or use `sed -i` with unescaped slashes — use the edit tool. `diff` exits 1 on any difference: chain independent checks with `;`, not `&&`. A check that answers by exit code prints nothing — judge by `$?`. Tee every script run to its log at launch, first run included.
- Scope port checks to the fixture pid and anchor the port (`grep -E ':<port>( |$)')` — a bare `:42` substring-matches the project daemon's `:4242`. `git init` fixtures need `.kanban/.logs` (a `>>` redirect fails without it) and `-c commit.gpgsign=false` (global gpgsign=true). Once the daemon's ensureInfoExclude names a path, a blanket `git add -A` silently skips it — commit with explicit paths. Daemon log lines are UTC ISO, fixture mtimes are local: never compare them directly.

## Report and real-board hygiene

- Report placement: append `## Live test (<date +%F>)` as a subsection under the existing `# Notes`, before the next top-level heading; plain bullets, one per finding (no inner `###` headings). Find the insert point with ONE `grep -n '^#' <task file>` + one tail read; build `oldText` from the file read, never from your command transcript; the edit tool takes an array of `{oldText, newText}` objects; never create an empty `# Open questions` section. `kanban_update` rejects a `notes` field — `# Notes` edits are direct file edits.
- Identify a running daemon only by its lock pid plus `ps` (ppid/argv); `/api/hub` returns `{pid, root, commit}` where root is the serving checkout. To pick up merged code, `orchestrator_stop` then `orchestrator_start` from a fresh session (in-flight agents survive the restart).
