## Shell traps (each killed a run at least once)

- Never kill by pattern from the test's own shell: `pkill -f <pattern>` matches the shell itself when the cmdline contains the pattern, exit 143 (#168, #210-#212, #220); `kill` of `grep -o 'pid=[0-9]*'` output hits the dead-pid `pid=0` bounce line (#211); `pgrep -x node` finds NOTHING here (#204, #210); `pgrep -f 'sleep 600'` from the test bash matches the test shell (#178). Kill recorded pids only; cleanup is this exact sequence from one bash, no plan block: `kill $(cat $T/*.pid)` -> `pgrep -af /tmp/<t>` from a script file (abort on any pid outside your fixture: other live-testers run daemons here) -> `ps -p <pid>` -> `ss -ltn | grep -F :<port>`. Never a machine-wide `pkill -f orchestrator`: it kills the project's own daemon (#168). Killing the daemon + its `sh -c` wrapper can reparent the agent shell to PID 1: read `ps --ppid <wrapper>` before the kill, kill that child too (#208). A lone pgrep hit whose cmdline is the cleanup bash itself is your own shell: ignore it, no `$$`-semantics derivation (#243 two thinking blocks; #246, #248 and #259 re-derived it).
- `$!` after `nohup ... &` records the subshell, not node (#187, #204): launch with `setsid nohup <launcher> &`, launcher writes its own pidfile with a trailing `\n` (#211, #231). A bare `String(process.pid)` has no newline, so `kill $(cat a.pid b.pid)` concatenates two pids into one invalid number and kills nothing (#258): kill each pidfile individually.
- An inline heredoc embeds the fixture path in the test shell's cmdline: a cleanup loop matching fixture paths must skip the caller's ancestor chain (#211).
- No single quote inside a single-quoted `node -e` argument in a heredoc: the shell cuts the script at the quote, the helper silently mangles output, which reads as a bug in your logic (#228). Write every node helper to a standalone `.mjs` from the start. Wrong-looking output: suspect shell mangling first, `cat -A` it and run standalone before re-reading your logic.
- Frontmatter value: `sed -n 's/^state: *//p' | head -1 | tr -d '"'`; `grep -m1 '^state:' | tr -d ' "'` leaves the prefix and fakes FAILs (#229). `sed -i` with unescaped slashes dies: use the edit tool or another delimiter (#229).
- Helpers must handle missing files: a `count_in` over an absent log prints 0 (#229). Remove fixture pidfiles between runs of one fixture dir (stale pidfile -> stale assertions, #229). Daemon fixture: also delete `.kanban/.orchestrator.lock` and truncate `.kanban/.logs/orchestrator.log` (#233). The bash `read` builtin reads stdin variables, it is not a file reader: `read src/pid.ts` errors, use the read tool (#248).
- A daemon killed right after its first log line can miss its SIGTERM handler (`main()` logs and bootstraps BEFORE installing handlers, #233): wait ~1 s after the started line before SIGTERM.
- Chain independent checks with `;`, never `&&` after a `diff`: `diff` exits 1 on any difference and silently drops the rest of the chain (#260 lost a check run to this). Many labeled probes in one bash garble their output when it truncates: one probe per question, or tee it to a file (#258).
- A check that answers by exit code prints nothing (`git merge-base --is-ancestor`, `git diff --quiet`, `test -f`): judge by `$?`, never re-read the log for missing output (#257).

## Real-board daemon hygiene

- No `AGENTS.*.md` in the real `.kanban/` while a daemon started before this feature runs: `listAll` has no filter and would promote the file to a phantom task and spawn a real agent.
- Do not trust a hygiene claim from task notes: check the live daemon. `ps -o ppid= -p $(cat .kanban/.orchestrator.lock)` must show a `node --watch` supervisor, `ps -o args= -p <ppid>` must contain `--watch`; identify the daemon ONLY by lock pid, PPID and supervisor argv. A bare daemon (PPID 1) runs pre-#192 code and will not restart on the next src/ merge, so the fix looks inert. `/api/hub.commit` is a live `git rev-parse` of the checkout: it shows on-disk HEAD, not which code the daemon loaded.
- Daemon staleness and restart (#187, fixed by #192's `node --watch`): an old daemon keeps its code until restarted, a pre-#192 daemon logs every finish as "agent pid=<pid> dead without state update" and livelocks the pipeline. Re-establish hygiene only from a FRESH pi session: pi loads extensions at session start, picks up merged code only after `/reload`, so a long-lived session's `orchestrator_start` spawns an unwatched daemon. `orchestrator_start` is a no-op while a daemon runs: `orchestrator_stop` then `orchestrator_start` from the fresh session, confirm the pid changed and "orchestrator started" is in `.kanban/.logs/orchestrator.log`. Check `ps -o lstart -p <pid>` against the merge commit time before trusting any real-board observation. In-flight agents survive the restart, but an old daemon spawned them without the exit-file wrapper, so the new daemon bounces each once before the respawn runs the merged code.
