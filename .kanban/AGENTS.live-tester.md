# live-tester: append project-specific guidance for this role below (e.g. how to run the project, how to live-test) so future agents of your kind start faster.

- Live-test the daemon on an isolated root, never on the real board:
  1. `git clone --bare /home/phamba/repos/se-llm-team /tmp/<t>/origin.git` (scratch origin, so pushes stay off the real mirror), then `git clone /tmp/<t>/origin.git /tmp/<t>/repo`.
  2. Put the probe task in `/tmp/<t>/repo/.kanban/` and `{"agent": "/tmp/<t>/fake-pi", "autoScheduleMinutes": 0.05, "pollMinutes": 1}` in `/tmp/<t>/repo/.kanban/se-llm-team.json`.
  3. Start the merged daemon code: `SE_LLM_TEAM_NO_WEBUI=1 node --input-type=module -e "const m = await import('/home/phamba/repos/se-llm-team/src/orchestrator.ts'); m.main(['--root','/tmp/<t>/repo','--rescan-seconds','1','--poll-minutes','1']);" &`
- `fake-pi` is a script that appends `"$@"` and its cwd to a log, records the `--append-system-prompt` path and its content, then sleeps, so the daemon sees a live agent and the real spawn argv is observable.
- Never start a daemon without `--no-webui` or `SE_LLM_TEAM_NO_WEBUI=1`: it reads the global config and binds the production webui port (4242).
- The daemon loads its code at start: a merged orchestrator change is inert until the daemon restarts. Restarting does not kill running agents.
- Do not drop `AGENTS.*.md` into the real `.kanban/` while a daemon started before this feature runs: its `listAll` has no filter and would promote the file to a phantom task and spawn a real agent.
- Clean up: kill the scratch daemon and every fake-pi process when the test ends.
- Role notes reach `meta/kanban` on the next `kanban: create`/`kanban: done` commit, only then; an idle board keeps them local.
- Webui/hub hot-reload tests need a mutable served graph: run the daemon from a scratch clone of the merged commit (`git clone --bare /home/phamba/repos/se-llm-team /tmp/<t>/origin.git`, clone it, `node <clone>/src/orchestrator.ts --root /tmp/<t>/root`), because `DEFAULT_WEBUI_PATH` resolves beside the loaded `hub.ts`. The real checkout must stay untouched.
- Fixture root needs `.kanban/se-llm-team.json` with `"webUi": {"enabled": true, "host": "127.0.0.1", "port": 4488}` (any free non-4242 port) plus isolated `HOME`; `git init` in the fixture needs `git -c commit.gpgsign=false commit` (global gpg signing fails with a bogus user email).
- The reload signal is the newest mtime across the webui import graph (`src/webui.ts`, `src/kanban.ts`, `src/pid.ts`). A change to any graph file must be re-read on the next `GET /` with no daemon restart; `GET /` embeds the order as `const LAYOUT = ...`.
- Real browser is available: `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"` (browsers in `~/.cache/ms-playwright`). Column x positions: `.c-<state> h2` boundingBox. A second working copy is `/home/phamba/.npm/_npx/e41f203b7505f1fb/node_modules/playwright` (1.63.0) if the paseo one moves.
- Webui log-payload/rendering tests need no hot reload: start only the hub on an isolated root and a scratch HOME (the hub registry is `$HOME/.pi/agent/se-llm-team-hub.json`, so this keeps the real registry and the production port 4242 untouched):
  `HOME=/tmp/<t>/home node --input-type=module -e "const {startHub}=await import('/home/phamba/repos/se-llm-team/src/hub.ts'); await startHub({root:'/tmp/<t>/repo',name:'t',host:'127.0.0.1',port:4321}); setInterval(()=>{},3600000)"`
  The default `webuiPath` is the real `src/webui.ts`, and its loader writes and sweeps `src/.webui-hot-<pid>-<v>` temp dirs in the real checkout (git-clean afterwards, but a scratch clone stays the safer route).
- Synthetic agent log fixture, exact real record shapes (one JSON record per line): `{"type":"message_update","assistantMessageEvent":{"type":"thinking_start"}}`, `...{"type":"thinking_delta","delta":"..."}`, `...{"type":"thinking_end","content":"..."}`. A task slug `NNNNNN_slug` needs `.kanban/NNNNNN_slug.md` plus `.kanban/.logs/NNNNNN_slug.developer.0.log`. LOG_LINES=100: 130 plain records before an open block of >100 deltas puts the init head at the 31st record (measured 2790 bytes), which proves the open block counts as ONE collapsed line. To keep the 1 s poll running (needed for the thinking_end finalization), write a live `sleep` pid into `.kanban/.pids/<slug>.pid` and set the task state to `doing`.
- A Thinking block renders as a collapsed `<details>`, so the pane can stay short and the poll tick itself sends the scrollTop-0 back-fill; use long preceding text paragraphs if the test must fire the real wheel-up `onscroll` request.
- Scratch origin hygiene: a bare clone of the repo carries refs/heads/meta/kanban, so a fixture daemon bootstraps the REAL board into the fixture and spawns agents for real tasks. After `git clone --bare`, run `git -C /tmp/<t>/origin.git update-ref -d refs/heads/meta/kanban` before cloning the fixture repo, so the fixture board starts empty.
- Docs/skill-change live test (task #161): the real interface is the pi skill command. Verify the merged text reaches an agent with `pi -p -nt --no-session "/skill:se-llm-team <prompt>"` (no tools, no board risk). To exercise the PM role, spawn a subagent that reads `skills/se-llm-team/SKILL.md` and does a read-only step 1-2 board dry run. The watcher side is `.pi/agents/watcher.md` only: there is no `.kanban/AGENTS.watcher.md`, and the daemon's `spawnAgent` appends role notes only to roles it spawns itself, never to the in-session watcher the PM spawns with the Agent tool. A real watcher (subagent_type "watcher") wakes only on a `kanban: create`/`kanban: done` commit; a backlog task with `openQuestions` on the real board is the fixture that tests whether its report carries blocked questions.
- `kanban_update` rejects a `notes` field (additionalProperties: false in index.ts), so a `# Notes` decision block comes from a direct file edit, not the documented kanban_update path.
- Hub/worktree live test (task #165): the hub lock and registry are per-$HOME (`~/.pi/agent/se-llm-team-hub.lock` and `.json`), so an isolated HOME isolates both. A non-worktree-rooted daemon becomes the hub on the configured port. A daemon rooted at `<root>/.worktrees/<name>` stands down (log "task worktree checkout stands down") and only registers. To stop a startup reap of that worktree daemon, put an owner task in the main board with frontmatter `worktree: "<name>"` plus a live sleep pid in `.kanban/.pids/<slug>.pid`. `SE_LLM_TEAM_HUB_HEALTH_MS=500` shortens the 5 s health poll and the `HEALTH_FAILS=2` failover (a worktree daemon never re-elects). `GET /api/hub` returns `{pid, root, commit}` and the dashboard `#hub` footer shows it, or "hub: old hub code (restart needed)" on a 404.
