# live-tester: append project-specific guidance for this role below (e.g. how to run the project, how to live-test) so future agents of your kind start faster.

## Check before you build any fixture or run any pi session

Past runs rediscovered these after they were already documented below. The #222 run lost 30+ blocks to them.

- The first in-modal poll waits out the 5 s board cadence. Skip about 5.6 s before you measure any tick or duration delta (#169).
- Synthetic logs need the real record shapes from #191 and #218: a session record, a turn_end usage record, then text_start/text_delta pairs. A lone message_end renders nothing in the pane.
- A manual tool probe loads tools with `pi -ne -e builtin:tool-search -e <worktree>/index.ts`. A plain `-ne` drops the built-in tool_search and every extension (#201).
- Run pi probes with the real HOME. An isolated HOME has no API key (the run dies with `No API key found`) and no extension symlink (#174).
- Script every timing-sensitive test (kill mid-flight, poll windows, sleep races) before you run it. A hand-timed kill/restart missed the 6 s doctor sleep in #222. The scripted version passed first try.

## Run discipline (from the #222 postmortem)

- Keep a fixture ledger at /tmp/<t>/LEDGER.md. Record one line per artifact you create: files, pids, markers, deletions, task numbers. Counts and provenance come from the ledger, never from a re-scan of .logs. Name hand-written fixtures with FIXTURE in the file name, or they pollute evidence counts and spawn-chase hunts.
- Keep a running evidence tally in the ledger (per task: spawns, doctor logs, reports, failures). Update it as each check lands. Never recount totals from scratch.
- Draft the report in a scratch file as each phase passes, one bullet per verified fact. Context compaction can erase your context mid-run. The #222 run spent about a third of its blocks re-collecting evidence it already had because nothing was on disk. Polish the draft and paste it into the task Notes at the end.
- Suffix appended-line markers with a timestamp so a rerun cannot pass on a stale marker.

- Live-test the daemon on an isolated root, never on the real board:
  1. `git clone --bare /home/phamba/repos/se-llm-team /tmp/<t>/origin.git` (scratch origin, so pushes stay off the real mirror), then `git clone /tmp/<t>/origin.git /tmp/<t>/repo`.
  2. Put the probe task in `/tmp/<t>/repo/.kanban/` and `{"agent": "/tmp/<t>/fake-pi", "autoScheduleMinutes": 0.05, "pollMinutes": 1}` in `/tmp/<t>/repo/.kanban/se-llm-team.json`.
  3. Start the merged daemon code: `SE_LLM_TEAM_NO_WEBUI=1 node --input-type=module -e "const m = await import('/home/phamba/repos/se-llm-team/src/orchestrator.ts'); m.main(['--root','/tmp/<t>/repo','--rescan-seconds','1','--poll-minutes','1']);" &`
- `fake-pi` is a script that appends `"$@"` and its cwd to a log, records the `--append-system-prompt` path and its content, then sleeps, so the daemon sees a live agent and the real spawn argv is observable. The daemon `spawn`s the configured agent path directly, so the script needs a `#!/usr/bin/env node` shebang and `chmod +x`; a bare `.mjs` fails with `spawn ... EACCES`, the daemon logs "failed to start", and the task sits in `doing` with no pid.
- Agent-prompt docs test (task #170, ~1 min): the daemon reads `agents/<role>.md` beside its loaded `src/`, so the merged code in the real checkout serves the merged prompts without a scratch clone.
