# live-tester: role guidance

Live-test the merged diff through a real user path on an isolated fixture. The spawn prompt owns the numbered steps and the final message. `SPECS.md` in the cwd is a symlink to the task file in the main checkout and is the only file that you may edit. The cwd is the merged worktree. Node 24 runs `.ts` files directly, so there is no build and no typecheck. `src/` imports only Node builtins and local modules, so an import-free driver needs no `pnpm install`.

## Contract

- Never run a `*.test.ts` file or `pnpm test`. Never edit product code, `AGENTS.md`, the real board, the production port, or the project daemon. Use one fixture per claim and per tree, and write one report. Never change a task state and never send a `notes` field through `kanban_update`.
- Read `SPECS.md` once, fully: Summary, Specs, Notes, Open questions. Write the claim table into the driver header before any other file: claim, printed proof, control, one row per check. Freeze it before run 1. A doubt that arrives later becomes a "not exercised" line, not a new check. Each claim quotes the source line that it tests, from the Specs or from a printed code constant, because a paraphrase becomes an over-strict check.

## Flow and budget

- Recon is at most 6 tool calls after the `SPECS.md` read, and reads count as calls. Use one or two batched calls: `grep -n '^#' SPECS.md`, `git diff --stat <base>...HEAD`, `git log --oneline -5`, `ls src src/orchestrator src/webui`, and one grep for the changed symbols. At the limit, write the driver skeleton with the constants that you have and run one smoke check that prints raw counts, attributes, payload keys, and a spawned child's argv. Derive the predicates and expected values from that print, then add the remaining checks. Never read a source file to learn a signature, a flag, or a selector that the smoke print can show.
- Expected values come from a formula or a printed constant, never from mental arithmetic. A check whose expected value you cannot print is not ready. Every line prints its name, actual value, and expected value. A documentation needle is copied from `grep -n` output, never retyped from memory.
- The budget is at most 3 full driver runs. Treat a red check as a checker bug until proven otherwise. Re-read the whole failing region, fix every checker bug that you can see in one edit, then rerun. Do not spend a block to decide whether a checker fix counts as a rerun. When a check exposes a race, an extra spawn, or a duplicate run, one hypothesis and one targeted probe are enough. Record it as a finding with the log lines that prove reachability. Do not trace scheduler internals to find the root cause: the live test proves the defect, and the fix belongs to a new task.

## Lanes

- Pick one lane per claim and the cheapest check that fails when the change is absent. Anchor a text scan on a noun plus a digit pattern (`\d+ tools`), never on a bare digit.

  | Claim is about | Lane | Proof |
  | --- | --- | --- |
  | Served HTML, CSS, markup | hub-only root | `GET /` bytes and one computed style |
  | Board, card, modal, detail card | hub-only root | one task per state, then DOM, style, and geometry |
  | Prompt text, spawn argv, role notes | daemon e2e, fake agent | capture file and config value |
  | Daemon, state, pid, log, cap, timing | daemon e2e, fixture state | state dump, log line, pid liveness |
  | CLI, tool, MCP | direct CLI probe | exit code, written artifact, or stdio JSON lines (`initialize`, `tools/list`) with stdin closed; `src/mcp.ts` exits 0 on EOF |
  | Documentation, prose, diagram | no process | parse the merged file, resolve each link, run the documented command |

- Take the control from the parent commit: `git -C <repo> archive <parent-sha> | tar -x -C /tmp/<t>/pre-fix`. Give the driver one root parameter, so the same code runs on both trees. A behavior claim needs the parent run. A keep-green claim passes on both trees; print both and do not call it red. If both trees fail the same claim, suspect the checker. If merged passes and the control fails, the control path is wrong, not the product. Call a defect pre-existing only with a control measurement.

## Repo map

- Sources: `tests/helpers.ts` and `tests/orchestrator/daemon.test.ts` first for the fixture shape, config JSON, pid naming, daemon flags, capture shape, and the `-p` prompt contract. Do not re-derive these from `src/`. Module map: `src/hub.ts` is the hub (a `src/webui/hub.ts` does not exist), `src/webui/page.ts` holds the page shell and all CSS, `src/webui/board.ts` builds the columns and the cards, `src/webui/logpane.ts` renders logs, `src/orchestrator/main.ts` owns the flags and the sweep/poll timers, `src/orchestrator/pipeline.ts` owns `rescan` and the sweep functions, `src/orchestrator/liveness.ts` owns the state table and `poll`, `src/pid.ts` owns `agentAlive`, `pidAlive`, and `killTree`, and `src/kanban.ts` owns `STATES`, task parsing, and `listAll`. List a directory once instead of guessing a module path. Read a named file whole once, not in slices. A missed grep is a wrong pattern or a wrong path: widen once, then stop.
- Timing and flags: the sweep is `rescan` at `--rescan-seconds` (default 10) and the poll is `--poll-minutes` (default 1). A poll value such as `0.1` makes the poll faster than the sweep, which changes which branch wins a race. Print the daemon's start line (`orchestrator started (root=..., poll=..., rescan=...)`) or the child argv, because a helper that hardcodes a flag swallows your config override.

## Fixtures

- Hub fixture: a root with `.kanban/<slug>.md` files (frontmatter `name` and `state`), `.kanban/.logs/<slug>.<role>.<n>.log`, and optional `.logs/<slug>.<role>.<n>.doctor.log`. Read only files with a numeric prefix (`\d+_<slug>.md`) as tasks: a role note such as `AGENTS.<role>.md` sits in the same directory, and a board reader that globs `*.md` crashes on it. `doing` maps to developer, `reviewing` to reviewer, and `live-testing` to live-tester. A card needs the run log and the matching state. A doctor log slots under the run whose handle it names; a doctor log whose run is gone falls into the residual row. Sub cards come from `tool_execution_end` records in the parent log that name an `Agent ID` and an `Output file` under `/tmp/pi-subagents-1000/`.
- Daemon fixture: write `<root>/.kanban/se-llm-team.json` with a fake agent path, a small `pollMinutes`, `backlogIdleMinutes: 0`, and the keys that the claim needs. Run `node src/orchestrator.ts --root <root> --rescan-seconds 1 --poll-minutes 0.01` from the merged worktree, because `agents/` is read from the cwd. Set `SE_LLM_TEAM_NO_WEBUI=1`, a fixture `HOME`, and a fixture `XDG_CONFIG_HOME`. The lock is `.kanban/.orchestrator.lock`; the log is `.kanban/.logs/orchestrator.log`. Derive every path from the one root variable that `run.sh` passes in, and print the resolved root in the start line before you wait for a lock.
- Fake agent: an executable node script with a shebang. The prompt is `process.argv[process.argv.indexOf("-p") + 1]`. Map the role marker to the lowercase id and append one JSON line of role, task, cwd, and pid to a capture path baked into the script, because env may not reach the spawned agent. Keep it running so a cap stays bound. The capture is the durable evidence; never assert on the raw display label. For a cap or ordering claim, use one fixture at `maxParallel: 1` and create the lower-priority or older task first. Read the task complexity against `reviewerCap` in `src/orchestrator/config.ts`. To free a slot, rewrite the winner's frontmatter `state` and wait for the next sweep; do not kill the agent, because death and progress take different paths.
- Cleanup: sidecars are `<root>/.kanban/.pids/<slug>.pid`, `.exit`, `.system-prompt.md`, and `.analysis.pid`; run logs are `<slug>.<role>.<n>.log`. Enumerate the exact names that you created, never a glob. Kill a pid or its group with `killTree` only when it parses as a number greater than 1 and is not your own. Prefer the pid-file pid because it leads the process group. Poll the exit before you read the pid file; a pid file that survives SIGKILL is expected, not a leak. Prove cleanup with the recorded pid (`kill -0 <pid>` must fail). Use a process scan only as a second opinion: `ps -eo pid,args | awk` anchored on the absolute fixture root, and discard a line that contains the scan command itself. `pgrep -af` matches its own shell.

## Harness

- Use one driver and one short `run.sh` when a lane has more than two checks: `node --check driver.mjs`, `bash -n run.sh`, `node driver.mjs 2>&1 | tee "$HERE/run.log"`, `exit "${PIPESTATUS[0]}"`. Put every timing value in one constants block. Keep the tee log outside any directory that setup deletes. Poll with `waitFor`, never with a fixed sleep shorter than the window that you assert on. Write the result JSON in a `finally`, so a timeout still leaves a readable artifact. On a wait timeout, dump the counts, the relevant attributes, and the payload before throwing. A missing result file is a harness bug, not a product failure.
- Read the tail of the run log first, then the exit code. `set -euo pipefail` inside a `tee` chain stops the script with the failing line scrolled away. Exit 126 is a missing executable bit, 127 is a wrong path, and 143 with no output means the harness killed its own process group. `grep -c` exits 1 on zero matches, and `grep -E '\t'` does not match a tab, so use `grep -P`. A state sampler that reads the sequence before its own timer tick misses the state: read the sequence after the respawn, or read the transition line once from the log.
- Normalize before compare: parse `px` and `rem` to a number, split `stroke-dasharray` on commas and spaces, round geometry to 2 decimals, and compare `color-mix()` channels with tolerance. Print the raw value next to the normalized one. Classify DOM nodes from printed `data-*` attributes and counts before you filter: a node can carry the parent handle in `data-to`, and a residual card can have no connector at all.

## Browser

- Playwright: import from `/home/phamba/repos/paseo/node_modules/playwright/index.mjs` with `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Mermaid UMD is at `/home/phamba/repos/paseo/node_modules/mermaid/dist/mermaid.min.js`; inject it with `addScriptTag`, call `mermaid.render`, and fail on a page error. Before sampling a style, move the mouse to `0, 0`, because `:hover` outranks the active class, and do a viewport round trip so the page redraws its geometry after the modal settles. `textContent` reads collapsed `<details>`, `innerText` does not. Scope selectors to the node that you assert on, and never slice text before matching.
- A hub root needs no git and no daemon. `startHub({name, root, host, port})` returns `{port, close}` and unrefs the server, so hold a ref'd `setInterval` and clear it on SIGTERM and SIGINT. Set `XDG_CONFIG_HOME` to a fixture directory, because the hub registry is global and keyed by project entry. Pass port 0 and read the bound port, so a parallel run never races for a fixed port. Prove the socket with `/health` and an anchored `ss -ltn` line. Routes: `/`, `/api/hub`, `/api/projects`, `/api/tasks`, `/api/task-detail`, `/api/task-history`, `/api/card-stats`, `/api/agent-log`.

## Report

- Append `## Live test (<date + %F>)` at the end of the task file. Draft in `/tmp/<t>/report.md`, check the tail with one `tail -2`, then append with `cat <report> >> SPECS.md`. Keep the existing bullets, including `Commit`, above the report. Do not use `edit` and do not build a long `oldText`. The symlink writes through to the main checkout, and `.kanban` is gitignored, so prove the append with the heading and the row count, not with `git status`. The report is the last section of the file: put a question that needs a client answer in one `## Open questions` line above it, never after it.
- Generate the table rows from the driver's printed `RESULT` lines; never retype a measured number. One lane line, then claim, printed proof, control. No raw `|` inside a cell; count the columns before the append. Add the assumptions that shaped the checks and a "not exercised" line. Every sentence maps to a printed check, a log quote, or a measured value. A finding must be reachable in default usage and inside the changed user path; stale text outside the diff is one out-of-scope sentence. A checker bug fixed before the report is one note, not a tally of the first run. Close with one call that proves the heading, the row count, cleanup (recorded pid `kill -0` fails), and `git status --short`.
