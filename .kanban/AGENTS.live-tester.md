# live-tester: append project-specific guidance for this role below (e.g. how to run the project, how to live-test) so future agents of your kind start faster.

## Run order (one pass, no re-derivation)
1. Read the task file, then the merge diff (`git show <merge>`). Pick the recipe below by change type; the task Notes or an earlier run may already name one.
2. `ss -ltn` for a free non-4242 port, build the fixture per the recipe, launch with a self-writing pidfile (hub-only recipe below).
3. Write the Playwright/shell check to a script file before the first run. On FAIL, diagnose the script first: a test-script bug is not a finding.
4. Record each verified fact once in `/tmp/<t>/LEDGER.md` as it lands. Do not re-grep or re-read to re-confirm.
5. Append the report per the Notes placement recipe, then role notes, then kill recorded pids.

## Playwright discipline (each trap cost a failed run at least once)

- Close the modal before you click anything behind the overlay: the overlay intercepts pointer events and the click times out after 30 s (#226, #209). Close with `#m-close`, then wait for the hidden class with `waitForFunction(() => document.querySelector("#modal").classList.contains("hidden"))`: `waitForSelector("#modal.hidden")` waits for VISIBILITY and times out on a hidden element (#226).
- A `:hover` rule outranks `.agent-card-active`, and the pointer stays over the element it just clicked: move the pointer away (`page.mouse.move(0,0)`) before you sample computed styles, or the active state reads as hover (#226).
- The first in-modal poll waits out the 5 s board cadence: skip about 5.6 s before you measure any tick or duration delta (#169, #222). `refreshMs` is already 1000 in the modal.
- A screenshot right after the modal opens catches the 200 ms `modalIn` fade and looks semi-transparent: wait ~300 ms before judging a picture (#196).
- Collapsed `<details>` content is hidden from `innerText`: read `textContent` or expand first (#218). Chromium keeps layout geometry for a closed details' children (paint-skipped, rects nonzero), so a collapsed check asserts details closed + visible summary, not zero-size children (#175). `waitForSelector` on hidden-by-default content (`pre.lg-out`) needs `{state:"attached"}` (#175).
- A Thinking block renders as a collapsed `<details>`: use long preceding text paragraphs if the test must fire the real wheel-up `onscroll` request (#191).
- `waitForSelector` can resolve after a 200 ms entrance ended: record `animationstart`/`animationend` in a capture listener plus a per-node `__aid` and measure the start->end delta (#191).
- Memory pressure can crash the browser ("Target crashed"/"Page crashed"): retry with a fresh browser; do not kill processes you do not own (#198).
- An `#m-attrs` row cell holds a bare text node when the value is plain (`issuer` "user", `blockedBy` an off-board ref), so `row.lastElementChild` is the LABEL span, not the value. Read `row.lastChild`, and detect a link with `cell.matches?.(".num-link") ? cell : cell.querySelector?.(".num-link")` - a `cell.querySelector` miss on the link itself reads as a false failure (#231).
- Browser: `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"` (a second copy `/home/phamba/.npm/_npx/e41f203b7505f1fb/node_modules/playwright`, 1.63.0, if the paseo one moves). Browsers live in `~/.cache/ms-playwright`.

## Shell traps (each killed a run at least once)

- Never `pkill -f <pattern>` (machine-wide, or `-P 1`) from the test's own `bash -c` when the cmdline contains the pattern: it matches the shell itself and kills the test mid-run, exit 143 (#168, #210, #211, #212, #220). Kill recorded pids only, or pgrep from a script file and abort on any pid outside your fixture: other live-testers run daemons on this machine.
- Never feed `grep -o 'pid=[0-9]*'` output to `kill`: dead-pid bounce lines contain `pid=0` and `kill 0` signals your whole process group (#211).
- `pgrep -x node` finds NOTHING on this machine, even for live node processes: get hub/node pids from `ss -ltnp` and kill by pid (#204, #210).
- `$!` after `nohup ... &` (e.g. `HOME=x nohup node script.mjs & echo $!`) records the subshell, not node: pgrep the script path and kill that (#187, #204). Launch fixture daemons with `setsid nohup <launcher> &` so signals stay off the test shell (#211).
- An inline heredoc embeds the fixture path in the test shell's own cmdline: a cleanup loop that matches fixture paths must walk and skip the caller's ancestor chain (#211).
- `pgrep -f 'sleep 600'` from the test's own bash matches the test shell: record the pid instead (`nohup sleep 600 >/dev/null 2>&1 & echo $! > .pids/<slug>.pid`) (#178).
- Cleanup: kill only the pids you recorded (`kill $(cat $T/*.pid)`), then `pgrep -af /tmp/<t>`. Never a machine-wide `pkill -f orchestrator`: it kills the project's own daemon, and that outage is invisible until the next board poll; if it happens, run `orchestrator_start` before any state transition (#168). The real daemon runs from the symlinked extension path `~/.pi/agent/extensions/se-llm-team/src/orchestrator.ts`; killing the daemon and a `sh -c` wrapper can leave the agent shell reparented to PID 1: read `ps --ppid <wrapper>` before the kill and kill that child too (#208).
- Never put a single quote inside a single-quoted `node -e` argument in a heredoc: the shell cuts the script at the quote and the helper silently mangles its output, which reads as a bug in your own regex or logic (#228: the extractor kept its quotes through two debug rounds before the shell showed as the cause). Write every node helper to a standalone `.mjs` file from the start. When a helper's output looks wrong, suspect shell mangling first: `cat -A` the raw output and run the helper standalone before you re-read your logic.

## Fixture shapes (do not rediscover these)

- Synthetic pi logs need the real record shapes (one JSON record per line): `{"type":"session","timestamp":"<ISO>"}`, usage `{"type":"turn_end","message":{"timestamp":<ms>,"usage":{"input":N,"output":N,"cacheRead":N,"cacheWrite":N,"reasoning":N,"totalTokens":...}}}`, then `{"type":"message_update","assistantMessageEvent":{"type":"text_start"}}` plus `{...,"assistantMessageEvent":{"type":"text_delta","delta":"..."}}` pairs (each pair renders one `<p>`; top-level `text_start`/`text_delta` records render NOTHING and cost a run in #230). A lone `message_end` renders nothing in the pane; `tool_execution_end` without its `tool_execution_start` makes the payload's reverse line walk treat the whole file as one open block; bare text lines and orphan records do not work (#191, #218, #222). `reasoning` is a subset of `output` (never added again); card tokens = input+output, cache excluded (#177).
- Claude logs: system init, user string prompt, assistant thinking/text/tool_use, user tool_result, result record with duration_ms; synthetic tool records need a non-empty `toolCallId` on BOTH start and end, `result: {content:[{type:"text",text:"..."}]}` for `pre.lg-out`, `message.model` + `message.usage` for `#m-log-meta`/`.card-stats`, and the task body needs an h1 for `#m-body h1` (#204, #218).
- A task slug `NNNNNN_slug` needs `.kanban/NNNNNN_slug.md` plus `.kanban/.logs/NNNNNN_slug.<role>.<n>.log`. A live card needs `state: "doing"` in the frontmatter plus a live sleep pid in `.kanban/.pids/<slug>.pid`; a bare pid is enough (disc null falls back to `kill(pid,0)`), but a zombie still answers `kill(pid,0)`, so SIGKILL and reap your own child (#169, #193). Doctor analysis pid name is `<slug>.<analysed role>.<n>.analysis` (#226). Orchestrator lock holds `<pid> <starttime-ticks>` (#210).
- `git init` fixtures need `.kanban/.logs` (a daemon's `>>` redirect fails without it) and `git -c commit.gpgsign=false commit`: the global config has commit.gpgsign=true (#195).
- Timestamps: daemon log lines carry UTC ISO; fixture file mtimes are local (UTC+2). Do not compare the two directly (#212).
- Node 24 strips types: import merged src directly (`await import('<repo>/src/kanban.ts')`). Worktrees need no node_modules (node resolves up the tree); git archives do (symlink the repo's) (#179, #195, #216).

The merged ui is served by `startHub` straight from the checkout that carries the change (the task worktree while the fix is unmerged, the main repo once the merge lands): no scratch clone since #192 removed the `.webui-hot-*` writer (`src/webui.ts` is a re-export shim over `src/webui/`, the hub serves the loaded module in place and writes nothing beside `src/`).
`HOME=/tmp/<t>/home PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright node --input-type=module -e "const {startHub}=await import('/home/phamba/repos/se-llm-team/src/hub.ts'); await startHub({root:'/tmp/<t>/repo',name:'t',host:'127.0.0.1',port:4321}); setInterval(()=>{},3600000)"`
- Launch through a launcher FILE that writes its own pid: write `/tmp/<t>/hub.mjs` with the `startHub` import plus `writeFileSync("/tmp/<t>/hub.pid", String(process.pid))`, then `setsid nohup node /tmp/<t>/hub.mjs >/tmp/<t>/hub.log 2>&1 &`. `$!` records the subshell, not node (#187, #204), so the self-written pidfile is the cheap kill handle (#231).
- Isolated HOME is mandatory: the hub lock and registry are per-HOME (`~/.pi/agent/se-llm-team-hub.lock`/`.json`), so a shared HOME makes the second hub stand down. One hub per process, one isolated HOME per hub.
- `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright` next to the isolated HOME, or Chromium resolves under the scratch HOME and launch fails (#194).
- `ss -ltn` first and take any free non-4242 port: the documented port can be busy with a concurrent live-tester (#177).
- The hub registry prunes curl-registered projects after staleMs (~15 s default): pass `staleMs: 3600000` to startHub when `.tab` needs 2 registered projects at load (#204).
- A non-worktree-rooted daemon becomes the hub on the configured port; a daemon rooted at `<root>/.worktrees/<name>` stands down and only registers (#165).

### Daemon e2e recipe (pipeline, spawns, state transitions)
1. Scratch origin: `git clone --bare /home/phamba/repos/se-llm-team /tmp/<t>/origin.git`, then `git -C /tmp/<t>/origin.git update-ref -d refs/heads/meta/kanban` BEFORE cloning (a bare clone carries refs/heads/meta/kanban, so the fixture bootstraps the REAL board and spawns agents for real tasks, #168), then `git clone /tmp/<t>/origin.git /tmp/<t>/repo` and `git -C /tmp/<t>/repo config commit.gpgsign false`.
2. Isolated HOME (plus XDG_CONFIG_HOME when config paths are under test). Fixture root `.kanban/se-llm-team.json`: `{"agent":"/tmp/<t>/fake-pi","autoScheduleMinutes":0.05,"pollMinutes":1}` plus `"webUi":{"enabled":true,"host":"127.0.0.1","port":<free non-4242>}` for hub tests.
3. `fake-pi` appends `"$@"` and its cwd to a log (record the `--append-system-prompt` path and content) and sleeps, so the daemon sees a live agent and the real spawn argv is observable. The daemon `spawn`s the configured path directly: the script needs a `#!/usr/bin/env node` shebang and `chmod +x`; a bare `.mjs` fails with `spawn ... EACCES` and the task sits in `doing` with no pid; an extensionless script with ESM syntax silently exits 0 (wrap it: `#!/bin/sh` + `exec node <script>.mjs "$@"`) (#189).
4. Start the merged code with `SE_LLM_TEAM_NO_WEBUI=1` (or `--no-webui`): without it the daemon reads the global config and binds the production webui port 4242. Example: `SE_LLM_TEAM_NO_WEBUI=1 node --input-type=module -e "const m = await import('/home/phamba/repos/se-llm-team/src/orchestrator.ts'); m.main(['--root','/tmp/<t>/repo','--rescan-seconds','1','--poll-minutes','1']);" &`
5. The daemon loads its code at start: a merged orchestrator change is inert until a restart, and restarting keeps in-flight tasks and running agents alive.
6. Live-test the daemon on an isolated root, never on the real board. Never run the repo's node suites: package.json runs eight suites, all developer/reviewer-owned unit tests.
7. Cleanup per the shell traps above: recorded pids, then `pgrep -af /tmp/<t>`.

## Report and run discipline (from the #222 and #226 postmortems)

- Script every timing-sensitive test (kill mid-flight, poll windows, sleep races) before you run it: a hand-timed kill/restart missed the 6 s doctor sleep in #222; the scripted version passed first try.
- Keep a fixture ledger at /tmp/<t>/LEDGER.md: one line per artifact (files, pids, markers, deletions, task numbers). Name hand-written fixtures with FIXTURE in the file name. Counts and provenance come from the ledger, never from a re-scan of .logs.
- Keep a running evidence tally in the ledger (per task: spawns, doctor logs, reports, failures); update it as each check lands. Never recount totals from scratch.
- Draft the report in a scratch file as each phase passes, one bullet per verified fact; context compaction can erase context mid-run. Polish the draft and paste it into the task Notes at the end.
- Append to the task file under the existing `# Notes` as a `##` subsection: an `#` heading splits the section and forces a second edit pass (#226). Find the insert point FIRST with `grep -n '^#' <task file>` and insert at the END of `# Notes`, just before the next top-level heading (usually `# Open questions`): an end-of-file append lands under the LAST section, and the move-back costs a second edit pass plus a heading re-check (#231).
- Verify placement with the heading grep, not a grep for the new header text: a content grep for `## Live test` passes even when the section sits under `# Open questions` (#231). Suffix appended-line markers with a timestamp so a rerun cannot pass on a stale marker.
- Verify each fact once, record it in the draft, move on. Re-grepping served pages, re-litigating what counts as a finding, and re-reading your own report for wording cost real blocks (#226). Do not re-run a passed check at wrap-up: #228 re-verified the clean worktree twice after recording it.
- Fix the verification plan in one pass before you build anything: map each acceptance to one check, pick the interfaces, then write the fixture and run. #228 re-derived the same plan in nine thinking blocks, with abandoned approaches, before the first fixture line; revise the plan only when a check fails.
- An acceptance that names a unit test does not lift the suite ban: the suites stay developer/reviewer gates, so live-test the production surface the test pins instead (prompt files, exported functions, served text; #180, #184, #228).
- Test-script bugs are not product findings: diagnose, patch the script, rerun once. Report only product-side findings; do not draft a PM report for a self-inflicted selector mistake (#226).
- Role notes reach `meta/kanban` on the next `kanban: create`/`kanban: done` commit, only then; an idle board keeps them local.
- `kanban_update` rejects a `notes` field (additionalProperties: false in index.ts), so a `# Notes` decision block comes from a direct file edit, not the documented kanban_update path.

## Real-board daemon hygiene

- Do not drop `AGENTS.*.md` into the real `.kanban/` while a daemon started before this feature runs: its `listAll` has no filter and would promote the file to a phantom task and spawn a real agent.
- Do not trust a daemon hygiene claim from task notes: check the live daemon. `ps -o ppid= -p $(cat .kanban/.orchestrator.lock)` must show a `node --watch` supervisor, and `ps -o args= -p <ppid>` must contain `--watch`. A bare daemon (PPID 1) runs pre-#192 code and will not restart on the next src/ merge, so the fix looks inert.
- Re-establish the hygiene only from a FRESH pi session: pi loads extensions at session start and picks up merged code only after `/reload`, so a long-lived session's `orchestrator_start` spawns an unwatched daemon and silently regresses the hygiene. The documented recovery is `orchestrator_stop` then `orchestrator_start` from the fresh session.
- `/api/hub.commit` is a live `git rev-parse` of the code checkout (src/hub.ts), so it shows the on-disk HEAD and does not prove which code the daemon loaded. Identify the running daemon by its lock pid, its PPID and the supervisor argv.
- Real-board daemon staleness (#187 second run): after a merge that changes `src/orchestrator/`, the running daemon keeps the old code and the pipeline livelocks. The merged developer, merger and live-tester prompts no longer call `kanban_set_state`, and the old daemon has no exit-0 success move, so every successful finish is logged as "agent pid=<pid> dead without state update, <state> -> <bounce state>" and respawned. A task can never reach done and each cycle burns a full agent run. `orchestrator_start` alone is a no-op while a daemon runs: restart with `orchestrator_stop` then `orchestrator_start`, then confirm the daemon pid changed and "orchestrator started" is in `.kanban/.logs/orchestrator.log`. Check `ps -o lstart -p <pid>` against the merge commit time before trusting any real-board observation of the merged flow. In-flight agents survive the restart, but the old daemon spawned them without the exit-file wrapper, so the new daemon bounces each of them one last time on finish before the respawn runs the merged code. Killing the daemon: `$!` after `cd X && nohup node ... &` records the subshell, not node; `pgrep -f` the fixture root and kill the node pid (and never `pkill -f <fixture-agent-path>` from the test's own shell, it matches the shell itself).
