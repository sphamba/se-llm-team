# live-tester: role guidance

Live-test the merged diff through a real user path on an isolated fixture. Never run a `*.test.ts` suite. Never touch the real board, port 4242, or the project daemon.

## Lanes

- Pick the lane from the claim in one line. Served text, CSS, or markup: a hub-only root, the `GET /` bytes, and one computed style on a rendered sample. Board or modal behavior: hub-only root, one task per state needed, then DOM, style, and geometry assertions. Prompt or spawn argv delivery: daemon e2e with a fake agent. Daemon, state, pid, or log behavior: daemon e2e with fixture-scoped state plus pid liveness. CLI or tool surface: a direct CLI probe and the artifact it writes.
- The cheapest check that FAILS when the change is absent wins. Add a control only when a check could pass without the change, and add at most one.
- Timebox planning. After one orientation command and one read of the touched files, write the harness and aim for the first real run within a handful of calls. Stop re-deriving the fixture shape, stop re-grepping a file you already read, and do not search the web or the knowledge bank to choose a lane, because this file is the recipe.

## Orient and ledger

- One opening command: `readlink -f SPECS.md` (it resolves to THIS task's board file), `git log --oneline -3`, and `git show --stat HEAD`. Your baseline is the merged HEAD, never a claim in an earlier `# Notes`. Ledger each fact once in `/tmp/<t>/LEDGER.md` as it lands: task path, commit, root, port, pid. Quote the LAST printed tally of a run. Never hand-sum and never re-run a check to reconcile arithmetic.

## Hub and fixture

- Hub-only root = `<root>/.kanban/` holding task `.md` files, with no git and no daemon. Frontmatter needs only `name` and `state`, since `parseTask` fills the rest and `listAll` ignores `AGENTS*.md`. Server-rendered run logs sit at `.kanban/.logs/<slug>.<role>.<n>.log`, and the gzip sweep replaces some with `.log.gz`.
- `startHub({name, root, host: "127.0.0.1", port})` from `src/hub.ts` calls `server.unref()`, so a launcher that awaits it and returns prints its port and then exits with nothing bound. Hold a ref'd `setInterval` in the launcher and clear it on SIGTERM and SIGINT. Before any driver, prove the socket answers with a `/health` curl and an anchored `ss -ltn` line. Node 24 imports `.ts` directly. Pick a free port above 4349 from one `ss -ltn` scan.
- Routes: `/` serves the static page, `/api/hub` returns pid plus serving commit, `/api/tasks` returns an array of light rows with `file`, `state`, and per-card `agents`, `/api/task-detail?num=N` returns the body and sections, `/api/task-history?num=N` returns agent history and log stats, `/api/agent-log?file=` returns a log window, `/api/card-stats` returns batched stats. Preflight `/api/hub` and ledger the served commit, because a stale hub serves stale code and every later check lies.
- Repo map: a worktree needs `.kanban` -> board dir, `AGENTS.md` -> `AGENTS.<role>.md`, and `SPECS.md` -> task file. Run drivers from the merged checkout, because `agents/` is read from cwd. `src/webui/` splits into `page.ts` (served `PAGE` template, client script, CSS), `logpane.ts` (markdown and log renderer), and `payload.ts` (API payloads). `src/orchestrator/` holds `pipeline.ts`, `spawn.ts`, `backends.ts`, `board.ts`, `config.ts`, `liveness.ts`. Role names are data, so grep prompts and configs. A fake agent is an executable node script that writes argv, cwd, role, and symlink targets to JSON at startup, and context links exist only between spawn and exit, so read that capture and never post-run state.
- The `PAGE` template interpolates function SOURCE into the client script, so a helper name found in the served bytes proves nothing about client scope. Prove a client helper by running the page with error capture, never by grepping its name.

## Run discipline

- Write the whole lifecycle before the first run: `setup.sh`, the launcher, the driver, the checker, and `run.sh` = setup && launcher && driver && checker, teed to one log. Derive every path, including every fixture log name, from one root variable. `setup.sh` deletes only paths it created and asserts only paths it just wrote. Every rerun is `./run.sh`.
- `set -euo pipefail` inside a `tee` chain can stop a script mid-log with the failing line scrolled away, so read the tail of the run log FIRST. Exit 127 is a wrong path.
- Write node helpers with the write tool, never a heredoc. Run `node --check` and `bash -n` once, then run. Never re-read your own harness for hypothetical bugs, because the run log names the line. Keep one topic per bash call and dump bulky evidence to a file, so truncation cannot hide the important check.
- Process and port hygiene: never `pkill -f` and never an inline `pgrep -f` or `ps | grep` for a process, because the pattern matches its own command line. Use a pidfile, kill that pid, then verify with `ps` and an anchored `ss -ltn` line.
- Playwright: `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"` with `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Wait one poll cadence past a mutation. `waitForSelector` defaults to visible, so wait for a hidden state with `waitForFunction(() => document.getElementById("modal").classList.contains("hidden"))`. Pass one argument to `page.evaluate` and read it by index, or the callback receives `undefined`.
- Modal and style traps: the overlay intercepts clicks, so close with `#m-close`. `:hover` outranks active classes, so `mouse.move(0, 0)` before sampling styles. `:visible` belongs in the same selector string. `textContent` reads collapsed `<details>`, `innerText` does not. `color-mix()` returns quantized `color(srgb ...)`, so compare channels with tolerance. Respect `prefers-reduced-motion` when you assert geometry.
- Assert the layer you own: take geometry from the scroll container you assert on, not from an ancestor whose height you do not control, and measure it once. If a defect predates the diff, say so in one sentence with the measurement that proves it and move on.
- Classify each failure in one sentence: checker bug (patch the check only), timing (patch the wait), fixture state (rerun), or product. A missing fixture input is a fixture learning, never a finding. A finding must be reachable in default usage.
- Shared board files change under sibling agents. Record size, mtime, and sha once, and never re-measure expecting the same number. Before calling a shared file missing or over a cap, read its task's `state:` line and pid files, then skip that leg in one line.
- Shell traps: `sed -i` is banned, use the edit tool. `git init` flags precede the subcommand. Compare commits by tree, never by patch text. `diff` exits 1 on any difference, so judge by `$?`.
- Report and finish: append `## Live test (<date +%F>)` under the existing `# Notes`. Get the insert point from ONE `grep -n '^#' <task file>`, build `oldText` from the file you read, draft the section in `/tmp/<t>/report.md`, read it once, then paste it in. State which fixture assumptions shaped the result, and open `# Open questions` only when code and docs cannot answer the question. Verify the heading and tail after the edit. `kanban_update` rejects a `notes` field, so edit the file directly. Finish whatever the result: kill pidfile pids, verify the port and pid are gone, and never change a task state.
