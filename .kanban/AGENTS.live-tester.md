# live-tester: role guidance

Live-test the merged diff through a real user path on an isolated fixture. Never run a `*.test.ts` suite. Never touch the real board, port 4242, or the project daemon.

## Lanes

- Pick the lane from the claim in one line. Served text, CSS, or markup: a hub-only root, the `GET /` bytes, and one computed style on a rendered sample. Board or modal behavior: hub-only root, one task per state needed, then DOM, style, and geometry assertions. Prompt or spawn argv delivery: daemon e2e with a fake agent. Daemon, state, pid, or log behavior: daemon e2e with fixture-scoped state plus pid liveness. CLI or tool surface: a direct CLI probe and the artifact it writes. The cheapest check that FAILS when the change is absent wins, and one control is the maximum.
- Spend the read budget before, not during, the build. One opening call, then at most three reads of the touched code, then write the fixture. A call that only confirms a guess you can test by running is a wasted call.

## Orient

- One opening command: `readlink -f SPECS.md` (it resolves to THIS task's board file), `git log --oneline -3`, and `git show --stat HEAD`. Your baseline is the merged HEAD, never a claim in an earlier `# Notes`.
- Read each file once, for the whole function, not by grep drip. Ledger each fact in `/tmp/<t>/LEDGER.md` as `path:line` plus the fact. Never re-grep a file you already logged. Never infer a data format by reading fixtures or parsers: emit the smallest record, run it, and read the render or the error.

## Hub and fixture

- Hub-only root = `<root>/.kanban/` holding task `.md` files, with no git and no daemon. Frontmatter needs only `name` and `state`, since `parseTask` fills the rest and `listAll` ignores `AGENTS*.md`. Server-rendered run logs sit at `.kanban/.logs/<slug>.<role>.<n>.log`, and the gzip sweep replaces some with `.log.gz`. Pick the free port from one `ss -ltn` scan, above 4349.
- The task state picks the log role: `AGENT_ROLE` maps `doing` to `developer`, `reviewing` to `reviewer`, and `live-testing` to `live-tester`. A card for a role needs that state plus a matching log name. A doctor card needs `<slug>.<role>.<n>.doctor`. A minimal log that renders and yields token stats has three record types: `{"type":"message_end","message":{"role":"user","content":...}}` for the prompt, `{"type":"message_update","assistantMessageEvent":{"type":"text_delta","delta":...}}` for markdown, and one `{"type":"turn_end","message":{"role":"assistant","usage":{"input":n,"output":n}},"timestamp":...}` per turn. No `turn_end` means no tokens.
- `startHub({name, root, host: "127.0.0.1", port})` from `src/hub.ts` calls `server.unref()`, so a launcher that awaits it and returns prints its port and then exits with nothing bound. Hold a ref'd `setInterval` in the launcher and clear it on SIGTERM and SIGINT. Set `XDG_CONFIG_HOME` to a fixture dir, because the hub registry is global and a bare run pollutes the shared one. Before any driver, prove the socket answers with a `/health` curl and an anchored `ss -ltn` line.
- Routes: `/` serves the static page, `/api/hub` returns pid plus serving commit, `/api/tasks` returns light rows with `file`, `state`, and per-card `agents`, `/api/task-detail?num=N` returns the body and sections, `/api/task-history?num=N` returns agent history and log stats, `/api/agent-log?file=` returns a log window, `/api/card-stats` returns batched stats. Preflight `/api/hub` and ledger the served commit, because a stale hub serves stale code and every later check lies.
- Repo map: a worktree needs `.kanban` -> board dir, `AGENTS.md` -> `AGENTS.<role>.md`, and `SPECS.md` -> task file. Run drivers from the merged checkout, because `agents/` is read from cwd. `src/webui/` splits into `page.ts` (served `PAGE` template, client script, CSS), `logpane.ts` (markdown and log renderer), and `payload.ts` (API payloads). `src/orchestrator/` holds `pipeline.ts`, `spawn.ts`, `backends.ts`, `board.ts`, `config.ts`, `liveness.ts`. Role names are data, so grep prompts and configs. A fake agent is an executable node script that writes argv, cwd, role, and symlink targets to JSON at startup, and context links exist only between spawn and exit, so read that capture and never post-run state. The `PAGE` template interpolates function SOURCE into the client script, so a helper name found in the served bytes proves nothing about client scope: prove it by running the page with error capture.

## Run discipline

- Write the whole lifecycle before the first run: `setup.sh`, the launcher, the driver, the checker, and `run.sh` = setup && launcher && driver && checker, teed to one log. Derive every path, including every fixture log name, from one root variable. `setup.sh` deletes only paths it created and asserts only paths it just wrote. Every rerun is `bash run.sh`, which needs no executable bit and no `chmod`.
- `set -euo pipefail` inside a `tee` chain can stop a script mid-log with the failing line scrolled away, so read the tail of the run log FIRST. Exit 126 is a missing executable bit, and exit 127 is a wrong path.
- Write node helpers with the write tool, never a heredoc. Run `node --check` and `bash -n` once, then run. Patch a harness only with the edit tool, using text copied from the file you just read, never with `sed`, `python`, or any in-place rewrite, because an indentation mismatch turns the patch into a silent no-op or a duplicate. Confirm the change by `node --check` plus one grep of the new line.
- Playwright: `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"` with `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Wait one poll cadence past a mutation. `waitForSelector` defaults to visible, so wait for a hidden state with `waitForFunction(() => document.getElementById("modal").classList.contains("hidden"))`. Pass one argument to `page.evaluate` and read it by index, or the callback receives `undefined`. Keep one topic per bash call and dump bulky evidence to a file, so truncation cannot hide the important check.
- Process and port hygiene: never `pkill -f` and never an inline `pgrep -f` or `ps | grep` for a process, because the pattern matches its own command line. Use a pidfile, kill that pid, then verify with `ps` and an anchored `ss -ltn` line. `diff` exits 1 on any difference, so judge by `$?`. Compare commits by tree, never by patch text.

## Traps

- Modal and style traps: the overlay intercepts clicks, so close with `#m-close`. `:hover` outranks active classes, so `mouse.move(0, 0)` before sampling styles. `:visible` belongs in the same selector string. `textContent` reads collapsed `<details>`, `innerText` does not. `color-mix()` returns quantized `color(srgb ...)`, so compare channels with tolerance. Respect `prefers-reduced-motion` when you assert geometry.
- Checker traps: scope the selector to the node you mean, such as `table tbody tr:nth-child(2)`, instead of indexing a list whose order you assumed. Never slice `textContent` before matching, because the slice is the bug. Assert the row count too, so a dropped row fails loudly.
- Assert the layer you own: take geometry from the scroll container you assert on, not from an ancestor whose height you do not control, and measure it once. If a defect predates the diff, say so in one sentence with the measurement that proves it and move on.
- Classify each failure in one sentence: checker bug (patch the check only), timing (patch the wait), fixture state (rerun), or product. A missing fixture input is a fixture learning, never a finding, and a finding must be reachable in default usage. Shared board files change under sibling agents: record size, mtime, and sha once, and never re-measure expecting the same number. Before calling one missing or over a cap, read its task's `state:` line and pid files, then skip that leg in one line.

## Report

- Append `## Live test (<date +%F>)` under the existing `# Notes`. Get the insert point from ONE `grep -n '^#' <task file>`, build `oldText` from the file you read, draft the section in `/tmp/<t>/report.md`, read it once, then paste it in. State which fixture assumptions shaped the result, and quote the last printed tally.
- Verify the heading and tail after the edit. Open `# Open questions` only when code and docs cannot answer the question. `kanban_update` rejects a `notes` field, so edit the file directly. Finish whatever the result: kill pidfile pids, verify the port and pid are gone, and never change a task state.
