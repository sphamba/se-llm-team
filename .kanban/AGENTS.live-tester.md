# live-tester: role guidance

Live-test the merged diff: real usage paths on an isolated fixture, never the unit-test suites (developer/reviewer gates) and never the real board.

## Run order

- Plan once, then build the fixture. Verify the Notes' merge hashes with ONE `git show --stat <h1> <h2>`: one hash, no hash, or an equal two-hash diffstat means a rebased change, so HEAD at start IS the merge. For a removal/refactor the diff IS the surface spec: derive old-behavior asserts from the removed hunk. Pick the lane in one pass, write it into the LEDGER, and treat it as closed (re-opening settled scope is this role's most expensive failure mode): pure content claim = greps on the shipped file; prompt/role-note/spawn-path delivery = direct fixture (a `.mjs` driver calls `renderPrompt`/`spawnAgent` with a fake agent); analysis-pipeline change = one `analysis-run.ts` e2e (covers CLI and daemon); daemon-only code (`board.ts`, `pipeline.ts`, hub routes) = daemon e2e or hub fixture. Probe the real call site before writing asserts. Keep the todo list to 3 items, one flip each.
- Ledger each verified fact once in `/tmp/<t>/LEDGER.md` as it lands. Every check script prints its own tally: quote tallies verbatim, never hand-sum. On FAIL diagnose the check script first: a script bug is not a product finding, a right-DOM empty/offset read is a timing race, patch the read. Doubt about a written file is `node --check` in the next bash.

## Codebase map

- `src/orchestrator.ts` is a facade, the code sits in `src/orchestrator/`: `main.ts`, `pipeline.ts` (sweep, states), `spawn.ts` (`renderPrompt` ships `agents/<role>.md` verbatim as the pi `-p` payload, `spawnAgent` builds args via `piSpawnArgs` in `backends.ts`), `board.ts` (`ensureWorktree` and `syncBoard`: worktree, `.kanban` symlink, context symlinks), plus `config.ts` and `liveness.ts`. Role names are data, not symbols: grep prompts and configs, never "developer" in src. Node 24 strips TS types: a driver `.mjs` imports these `.ts` files directly.
- All `/api/*` routes register in `src/hub.ts`. `src/webui/page.ts` serves the whole client, `index.ts` registers every TOOLS entry (a new tool also needs a LABELS entry), `STATES` sit atop `src/kanban.ts`. Artifacts: run log `.kanban/.logs/<slug>.<role>.<n>.log` (`.gz` when finished), pid `.kanban/.pids/<slug>.pid`.

## Fixtures

- Direct spawn-path fixture (prompt/role-note/spawn changes): write a `setup.sh` first so a rerun is one command. The task worktree MUST mirror what `syncBoard` creates, or reads through the links fail with ENOENT: `.kanban` -> root board dir, `AGENTS.md` -> `.kanban/AGENTS.<role>.md`, `SPECS.md` -> task file. Fake agent = executable node script logging argv+cwd as JSON; the `-p` payload is shipped `agents/<role>.md` with `{{logStallMinutes}}` filled. Run the driver from the merged checkout (`renderPrompt` reads `agents/` from cwd).
- Hub-only (webui/CSS/modal): fixture root = `.kanban` files only, no git repo. Launch `startHub` from the merged checkout via a launcher that writes its own pidfile (`setsid nohup … &`). Isolated HOME mandatory plus `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Never port 4242: pick the first free port above 4349 from one `ss -ltn` scan; if taken, take the next. Preflight `/api/hub` (pid + commit) before any data curl.
- Daemon e2e: scratch origin = bare clone with BOTH `meta/kanban` refs deleted before every re-clone; root config `{"agent": "<fake-pi>", "pollMinutes": 0.05, "autoScheduleMinutes": 0.05}`. The fake agent (executable node script) captures argv, cwd, and symlink targets into one JSON AT STARTUP: the daemon creates worktree context symlinks at spawn and clears them on exit, so checks read captures, never post-run state. Run the lifecycle from one teed run.sh in one bash call, scope checks to fixture slugs, pair state with pid-alive checks (state is set before spawn). Leave fixture task files UNTRACKED so the to-merge rebase never refuses.
- pi session probes need the REAL HOME (isolated HOME = no API key/symlink), always prefix `SE_LLM_TEAM_NO_WEBUI=1`; default model and settings; settle flags with one `pi --help` grep. JSONL recipe: `pi -p --no-session --no-context-files --approve --no-mcp --mode json "<prompt>"` with cwd = a fixture git root, the extension loads from the main checkout which must be at the merged commit. `tool_execution_start` carries args, `tool_execution_end` carries `result.content[0].text` + `durationMs`, filter tool records by name prefix, never count or index.

## Playwright discipline

- `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"`. The modal overlay intercepts clicks: close with `#m-close`, wait for `#modal.hidden` with waitForFunction on classList (waitForSelector times out on hidden elements). `:hover` outranks active classes, so `page.mouse.move(0,0)` before sampling styles. Board cadence 5 s, modal 1 s: skip ~5.6 s before a tick or duration delta.
- `:visible` must sit in the SAME selector string, hidden-by-default content needs `waitForSelector(..., {state:"attached"})`, collapsed `<details>` content is invisible to `innerText` (use `textContent` or expand). Computed `color-mix()` backgrounds come back as `color(srgb r g b / a)` with quantized alpha: parse channels with tolerance, never string-equal. Hold route responses to sample spinners mid-flight, abort AFTER the sample (a flag left in hold hangs later fetches), try/catch each sample.

## Shell traps

- Never kill by pattern: `pkill -f` matches your own shell (exit 143), and machine-wide `pkill -f orchestrator` kills the project daemon. An inline `pgrep -f`/`grep` in the bash tool ALWAYS matches its own command line: run it from a script file with an anchored pattern. Cleanup: kill pidfile pids, abort on foreign pids, verify with `ps`/`ss`. A daemon's `sh -c` wrapper can reparent children, check `ps --ppid` first.
- Launch background helpers with `setsid nohup <launcher> &`, the launcher writes its own pidfile with a trailing newline. Kill pidfiles individually and redirect every background helper's stdout, or the `| tee` pipe hangs.
- Write node helpers as standalone `.mjs` files (no single quotes inside a single-quoted `node -e`). `rg -n` searches, `rg -r` replaces; an empty result means a wrong symbol name, grep the definition site. Never nest a grep inside a sed expression and never use `sed -i` with unescaped slashes, use the edit tool. `diff` exits 1 on any difference and an exit-code check prints nothing: chain the commands and judge by `$?`.
- Scope port checks to the fixture pid and anchor the port (`grep -E ':<port>( |$)'`), a bare `:42` substring-matches the project daemon's `:4242`. `git init` fixtures need `.kanban/.logs`; flags precede the subcommand: `git -c commit.gpgsign=false init` (`git init -c` exits 129). Once the daemon's ensureInfoExclude names a path, a blanket `git add -A` silently skips it, commit with explicit paths. Daemon log lines are UTC ISO, fixture mtimes are local: never compare them directly.

## Report and board hygiene

- Report placement: append `## Live test (<date +%F>)` under the existing `# Notes`, before the next top-level heading, plain bullets. Insert point from ONE `grep -n '^#' <task file>`, build `oldText` from the file read, never the transcript, the edit tool takes an array of `{oldText, newText}`, verify with the heading grep in a later turn. `kanban_update` rejects a `notes` field, so `# Notes` edits are direct file edits. Classify each failure in one sentence: missing fixture input is a fixture learning (one-line note, not a finding); a finding is only a failure reachable in real default usage.
- Shared board files are rewritten concurrently by sibling doctors: measure once, record mtime, never chase transient states; a role file over its byte cap is a one-line report finding, not an investigation. Metrics self-reported in analysis logs are stale, verify against the file. Never edit a file an active sibling owns, note it.
- Identify a daemon by lock pid + `ps`; `/api/hub` returns `{pid, root, commit}`. `orchestrator_stop` then `orchestrator_start` from a fresh session picks up merged code.
