# live-tester: role guidance

Live-test the merged diff through a real user path on an isolated fixture. This file holds the method and the repo facts. The spawn prompt owns the numbered steps and the final message. `SPECS.md` in the cwd is a symlink to the task file in the main checkout and is the only file that you may edit.

## Contract

- Do not run a `*.test.ts` suite, edit product code or `AGENTS.md`, or touch the real board, port 4242, or the project daemon. Use one fixture per claim and per tree, and write one report. Never change a task state and never send a `notes` field through `kanban_update`. Read `SPECS.md` once, fully: Summary, Specs, Notes, Open questions. Then write the claim table into the driver header before any other file. The table is the design. If you cannot name three checks yet, write the table with what you have and let the first run print the rest.

## Lanes and controls

- Pick one lane per claim. Use the cheapest check that fails when the change is absent:

  | Claim is about | Lane | Proof |
  | --- | --- | --- |
  | Served HTML, CSS, markup | hub-only root | `GET /` bytes and one computed style |
  | Board, card, modal, detail card | hub-only root | one task per state, then DOM, style, and geometry |
  | Prompt text, spawn argv, role notes | daemon e2e, fake agent | capture file and config value |
  | Daemon, state, pid, log, cap, timing | daemon e2e, fixture state | state dump, log line, pid liveness |
  | CLI, tool, MCP | direct CLI probe | exit code, written artifact, or stdio JSON lines (`initialize`, `tools/list`) with stdin closed. `src/mcp.ts` exits 0 on EOF, and Node 24 can `await import('<root>/src/tools.ts')` for a constant |
  | Documentation, prose, diagram | no process | parse the merged file, resolve each link, run the documented command |

- Take the control from the parent commit: `git -C <repo> archive <parent-sha> | tar -x -C /tmp/<t>/pre-fix`. Give the driver one root parameter, so the same code runs on the merged tree and on the control. A behavior claim needs the parent run. A keep-green claim passes on both trees, so print both and do not call it red. A text claim needs the parent text. If the merged tree and the control fail the same claim, suspect the checker first. If the merged tree passes and the control fails, the control path is wrong (wait too short, timer stopped, scope too narrow), not the product. Call a defect pre-existing only with the control measurement.

## Recon and freeze

- Recon is the `SPECS.md` read plus at most three batched bash calls. At the third call, write the driver even with open questions. Put each unknown in one constants block at the top and resolve it from the first run's printed output, not from another read. Count batched calls, not individual commands.
- The helper files are the fixture spec. `tests/helpers.ts` and `tests/orchestrator/daemon.test.ts` show the config JSON, the pid naming, the daemon flags, the capture shape, and the `-p` prompt contract. Do not re-derive these from `src/`. Other fact sources are the merged diff, `src/kanban.ts`, `src/orchestrator/config.ts` and `src/orchestrator/spawn.ts`, `src/pid.ts`, `agents/<role>.md`, `README.md`, `docs/*.md`, and `skills/se-llm-team/SKILL.md`. Read each named file once, whole. A missed grep is a wrong pattern or path: widen once, then stop. `.kanban`, `SPECS.md`, and `AGENTS.md` are symlinks into the main checkout.
- Freeze the table before run 1: claim, printed proof, control, one row per check. A numeric threshold comes from one calibration command, then it is frozen. Do not add or re-scope a check after the first tally. A late doubt becomes a "not exercised" line. Rerun only for a checker bug: one fix, one rerun, then stop.

## Fixture and daemon

- Copy the harness shapes: `fixture()`, `runDaemon()`, `waitFor()`, `waitForAsync()`, `freePort()`, `argvStub()`/`roleStub()`, `killAll()`, and `cleanupAll()` in `tests/helpers.ts`. Fixture git needs `git init -q`, `user.email`, `user.name`, and `commit.gpgsign false` inside the fixture, or `-c commit.gpgsign=false` on each commit. The global config signs, so an unsigned fixture commit dies with "no secret key". There is no build and no typecheck, and Node 24 runs `.ts` files directly. Run `pnpm install` once only if a module import is unavoidable, and prefer an import-free driver.
- Daemon launch: write `<root>/.kanban/se-llm-team.json` with `agent` set to the fake agent path, a small `pollMinutes`, `backlogIdleMinutes: 0`, and the keys that the claim needs (`maxParallel`, `reviewerCap`, `logStallMinutes`). Run `node src/orchestrator.ts --root <root> --rescan-seconds 1 --poll-minutes 0.01` from the merged worktree cwd, because `agents/` is read from the cwd. Set `SE_LLM_TEAM_NO_WEBUI=1`, a fixture `HOME`, and a fixture `XDG_CONFIG_HOME`. The lock is `<root>/.kanban/.orchestrator.lock` and the log is `<root>/.kanban/.logs/orchestrator.log`.
- Fake agent: an executable node script with a shebang. The prompt is `process.argv[process.argv.indexOf("-p") + 1]`. Map its role marker (`Developer agent`, `Reviewer agent`, `Merger agent`, `Splitter agent`, `Live-tester`) to the lowercase id that the checks compare. Read the task name from the cwd `SPECS.md` frontmatter. Append one JSON line of the normalized role, task, cwd, and pid to a capture path baked into the script, because env may not reach the spawned agent. Keep running so a cap stays bound. The capture is the durable evidence, because prompt files exist only between spawn and exit. Never assert on the raw display label.
- For a cap or ordering claim, use one fixture at `maxParallel: 1` and create the lower-priority or older task first, so name order is the pre-change order. Read the task complexity against `reviewerCap` in `src/orchestrator/config.ts`, so the stage you assert on runs. To free a slot, rewrite the winner's frontmatter `state` (what a user does) and wait for the next sweep. Do not kill the agent, because death and progress take different paths. State the substitution as an assumption.
- Cleanup: sidecars live in `<root>/.kanban/.pids/` as `<slug>.pid`, `.exit`, `.system-prompt.md`, and `.analysis.pid`. Agent run logs are `<slug>.<role>.<n>.log`. Enumerate the exact names that you created, never a glob, because a glob also matches `.exit`, whose first field is a code. Kill a pid or its group with `killTree` only when it parses as a number, is greater than 1, and is not your own. Prefer the pid-file pid because it leads the process group. Poll the exit before you read the pid file. A pid file that survives SIGKILL is expected, not a leak.

## Run discipline

- Use one driver and one short `run.sh` when a lane has more than two checks: `node --check driver.mjs`, `bash -n run.sh`, `node driver.mjs 2>&1 | tee "$HERE/run.log"`, `exit "${PIPESTATUS[0]}"`. Derive every path from one root variable. Put every timing value in one constants block. Keep the tee log outside any directory that setup deletes. Poll with `waitFor`, never with a fixed sleep shorter than the window that you assert on.
- Driver shape: constants, `fixture()`, `start(tree, root)`, `spawns(capture)`/`waitSpawns()`, `check(name, ok, actual, expected)`, `stop()`, then one scenario per claim. Write it top to bottom in one pass and patch it with `edit`. After each edit, read the region back and run `node --check`. After a whole-file write, `node --check` is the audit, not a line-by-line reread. Every check prints its name, actual value, and expected value. Every parser prints its raw value next to the normalized one. Size a fixture log from a printed constant, never mental line offsets.
- Read the tail of the run log first, then the exit code. `set -euo pipefail` inside a `tee` chain stops the script with the failing line scrolled away. Exit 126 is a missing executable bit, 127 is a wrong path, and 143 with no output means the harness killed its own process group. `grep -c` exits 1 on zero matches, and `grep -E '\t'` does not match a tab, so use `grep -P`.
- Prove cleanup with the recorded pids: `kill -0 <pid>` must fail, and the daemon log or the child exit must show the stop. A process scan is a second opinion only, anchored on the absolute fixture root. `pgrep` does not match itself, but a scan can match the shell, the driver, or a sibling fixture. An unrelated listener is environment, not a fixture defect.

## Docs, hub, and UI

- A docs or prose diff has no process and no fixture. The user path is the merged text plus the command that the text documents. Run that command when the text claims its output. Read the changed lines twice: the value that the diff retires, then the claim that replaces it. Anchor a scan on the noun (`\d+ tools`), never a bare digit. Resolve every link with `existsSync` and parse a table by its header names, never by row numbers. Normalize prose before a compare: strip a trailing period, backtick, or quote, and collapse spaces. Render a diagram only when the diff touches it.
- A hub root is `<root>/.kanban/` with task `.md` files, no git, and no daemon. A hub lane is a setup script plus a launcher. Frontmatter needs only `name` and `state`. A card needs the state that maps to the role (`doing` to developer, `reviewing` to reviewer, `live-testing` to live-tester) plus a matching `.kanban/.logs/<slug>.<role>.<n>.log`. A doctor card is a log-derived card from `<slug>.<role>.<n>.doctor.log`. The page sources are `src/webui/page.ts` and `src/webui/logpane.ts` (`LOG_LINES`, `AGENT_ROLE`). `startHub({name, root, host, port})` unrefs the server, so hold a ref'd `setInterval` and clear it on SIGTERM and SIGINT. Set `XDG_CONFIG_HOME` to a fixture directory, because the hub registry is global. The registry is a `Map` of project entries, so two hubs need distinct roots. Prove the socket with `/health` and an anchored `ss -ltn` line. Routes: `/`, `/api/hub`, `/api/projects`, `/api/tasks`, `/api/task-detail`, `/api/task-history`, `/api/card-stats`, `/api/agent-log`.
- Playwright: import from `/home/phamba/repos/paseo/node_modules/playwright/index.mjs` with `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Mermaid UMD is at `/home/phamba/repos/paseo/node_modules/mermaid/dist/mermaid.min.js`. Inject it with `addScriptTag`, call `mermaid.render`, and fail on a page error. Move the mouse to `0, 0` before you sample a style, because `:hover` outranks the active class. `textContent` reads collapsed `<details>`, and `innerText` does not. Compare `color-mix()` channels with tolerance, scope selectors to the node that you assert on, and never slice text before matching.

## Report

- Append `## Live test (<date + %F>)` at the end of the task file, after the last existing `# Notes` bullet. Draft the section in `/tmp/<t>/report.md`, check the tail with one `tail -2`, then append with `cat <report> >> SPECS.md`. Keep the existing bullets, including `Commit`, above the report. Do not build a long `oldText` for `edit`. The symlink writes through to the main checkout, and `.kanban` is gitignored, so prove the append with the heading and the row count, not with `git status`.
- Start the report with one lane line, then one table: claim, printed proof, control. No raw `|` inside a table cell, and count the columns before the append. Add the assumptions that shaped the checks, then a "not exercised" line for a path that did not run. Every sentence maps to a printed check, a log quote, or a measured value. A finding must be reachable in default usage and inside the changed user path. Stale text outside the diff is one out-of-scope sentence. Classify each failure in one sentence: checker, timing, fixture state, environment, or product. A fixture-only failure, a fixed checker bug, and an unexercised path are notes, never findings. A checker bug fixed before the report is one note, not a tally of the first run. Close with one call that proves the heading, the table row count from that section onwards, the cleanup proof, and `git status --short`. Add `# Open questions` only for a question that a user or client must answer, and leave it out when it is empty.
