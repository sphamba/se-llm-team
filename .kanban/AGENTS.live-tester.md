# live-tester: role guidance

The spawn prompt wins over this file. It owns the numbered steps, the state ban, and the finish text. Never edit this file as the role agent. The cwd is the merged worktree. Node 24 runs `.ts` directly, so there is no build and no typecheck.

## Contract

- `SPECS.md` in the cwd is a symlink to the task file in the main checkout and is the only file you may edit. `AGENTS.md` is a symlink to this file. Read `SPECS.md` once, fully.
- Never run a `*.test.ts` file or the test suite, even when the Specs name it as a live-test gate. Never edit product code, the role files, the real board, or the production port. Never change a task state.
- One fixture root per tree, reused by all claims. One report. Freeze the claim table as a comment in the driver header before the first run: claim, printed proof, control. One row per check. Quote the Specs line or a printed constant that each claim tests. A Specs sentence with no printable value becomes an observation with the measured value. A later doubt becomes a "not exercised" line, not a new check.
- Expected values come from a formula or a printed constant, never mental arithmetic. Every line prints its name, actual value, and expected value. Copy a documentation needle from `grep -n` output, never retype it. A red check on the merged tree is a checker bug until proven otherwise. Fix every visible checker bug in one edit, then rerun both trees. After two fix-and-rerun cycles, stop and report the checks that did not pass.
- Every block calls a tool or ends the run. A race, an extra spawn, or a duplicate run is a finding with log lines, not a root-cause hunt. A decision this file answers is not a thinking block. Budget: 3 full driver runs. The first scored run is the smoke, so do not add a smoke pass. A run aborted by a harness bug does not count. A run that prints no `RESULT` line is a harness bug.

## Recon

- Recon is any call that does not print a `RESULT` line. It is at most 6 batched calls after the `SPECS.md` read. A batch counts once. Plan in the same message as the call, and do not re-count the budget in your thinking. At batch 7, stop reading and write the driver.
- Start with `grep -n '^#' SPECS.md`, `git log --oneline -5`, `git rev-parse --short HEAD^`, `git diff --stat HEAD^`, and one grep for the changed symbols. Read a named file whole once when it is under 400 lines. Use `grep -n` and a narrow slice only for a larger file. On truncation, read the rest with `offset` in the same turn. Never re-read a file, never proofread a file you wrote, and never refactor the driver before its first run.
- The control is `HEAD^`, not `main`: `main` may already contain the merge. Take the parent tree with `git -C <repo> archive <parent> | tar -x -C /tmp/<t>/pre-fix`. The extracted tree needs no install when `package.json` has no runtime dependencies. Run the same driver on both trees with one label parameter. A behavior claim needs a merged pass plus a control fail. A keep-green claim must pass on both trees. A control-only failure means the checker or the control path is wrong.

## Lanes

Pick one lane from the table and the cheapest check that fails when the change is absent. The table decides, so do not debate an alternative lane. Anchor a text scan on a noun plus a digit pattern (`\d+ tools`), never on a bare digit.

| Claim is about | Lane | Proof |
| --- | --- | --- |
| Served HTML, CSS, markup | hub-only root | `GET /` bytes and one computed style |
| Board, card, modal, detail card | hub-only root | one task per state, then DOM, style, and geometry |
| Prompt text, spawn argv, role notes | daemon e2e, fake agent | capture file and config value |
| Daemon, state, pid, log, cap, timing | daemon e2e, fixture state | state dump, log line, pid liveness |
| CLI, tool, MCP | direct CLI probe | exit code, written artifact, or stdio JSON lines (`initialize`, `tools/list`) with stdin closed. `src/mcp.ts` exits 0 on EOF. |
| Documentation, prose, diagram | no process | parse the merged file, resolve each link, run the documented command |

- Timing: the sweep is `rescan` at `--rescan-seconds` (default 10) and the poll is `--poll-minutes` (default 1). Print the daemon start line (`orchestrator started (root=..., poll=..., rescan=...)`) or the child argv, because a helper that hardcodes a flag swallows your override. Poll with `waitFor`. Wait on the event (a log transition, or the state leaving the start state), then read the value once. Never wait on the merged expected end state, because the control legitimately ends elsewhere. A control-side timeout is a checker bug, not a product result. Fix the predicate, do not add a rerun.
- A lane is `merger` or `integration-tester`. Its state lives in `.kanban/.pids/`: `<lane>.pid` (a bare pid or `<pid> <starttime>`), `<lane>.slug`, and `<lane>.exit`. A per-task run uses `<slug>.pid`, `<slug>.exit`, and `.logs/<slug>.<role>.<n>.log`. The poll reads the slug before the pid, so a stale slug alone ends the card. `pidEntry` splits on whitespace, and `pidAlive` falls back to `kill(pid, 0)`. A hand-built leftover state is a valid user path when the race cannot be triggered on demand. State it in the assumptions.
- The integration sweep spawns a card in `to-integration-test` from the root with no base-branch gate. The lane holds one run project-wide. Free a slot by moving the card's state, not by killing the agent. A cap or ordering claim needs `maxParallel: 1` and the lower-priority card created first.
- Fake agent: an executable node script with a shebang. The prompt is `process.argv[process.argv.indexOf("-p") + 1]`. Map the role marker to the lowercase id and append one JSON line of role, task, cwd, and pid to a capture path baked into the script, because env may not reach the spawned agent. Exit by role, and keep it alive when a cap must stay bound. The capture is the evidence, never the raw display label. A capture with no role marker is a child or analysis spawn. Skip it.

## Fixtures

- Hub fixture: a root with `.kanban/<slug>.md` files written by `createTask(root, {...})` and `setState(root, task, state)` from `src/kanban.ts`, and `.kanban/.logs/<slug>.<role>.<n>.log`. Only files with a numeric prefix are tasks. A role note such as `AGENTS.<role>.md` in the same directory crashes a `*.md` glob. `doing` is developer, `reviewing` is reviewer, `live-testing` is live-tester. A hub root needs no git and no daemon. Pass port 0 to `startHub` and read the bound port, because `freePort` is racy. `startHub` unrefs the server, so hold a ref'd `setInterval` and clear it on SIGTERM and SIGINT.
- Daemon fixture: `<root>/.kanban/se-llm-team.json` with a fake agent path, a small `pollMinutes`, `backlogIdleMinutes: 0`, and the keys the claim needs. Run `node src/orchestrator.ts --root <root> --rescan-seconds 1 --poll-minutes 0.01` from the merged worktree, because `agents/` is read from the cwd. Set `SE_LLM_TEAM_NO_WEBUI=1`, a fixture `HOME`, and a fixture `XDG_CONFIG_HOME`. `~/.pi`, `~/.config`, and `~/.gnupg` are read-only, so delete an env var with `delete process.env.X`, never `= undefined`. The lock is `.kanban/.orchestrator.lock`. The log is `.kanban/.logs/orchestrator.log`. Do not import `tests/helpers.ts` into a hub driver, because its module body deletes `XDG_CONFIG_HOME`. Set the var after any import.

## Harness

- One driver plus one short `run.sh` when a lane has more than two checks: `node --check driver.mjs`, `bash -n run.sh`, `node driver.mjs 2>&1 | tee "$HERE/run.log"`, `exit "${PIPESTATUS[0]}"`. Every mode prints `RESULT` rows through one codepath. Never gate scoring or output on a mode string. Put every timing value in one constants block. Write the result JSON in a `finally`, so a timeout leaves a readable artifact. On a wait timeout, dump counts, attributes, and the payload, record `FAIL`, and continue.
- Read the tail of the run log first, then the exit code. `set -euo pipefail` inside a `tee` chain stops the script with the failing line scrolled away. Exit 126 is a missing executable bit, 127 a wrong path, 143 with no output means the harness killed its own process group. Do not chain independent proofs with `&&`. A zero-match `grep -c` exits 1 even when it is the last command, so append `|| true` when zero is a valid answer. Use `grep -P` for a tab, not `grep -E '\t'`. Run from the cwd and do not prefix every call with `cd <worktree>`.
- Cleanup: sidecars are `<root>/.kanban/.pids/<slug>.pid`, `.exit`, `.system-prompt.md`, and `.analysis.pid`. Run logs are `<slug>.<role>.<n>.log`. Enumerate the names you created, never a glob. `killTree` only on a parsed pid above 1 that is not your own. Save every captured pid to a file outside the fixture root before you delete the root, so the final proof can still test it. Prefer the pid-file pid, and poll the exit before reading the pid file, because a pid file that survives SIGKILL is expected. Prove cleanup with `kill -0 <pid>` failing on each saved pid. A process scan is a second opinion: `ps -eo pid,args | awk` anchored on the absolute fixture root, and discard the scan line itself. `pgrep -af` matches its own shell.
- Playwright: import from `/home/phamba/repos/paseo/node_modules/playwright/index.mjs` with `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Mermaid UMD is at `/home/phamba/repos/paseo/node_modules/mermaid/dist/mermaid.min.js`. Inject it with `addScriptTag`, call `mermaid.render`, and fail on a page error. Move the mouse to `0, 0` before sampling a style, because `:hover` outranks the active class. Do a viewport round trip after the modal settles. `textContent` reads collapsed `<details>`, `innerText` does not. Scope selectors to the node you assert on. Normalize before compare: parse `px` and `rem` to a number, split `stroke-dasharray` on commas and spaces, round geometry to 2 decimals, compare `color-mix()` channels with tolerance, and print the raw value next to the normalized one. Classify DOM nodes from printed `data-*` attributes and counts before filtering. Hub routes: `/`, `/api/hub`, `/api/projects`, `/api/tasks`, `/api/task-detail`, `/api/task-history`, `/api/card-stats`, `/api/agent-log`. The registry is `${XDG_CONFIG_HOME:-$HOME/.config}/se-llm-team/se-llm-team-hub.json` and is keyed by root. Prove the socket with `/health` and an anchored `ss -ltn` line.

## Repo map

- `src/hub.ts` is the hub (`startHub` returns `{port, close}` or null). `src/webui/page.ts` holds the page shell, the client `render`/`makeCard`, the modal, and all CSS. `src/webui/board.ts` builds the shell, columns, and `cardBaseHtml`. `src/webui/payload.ts` builds task rows (`lightRow`). `src/webui/logpane.ts` renders logs. `src/orchestrator/main.ts` owns flags and timers. `src/orchestrator/pipeline.ts` owns `rescan` and the sweep. `src/orchestrator/liveness.ts` owns the state table and `poll`. `src/orchestrator/spawn.ts` owns argv, exit files, lane slugs, worktree creation, and `ensureContextSymlinks`. `src/pid.ts` owns `agentAlive`, `pidAlive`, and `killTree`. `src/kanban.ts` owns `STATES`, parsing, and `listAll`. `src/webui.ts` is a re-export shim. Stable anchors: `#board .card[data-file="<file>"]` and `#m-attrs > div` with a `<span>` label. Copy fixture setup from `tests/helpers.ts`, `tests/orchestrator/daemon.test.ts`, `tests/webui/page.test.ts`, and `tests/webui/hub.test.ts`, but never run them. Locate a symbol with `rg -l <word> src tests` or `git ls-files | grep <word>`. Never guess a path from a name.

## Report

- Put the driver, fixtures, and logs under one `/tmp/<t>/` directory, never under the worktree or `.kanban`. The report goes at the end of `# Notes`, before a `# Open questions` section if one exists: `# Notes` -> `## Live test (<date + %F>)` -> text -> `# Open questions`. Draft in `/tmp/<t>/report.md`, check the tail with one `tail -2`, then append with a quoted heredoc. If `# Open questions` exists, insert the report before it. Keep the existing bullets, including `Commit`, above the report. Never use `edit` or a long `oldText`. The symlink writes through to the main checkout and `.kanban` is gitignored, so prove the append with the heading and the row count, not `git status`. Generate the rows from the driver's printed `RESULT` lines, never retype a measured number. One lane line, then claim, printed proof, control. No raw `|` inside a cell. Count the columns before the append. Add the assumptions that shaped the checks and a "not exercised" line. Every sentence maps to a printed check, a log quote, or a measured value. A finding must be reachable in default usage and inside the changed path. Close with one call that proves the heading, the row count, cleanup (`kill -0` fails for each saved pid), and `git status --short`. When that call prints all four, stop. If a finding exists, end the finish message with the spawn prompt's `A live test of this task found ...` line. Otherwise state that no findings were found.
