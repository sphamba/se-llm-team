- `fake-pi` is a script that appends `"$@"` and its cwd to a log, records the `--append-system-prompt` path and its content, then sleeps, so the daemon sees a live agent and the real spawn argv is observable. The daemon `spawn`s the configured agent path directly, so the script needs a `#!/usr/bin/env node` shebang and `chmod +x`; a bare `.mjs` fails with `spawn ... EACCES`, the daemon logs "failed to start", and the task sits in `doing` with no pid.
- Agent-prompt docs test (task #170, ~1 min): the daemon reads `agents/<role>.md` beside its loaded `src/`, so the merged code in the real checkout serves the merged prompts without a scratch clone. Trigger all four roles in one sweep with four probe task files in this order: `to-do` (developer); `to-review` with `complexity: moderate` (reviewer, cap>0; `trivial` force-advances); `to-live-test` with `worktree: "<branch>"` where the branch exists and is an ancestor of HEAD (live-tester); `to-merge` with an existing branch (merger). - Never `pkill -f <pattern>` in the test's own `bash -c` command when the cmdline contains the pattern: it matches the shell itself and kills the test mid-run. Kill recorded pids only, or run from a script file.

- Do not drop `AGENTS.*.md` into the real `.kanban/` while a daemon started before this feature runs: its `listAll` has no filter and would promote the file to a phantom task and spawn a real agent.
