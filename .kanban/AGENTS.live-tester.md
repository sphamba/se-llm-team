# live-tester: role guidance

The spawn prompt wins over this file. The cwd is the task worktree at the merged branch tip. Node 24 runs `.ts` files directly. There is no build and no typecheck.

## Contract and budget

- `SPECS.md` in the cwd is a symlink to the task file in the main checkout and is the only file you may edit. Read it once, fully. Never edit product code, role files, the real board, or the production port. Never change a task state. Never run a `*.test.ts` file or a test suite, even when the Specs name one as a gate. Never read your own transcript or another role's log. Name a log `<slug>.<role>.<n>.log`, because a glob also matches the log that you are writing. Use one fixture root per tree, one driver, and one report.
- Plan in at most 5 lines and put the tool call in the same message. Take the first option and call the tool. Do not narrate the options that you reject. A doubt that survives one check becomes an assumption or a "not exercised" line. Do not analyze your own analysis.
- Budget: 8 recon calls after the `SPECS.md` read, then the driver file by call 9. This is a hard stop, not a target. Stop reading even when a fact is missing and write it as an assumption. The recon cap is the main defense against a late driver. Use 3 driver runs, and the first scored run is the smoke run. A run that aborts before the first scored check is a harness bug and uses no slot. Fix the harness and rerun at once. Never refactor the driver before its first run.

## Tree check

- Prove the change in one call: `git log --oneline -3`, `rg -n '<token>' <file>`, and `grep -n 'Commit' SPECS.md`. Absence is a finding, not a puzzle. Print the proofs and state the absence in the report. Never hunt for a lost commit with `--all`, `-S`, reflogs, or another role's log. Append `|| true` to a zero-match `grep -c`. Locate a symbol with `rg -l <word> src tests`, never with a guessed path. Read a file whole once, and on truncation read the rest with `offset` in the same turn.
- Name the control as the feature's parent. A branch can hold several commits, so read the log once and use the commit before the feature, not always `HEAD^`. Extract it with `git -C <repo> archive <sha> | tar -x -C /tmp/<t>/pre-fix` and run the same driver on both trees with one label argument. A scope claim needs `git show --stat <sha>` or `git diff --stat <base>..HEAD`. An archived control has no git metadata, so its scope cell is empty. If you cannot name the base, drop the scope check. Never report a scope check as FAIL or SKIP because you built it wrong.

## Lanes

- Pick one lane and the cheapest check that fails when the change is absent. Prefer a printed value, a state file, a DOM attribute, or a computed style. Do not add a second proof for a claim that already has a cheap proof.

| Claim is about | Lane | Proof |
| --- | --- | --- |
| Served HTML, CSS, markup | hub-only root | `GET /` bytes and one computed style |
| Board, card, modal, detail card | hub-only root | one task per state, then DOM, style, and geometry |
| Prompt text, spawn argv, role notes | daemon e2e, fake agent | capture file and config value |
| Daemon, state, pid, log, cap, timing | daemon e2e, fixture state | state dump, log line, pid liveness |
| CLI, tool, MCP | direct CLI probe | exit code, written artifact, or stdio JSON lines (`initialize`, `tools/list`) with stdin closed. `src/mcp.ts` exits 0 on EOF. |
| Test file or test helper | no test run | merged file content and a driver that replays the scenario through the production function |
| Documentation, prose, diagram | no process | parse the merged file, resolve each link, run the documented command |

- Timing: the sweep is `rescan` at `--rescan-seconds` (default 10) and the poll is `--poll-minutes` (default 1). Poll with a bounded loop that records `FAIL` and continues. `waitFor` that throws on timeout ends the whole run, so never use it as the only guard. Wait on the event, then read the value once. Never wait on the merged end state.
- A control check asserts that the change is absent, not an exact end state. The unguarded daemon can advance further. Accept any state in the allowed next set, or assert a monotonic field such as a pid, branch, or marker. A control-side timeout is a checker bug. Do not explain a control difference unless it changes a claim.
- Lane state lives in `.kanban/.pids/`: `<lane>.pid` (a bare pid or `<pid> <starttime>`), `<lane>.slug`, and `<lane>.exit`. A per-task run uses `<slug>.pid`, `<slug>.exit`, and `.logs/<slug>.<role>.<n>.log`. The reviewer arms `.logs/<slug>.reviewer-armed` with the reviewer pid. The global merger and integration lanes use `merger.pid`, `merger.slug`, `integration-tester.pid`, and `integration-tester.slug`. The poll reads the slug before the pid, so a stale slug alone ends the card. Free a slot by moving the card state, not by killing the agent.

## Fixtures and harness

- Daemon fixture: `<root>/.kanban/se-llm-team.json` with a fake agent path, a small `pollMinutes`, `backlogIdleMinutes: 0`, and the keys that the claim needs. Run `node src/orchestrator.ts --root <root> --rescan-seconds 1 --poll-minutes 0.01` from the worktree, because `agents/` is read from the cwd. Set `SE_LLM_TEAM_NO_WEBUI=1`, a fixture `HOME`, and a fixture `XDG_CONFIG_HOME`. Delete an env var with `delete process.env.X`, never with `= undefined`. The lock is `.kanban/.orchestrator.lock`. The log is `.kanban/.logs/orchestrator.log`. Never import `tests/helpers.ts` from a driver, because its module body deletes `XDG_CONFIG_HOME`. The daemon fixture root needs a real git repo when a task has a worktree or reaches merge. `git init -b main`, set local `user.name`, `user.email`, and `commit.gpgsign false`, because a host global config can break fixture commits. `ensureWorktree` is in `src/orchestrator/board.ts`. A hub-only root needs no git.
- Hub fixture: a root with `.kanban/<slug>.md` files written by `createTask(root, { name, summary })` and `setState(root, task, state)` from `src/kanban.ts`, plus `.kanban/.logs/<slug>.<role>.<n>.log`. `listAll(root)` reads them. Only files with a numeric prefix are tasks. A role note such as `AGENTS.<role>.md` in the same directory crashes a `*.md` glob. Pass port 0 to `startHub` and read the bound port, because `freePort` is racy. `startHub` unrefs the server, so hold a ref'd `setInterval` and clear it on SIGTERM and SIGINT.
- Fake agent: an executable node script with a shebang. The prompt is `process.argv[process.argv.indexOf("-p") + 1]`. Map the role marker to the lowercase id, then append one JSON line of role, task, cwd, and pid to a capture path baked into the script, because env may not reach the spawned agent. Exit by role. Keep the agent alive when a cap must stay bound. The capture is the evidence, not the raw display label. A capture with no role marker is a child or analysis spawn, so skip it. Kill every spawned agent at cleanup.
- Shape: one driver plus one short `run.sh` when a lane has more than two checks. `node --check driver.mjs`, `bash -n run.sh`, `node driver.mjs 2>&1 | tee "$HERE/run.log"`, and `exit "${PIPESTATUS[0]}"`. Every mode prints `RESULT` rows through one codepath. Put every timing value in one constants block. Write the result JSON in a `finally`, so a timeout leaves a readable artifact. On a wait timeout, dump the counts, the attributes, and the payload, record `FAIL`, and continue. Wipe the fixture root at the top of the driver with `rmSync(ROOT, { recursive: true, force: true })`.
- One source per value: compute each derived value once, store it in one variable, and use that variable in every check. After you edit the driver, run `node --check driver.mjs` and `rg -n '<edited identifier>' driver.mjs`, because `node --check` does not catch a stale name. A `ReferenceError` or a parse mismatch is a checker bug, not a product finding. Fix every visible checker bug in one edit, rerun both trees, and stop after two cycles.
- Children: save every spawned pid at spawn time. Attach `once("exit")` to every child and destroy `stdout` and `stderr` there. Send `SIGTERM`, await the exit event with a timeout, then `SIGKILL`, and await again. Never leave a keeper process such as a long `sleep` alive. Save the pids as JSON outside the fixture root, never as text lines. Prove cleanup with `kill -0` failing for each saved pid and print the count. Skip a process scan when the saved-pid proof is clean. A scan also matches its own command line.

```js
const child = spawn(cmd, args, { stdio: ["ignore", "pipe", "pipe"] });
savedPids.push(child.pid);
child.exited = new Promise((r) => child.once("exit", r));
child.exited.then(() => { child.stdout.destroy(); child.stderr.destroy(); });
```

- Shell traps: read the tail of the run log first, then the exit code. `set -euo pipefail` inside a `tee` chain stops the script with the failing line scrolled away. Exit 126 is a missing executable bit, 127 is a wrong path, and 143 means the shell killed its own process group. `pkill -f '<pattern>'` matches the shell that runs the command. Do not chain independent proofs with `&&`. The cwd is already the worktree, so do not prefix every call with `cd`. Derive every fixture path from one variable, never retype it. Enumerate the names that you created, never a glob.

## Repo map

- `src/orchestrator.ts` is the entry point. `src/orchestrator/main.ts` owns flags and timers. `src/orchestrator/pipeline.ts` owns `rescan` and the sweep. `src/orchestrator/liveness.ts` owns the state table and `poll`. `src/orchestrator/spawn.ts` owns argv, exit files, lane slugs, and `ensureContextSymlinks`. `src/orchestrator/board.ts` owns `ensureWorktree`, `commitKanban`, `showTip`, and `mirrorSubjects`. `src/kanban.ts` owns `STATES`, `createTask`, `setState`, `listAll`, `updateAttrs`, and parsing. `src/pid.ts` owns `agentAlive`, `pidAlive`, and `killTree`. `src/hub.ts` is the hub (`startHub` returns `{port, close}` or null). `src/webui/page.ts` holds the page shell, the client render, the modal, and all CSS. `src/webui/board.ts` builds the shell, columns, and cards. `src/webui/payload.ts` builds task rows. Copy fixture setup from `tests/helpers.ts`, `tests/orchestrator/daemon.test.ts`, `tests/webui/page.test.ts`, and `tests/webui/hub.test.ts`, but never run them and never import the helpers.

## Playwright and report

- Playwright: import from `/home/phamba/repos/paseo/node_modules/playwright/index.mjs` with `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Mermaid UMD is at `/home/phamba/repos/paseo/node_modules/mermaid/dist/mermaid.min.js`. Inject it with `addScriptTag`, call `mermaid.render`, and fail on a page error. Move the mouse to `0, 0` before sampling a style, because `:hover` outranks the active class. `textContent` reads collapsed `<details>`, and `innerText` does not. Scope selectors to the node that you assert on. Normalize before compare: parse `px` and `rem` to a number, split `stroke-dasharray` on commas and spaces, round geometry to 2 decimals, and print the raw value next to the normalized one. Hub routes: `/`, `/api/hub`, `/api/projects`, `/api/tasks`, `/api/task-detail`, `/api/task-history`, `/api/card-stats`, `/api/agent-log`.
- Report: put the driver, fixtures, and logs under one `/tmp/<t>/` directory, never under the worktree or `.kanban`. Draft the report in `/tmp/<t>/report.md`. The driver writes one JSON object per check with an explicit `id`, `claim`, `actual`, `expected`, `control`, and `pass`, in claim order. Generate the rows from that JSON with one node call. Never retype a measured number, and never parse the run log with a regex that can match `C1` inside `C13`. Escape every `|` inside a cell as `\|`, render an empty value as `(empty)`, and check the column count once. Build the report in at most 3 calls. Do not regenerate a table that already has the right rows.
- Append at the end of `# Notes`, before a `# Open questions` section if one exists: `# Notes`, then `## Live test (<date + %F>)`, then the text, then `# Open questions`. Keep the existing bullets above the report. Insert with `awk` before the `# Open questions` heading or with a quoted heredoc, never with `edit` or a long `oldText`. The symlink writes through to the main checkout and `.kanban` is gitignored, so prove the append with the heading and the row count, not `git status`. Add the assumptions that shaped the checks and a "not exercised" line. Every sentence maps to a printed check, a log quote, or a measured value. A finding must be reachable in default usage and inside the changed path. Close with one call that proves the heading, the row count (`grep -c '^| C[0-9]'`), cleanup (the saved pid count, and `kill -0` failing for each saved pid), and `git status --short`. When that call prints all four, stop. If a finding exists, end the finish message with the spawn prompt's line. Otherwise state that no findings were found.
