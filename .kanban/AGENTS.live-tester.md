0. Plan in ONE thinking block: pick the recipe, map each acceptance bullet to one check, fix script names and port, write the files. Overflow goes to /tmp/<t>/PLAN.md, never a second planning block (a truncated block loses its tail: #229, #259, #263; #256 re-planned the split-chore checks across six blocks the recipe already held, #254 re-derived a 17k-token variant across five). A recipe covering the acceptance's task family IS the plan: adapt its fixture/assert list, copy its enumerated check list, never re-derive the feature from source (#252 re-derived lazy-stats over ten blocks of board.ts/page.ts/hub.ts reads the map and recipes already covered; #266 re-derived counter/cap, symlink, board-sync and listAll facts over ~30 blocks of pipeline/board/kanban/spawn reads with the daemon e2e recipe in hand, first fixture file only at block 38; #255 rebuilt the split-chore five over five plan blocks). 1. Read the task file, then the merge diff. Take the merge commit from the Notes read; the Notes name no hash, or the named hashes are absent from the log (a rebased fix) -> HEAD at task start IS the merge, confirm with ONE `git show --stat HEAD`, never git-log archaeology (#263, #264, #254 repeated it anyway: two blocks on absent Notes hashes; #250: two identical commit messages, the Notes-named commit is the merge, no cross-check). For a removal or refactor the diff IS the surface spec: the removed hunk names the old trigger, control id, config key and payload, so derive old-behavior assertions from it and grep the SERVED old page before writing ids (#249). For a new /api endpoint or client feature the diff names the route, payload function, export and touched call sites: fixtures and assertions come from diff + Codebase map + Fixture shapes, at most ONE read of each changed region, never a client-flow re-trace file by file (a task with no recipe spent 7 windowed reads, 8 greps and 5 hub.ts blocks re-deriving the diff before writing a fixture, #264). Skip knowledge-bank searches: pages come back empty, the role file and the merge diff are the spec (#264). The TESTED task's own Notes and deviation records are the expected behavior: verify each documented claim with at most ONE read, build the fixture from Notes + diff, never a component-by-component re-derivation of an interaction the Notes settle (#267 spent five thinking blocks re-deriving a poll-race deviation the Notes already documented). Resolve the task-file name with `ls .kanban | grep <n>`. One task-file read covers the run; a wrap-up re-read for the exact insert point is the one allowed look (#243). For a test-split or verbatim-move task, jump to Test-suite split chores (Per-task recipes) before any diff; never re-derive line numbers across blocks (#258). Sibling task notes are not precedent: the role file and the merge diff are the spec (#257).

Never `rm -rf /tmp/<t>` AFTER writing this run's scripts into it: clean before writing, or rm only the repo subdir (#252 caught its own rm mid-plan). A probe that copies repo scenarios is cwd-sensitive (`git rev-parse`, `realpathSync(join(HERE, "..", ".."))`): run it at repo-relative depth as an untracked `__lt_<name>.probe.ts` inside the worktree's `tests/<area>/` (the runner's EXIT trap removes it), never from /tmp depth (HERE math and git commands break, 3 crashed probes and a redesign loop, #254). A cleanup trap must not remove files a later part still needs: when the trap cleans the probes, regenerate them before EVERY part (an EXIT trap deleted the probes before part 2: rc=1 in 0 s, no tally, #254). Rebuilding mid-run: kill the previous fixture's pids first, the regenerated files leave the old sleeper running. Launch with a self-writing pidfile. The daemon's startup sweep (compactFinishedLogs) runs BEFORE joinHub, so fixture logs are already .gz when /health first answers: a plain -> gz transition is only observable for logs written after startup (#250).
4. Check script to a file before the first run. Assertions from MEASURED values (a line-range read of the served file, or one computed-style/geometry/rAF sample), not analytic derivations (#236: 9 FAILs on derived values); a smoke assertion over an imported helper copies the moved suite's own expected values. An animation acceptance is settled by the rAF sampler at probe time, never pre-decided from source reading (three hedging blocks before one frame sample settled it, #264). Decide finding-vs-not once, ledger it, never revisit. Grep the script for sibling assertions with the same wrong assumption, fix in one pass (#230). Assert only what the merged diff changes: a counter an earlier path resets by design (push-failure/push-warned reset to 0 on every successful board push) is seeded and re-triggered in a no-push window, never asserted untouched across a push (#266: two of four FAILs were by-design resets). Route abort AFTER the sample point, else the held window is ~0 ms. A forgotten arrow body in a destructure passes `node --check` and crashes mid-tally: read the exact source line. Self-doubt -> `node --check` or ONE read of the exact source line, never a re-read, a third grep or a used-not-defined scan (#236; #262 five blocks on a one-line answer; #263 re-read a valid line on a false-alarm typo). Doubt about a file you just wrote: `node --check` it inside the NEXT bash, never a deliberation block first; an edit that reported success inserted exactly its text, a stray transcript glyph is not file content; after a green check move on, no null-guard block over an existing short-circuit (#265 burned three deliberation blocks on imagined typos and a guard its own `!!got` already covered). A helper outside `page.evaluate` sees no browser locals: hoist or pass as argument. Assert the SETTLED state from STATES, never log wording (#234). Every mapped check green -> step 7; no re-verification pass after green (#260; #256 re-grepped a green probe's log twice for coverage and regex doubts).
5. API preflight before the first browser run: `curl` /api/tasks + /api/agent-log (or the task's new endpoint), confirm markers, stats, handles; the preflight caught a fixture/endpoint mismatch before the browser run (#264). A modal agent-card/doctor fixture preflights `/api/task-history?num=N`, the endpoint the modal fetches agent history from; `/api/task-detail` carries only the light row and text, so empty `agents`/`doctors` there name the endpoint, not a broken fixture (#265 spent ten blocks cycling hypotheses over an empty array before curling the right one). /api/tasks is a bare JSON array (#235). 404 bodies differ: /api/task-detail JSON `{"error":"unknown task"}`, /api/agent-log EMPTY body, guard JSON.parse on `res.ok` (#247). Agent-log GET params (?file, &sub=list|<n>, back-fill &offset=<head>&before=1) from the served page source, never guessed (#240). For a timing/heavy-parse acceptance, time the API first: a thin margin at curl cost is one fixture rebuild, in the browser a debug loop (#248).
6. Ledger each verified fact once in /tmp/<t>/LEDGER.md as it lands (format: Report discipline); a ledger written only at wrap-up risks losing mid-run facts to compaction (#264).
7. Wrap up in one pass, then stop: report per the placement recipe, role-notes line (ONE bullet, routed per Report discipline), kill recorded pids (cleanup sequence: Shell traps). After 0 failed, ONE placement grep per edited file, all in one bash, is the only remaining verification: no re-reading edited text to re-verify (a typo you know you just wrote is one anchored edit, not a deliberation block), no re-printing sections, no re-running greps, no re-deciding cleanup or ledger lines (#263 spread wrap-up over five thinking blocks, #264 over four, #252 over four, #256 over four plus a three-block /tmp leftover audit). Assemble the report from ledger bullets in one draft (#239). A pre-kill ledger read for pids is the one allowed extra look; headers+tail+wc are not (#239). Edit-anchor recon is the ONE placement bash of Report discipline (`grep -n '^#' <task file>` + `tail -3` (+ `grep -n '^## ' <role file>` when routing)), then edit immediately: no staged tail reads, no `cat -A` rounds, no second re-read of headings, insert point or date (#252 spread two anchored edits over six blocks; #254 re-verified them across three).

## Fixture shapes (copy these, do not re-derive)

- Heavy-parse fixture: filler lines must pass the parse's own cheap prefilter. Plain filler is an indexOf scan only (90 MB = 542 ms cold, thin margin); JSON-noise lines (a `"timestamp"` field per line, 60 MB) parse cold in ~1.2 s (#248). Measure cold timing on the FIRST request after a hub start: board polls and opened modals warm `logStats`/`doneAgents`, so restart the hub and judge the first hit.
- Stats caches survive fixture edits: `doneAgents` holds a done task's agents per task file, `logStats` re-parses only on a byte-size change, so a same-size rewrite keeps stale tokens until a state flip or hub restart. Apply fixture edits before the first hub start, or restart after a rewrite (#247).
- Reopen measurement: ignore sampler ticks while `#modal.hidden` (the closed modal keeps the previous open's body and doctor cards, a stale read fakes text/history at ~20 ms). Arm the sampler only once the modal is visible, t0 at the open, not the click (#248).
- Synthetic pi logs need the real record shapes (one JSON record per line). Copy and extend:

  ```jsonl
  {"type":"session","timestamp":"2026-01-01T00:00:00.000Z"}
  {"type":"turn_end","timestamp":1767225610000,"message":{"timestamp":1767225610000,"usage":{"input":100,"output":200,"cacheRead":0,"cacheWrite":0,"reasoning":0,"totalTokens":300}}}
  {"type":"message_update","assistantMessageEvent":{"type":"text_start"}}
  {"type":"message_update","assistantMessageEvent":{"type":"text_delta","delta":"FIXTUREMARKER paragraph\n"}}
  ```

  Top-level `text_start`/`text_delta` render NOTHING (the pane reads only `message_update.assistantMessageEvent`). Each start/delta pair renders one `<p>`. A lone `message_end` renders nothing; `tool_execution_end` without its `tool_execution_start` makes the reverse line walk treat the file as one open block; bare text lines and orphan records do not work (#191, #218, #222). An open text block counts as ONE collapsed line for the back-fill head (#169). `reasoning` is a subset of `output` (never added again); card tokens = input+output, cache excluded (#177). ## Playwright discipline (each trap cost a failed run at least once)

- Close the modal before clicking anything behind the overlay (`#theme` sits under it): close with `#m-close`, wait `waitForFunction(() => document.querySelector("#modal").classList.contains("hidden"))`; `waitForSelector("#modal.hidden")` waits for VISIBILITY and times out on a hidden element (#226, #209).
- A `:hover` rule outranks `.agent-card-active`, and the pointer stays over what it just clicked: `page.mouse.move(0,0)` before sampling computed styles (#226).
- The first in-modal poll waits out the 5 s board cadence: skip ~5.6 s before measuring any tick or duration delta; `refreshMs` is 1000 in the modal (#169, #222). (Task sampling numbers below build on this one rule.)
- A screenshot right after the modal opens catches the 200 ms `modalIn` fade: wait ~300 ms (#196). After `page.hover`, wait ~100 ms before sampling pixels; board elements carry no background transition.
- A content assertion must not pass on a placeholder: non-empty `#m-log-text` matches `Loading...`, so assert real marker/filler content (e.g. `/[H]{10}/`), not length > 0 (#248).
- Collapsed `<details>` content is hidden from `innerText`: read `textContent` or expand (#218). Chromium keeps geometry for closed details' children (rects nonzero): assert details closed + visible summary, not zero-size children (#175). `waitForSelector` on hidden-by-default content needs `{state:"attached"}` (#175).
- A Thinking block renders as a collapsed `<details>`: long preceding paragraphs if the test must fire the real wheel-up `onscroll` request (#191).
- `waitForSelector` can resolve after a 200 ms entrance ended: record `animationstart`/`animationend` in a capture listener + per-node `__aid` (#191).
- `.toggle` renders `display:none` until its column hides cards (over 5): a `.toggle` hover check needs 6 cards in one column. `:visible` must sit in the SAME selector (`page.locator('.toggle:visible')`): a chained `locator(':visible')` searches visible DESCENDANTS, hovers a child, fakes a fail (#240). Pick the element with `page.locator('<sel>:visible').first()`.
- Wrap per-element hover/pixel sampling in try/catch, print each sample as it lands: one bad selector must fail soft, not kill the probe (#240 lost two runs). A wait helper must await its predicate in try/catch: a synchronous predicate returns a boolean and `fn().catch` throws `is not a function`, cascading timeouts through every later phase (7 fails + a full rerun, #264).
- A route-intercept mode flag resets to the pass-through mode at the END of each held/aborted phase: a handler left in `hold` hangs every later fetch, which reads as missing stats (2 false fails + a rerun, #264).
- Memory pressure can crash the browser ("Target crashed"): retry with a fresh browser, reset state the crashed run mutated; never kill processes you do not own (#198, #249).
- An `#m-attrs` row cell holds a bare text node when the value is plain, so `row.lastElementChild` is the LABEL span: read `row.lastChild`; detect a link with `cell.matches?.(".num-link") ? cell : cell.querySelector?.(".num-link")` (#231).
- The LIVE doctor card has `.spin` and NO `.check`; labels concatenate with spinner/check/stats text: strip `.agent-stats`/`.spin`/`.check` from a clone before reading a label, never assert check color on a live doctor (#227, #230).
- Served-CSS diffs: extract rule text and `diff`. Count occurrences, not lines (`grep -o | wc -l`); anchor selector counts (`rg '^\.sel[ {:]'`); never let a variable pattern match its own `var(--x)` usages or its `-strong` sibling (#230, #232). Extract served-page JS bodies with a line-range READ, not a grep regex (#236).
- Reduced-motion acceptance needs a `reducedMotion:"reduce"` context plus computed `animationName`, never a rule-text pin: a media rule that only ADDS a selector is dead when its base rule sits LATER with equal specificity (#237). Computed CSS lengths carry px: parse with parseFloat.
- Browser: `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"` (second copy `/home/phamba/.npm/_npx/e41f203b7505f1fb/node_modules/playwright`). Browsers live in `~/.cache/ms-playwright`; trust these paths, no per-run existence check (#247).

## Shell traps (each killed a run at least once)

- Never kill by pattern from the test's own shell: `pkill -f <pattern>` matches the shell itself when the cmdline contains the pattern, exit 143 (#168, #210-#212); `kill` of `grep -o 'pid=[0-9]*'` output hits the dead-pid `pid=0` bounce line (#211); `pgrep -x node` finds NOTHING here (#204, #210); `pgrep -f 'sleep 600'` from the test bash matches the test shell (#178). Kill recorded pids only; cleanup is this exact sequence from one bash, no plan block: `kill $(cat $T/*.pid)` -> `pgrep -af /tmp/<t>` from a script file (abort on any pid outside your fixture: other live-testers run daemons here) -> `ps -p <pid>` -> `ss -ltn | grep -F :<port>`. Never a machine-wide `pkill -f orchestrator`: it kills the project's own daemon (#168). Killing the daemon + its `sh -c` wrapper can reparent the agent shell to PID 1: read `ps --ppid <wrapper>` before the kill, kill that child too (#208). A lone pgrep hit whose cmdline is the cleanup bash itself is your own shell: ignore it, no `$$`-semantics derivation, no extra verification block (#246, #249, #264 hit it after the rule existed). A cleanup SCRIPT is not exempt: a pattern naming the fixture dir still matches the harness ancestor cmdlines (`pgrep -f '/tmp/<t>'` in cleanup.sh SIGTERMed run.sh itself, exit 143, #266). Cleanup kills pidfile pids plus a narrow script-name allowlist (`*fake-pi*|*daemon.mjs*|*analysis-run*` in one `case`), never a bare fixture-path pattern.
- Leftover `/tmp/<pattern>-*` dirs outside this run's exact artifact names are other runs' or other agents' files: one `ls -dt /tmp/<pattern>*` at cleanup, leave them with ONE ledger line, never mtime or timestamp archaeology to prove ownership (#256 burned three blocks proving `/tmp/webui-done-*` was not its own).
- `$!` after `nohup ... &` records the subshell, not node (#187, #204): launch with `setsid nohup <launcher> &`, launcher writes its own pidfile with a trailing `\n`. A bare `String(process.pid)` has no newline, so `kill $(cat a.pid b.pid)` concatenates two pids into one invalid number and kills nothing (#258): kill each pidfile individually.
- An inline heredoc embeds the fixture path in the test shell's cmdline: a cleanup loop matching fixture paths must skip the caller's ancestor chain (#211).
- No single quote inside a single-quoted `node -e` argument in a heredoc: the shell cuts the script at the quote, the helper silently mangles output, which reads as a bug in your logic (#228). Write every node helper to a standalone `.mjs` from the start. Wrong-looking output: suspect shell mangling first, `cat -A` it and run standalone before re-reading your logic. A node helper can also die on EPIPE when its stdout reader closes: run helpers with output to a file (#264).
- Frontmatter value: `sed -n 's/^state: *//p' | head -1 | tr -d '"'`; `grep -m1 '^state:' | tr -d ' "'` leaves the prefix and fakes FAILs (#229). `sed -i` with unescaped slashes dies: use the edit tool or another delimiter (#229). Every extracted-text compare strips the matched prefix on both sides: a `## Notes` section diff against a saved copy fakes a change when one side keeps the `# Notes` heading and the other does not (#266).
- Helpers must handle missing files: a `count_in` over an absent log prints 0 (#229). Remove fixture pidfiles between runs of one fixture dir (stale pidfile -> stale assertions). Daemon fixture: also delete `.kanban/.orchestrator.lock` and truncate `.kanban/.logs/orchestrator.log` (#233). The bash `read` builtin reads stdin variables, it is not a file reader: `read src/pid.ts` errors, use the read tool (#248).
- A daemon killed right after its first log line can miss its SIGTERM handler (`main()` logs and bootstraps BEFORE installing handlers, #233): wait ~1 s after the started line before SIGTERM.
- Chain independent checks with `;`, never `&&` after a `diff`: `diff` exits 1 on any difference and silently drops the rest of the chain (#260), and a trailing `grep '^FAIL'` with no match also exits 1: a green run can end with chain status 1, judge by the printed tally (#255).
- A check that answers by exit code prints nothing (`git merge-base --is-ancestor`, `git diff --quiet`, `test -f`): judge by `$?`, never re-read the log for missing output (#257). `$?` after `cmd | tee f` is tee's status, so a check script can record SHELL_EXIT=0 from the pipeline and mask the real result (#255): write generated check scripts with an explicit if/else per check that prints its count, never a terse `ck $?` (an inverted exit assertion faked a FAIL and cost a diagnose-edit-rerun cycle, #255). Tee every script run to its `/tmp/<t>/<name>.log` as you launch it, first run included: an un-teed green run costs a wrap-up re-run (#252 re-ran the passing api.mjs only to capture api.log), and many labeled probes in one bash garble their output when it truncates: one probe per question, or tee it (#258).
- A fixture's background sleeper (`sleep 120 &`) inherits the runner's stdout: the script prints its tally and exits, but the pipe stays open, so the `| tee` call hangs until the tool timeout. Redirect every background helper or kill it before run.sh returns (#267).
- Port cleanup checks: assert only a port the fixture binds, scoped to the fixture pid (`ss -ltnp | grep 'pid=<pid>'`), and anchor the port (`grep -E ':<port>( |$)')`: a bare `grep -F :42` substring-matches the project daemon's `:4242`, and a foreign listener is not a finding, never diagnose it (#267: two diagnosis blocks).
