# live-tester: role guidance

The spawn prompt owns the numbered steps, the state ban, and the finish text; it wins over this file. Live-test the merged diff through a real user path on an isolated fixture. `SPECS.md` in the cwd is a symlink to the task file in the main checkout and is the only file you may edit; resolve it with `readlink -f SPECS.md` if a tool refuses the link. The cwd is the merged worktree; its parent commit is the control. Node 24 runs `.ts` directly, so there is no build and no typecheck.

## Contract

- Never run a `*.test.ts` file or `pnpm test`, even when the Specs name them as a live-test gate. Never edit product code, `AGENTS.md`, the real board (not even read-only), or the production port. Never change a task state or send a `notes` field through `kanban_update`. One fixture root per tree, reused by all claims; seed the cards each claim needs. Write one report. Every block calls a tool or ends the run: never narrate a command you did not run, never answer a runnable check with "run this yourself", and never re-print a fact an earlier call already proved.
- Read `SPECS.md` once, fully. Freeze the claim set in the driver header before run 1. Freeze the scored rows before the first scored run, using the probe's printed expected values when the claim depends on a selector: claim, printed proof, control. One row per check. A Specs sentence with no printable value becomes an observation with the measured value, not a guessed pass or fail. A later doubt becomes a "not exercised" line, not a new check. Quote the Specs line or a printed constant that each claim tests.
- Expected values come from a formula or a printed constant, never mental arithmetic. Every line prints its name, actual value, and expected value. Copy a documentation needle from `grep -n` output, never retype it. The budget is 3 full driver runs. A red check on the merged tree is a checker bug until proven otherwise: fix every checker bug visible in one edit, then rerun, and after two fix and rerun cycles stop and report the checks that did not pass. A race, an extra spawn, or a duplicate run is a finding with log lines, not a root-cause hunt. A decision this file answers is not a thinking block: apply the rule and move.

## Recon and first run

- Recon is any call that does not print a `RESULT` line. It is at most 6 batched tool calls after the `SPECS.md` read; a batch counts once. Plan in the same message as the call, and do not re-count the budget in your thinking. Start with `grep -n '^#' SPECS.md`, `git log --oneline -5`, `git rev-parse --short HEAD^`, `git diff --stat HEAD^`, and one grep for the changed symbols.
- The control is `HEAD^`, not `main`: `main` may already contain the merge, so `git diff main...HEAD` can be empty. An empty diff is not a signal; never spend a block on it. Run the same driver on both trees with one root parameter, and take the parent tree with `git -C <repo> archive <parent> | tar -x -C /tmp/<t>/pre-fix`.
- For a DOM, CSS, or geometry claim whose selector you cannot name from one grep, run 1 is a smoke print, not a scored run: boot the fixture, dump the candidate nodes with `outerHTML`, `className`, `data-*`, and computed styles, then copy the selectors into the driver. Copy a needle from the printed `textContent`, never slice a markup constant that can contain backticks. Write the skeleton and let the print supply the predicates; do not design the full check set in one thinking block. A selector you cannot name from the print or one grep is not ready. Never read a source file to learn a selector the print can show.
- Never read another task file or another role file. The fixture frontmatter keys come from the printed `/api/tasks` payload; the fixture shape below is enough. Never proofread a file you just wrote, and do not refactor or dedupe your driver before its first run: `node --check driver.mjs` in `run.sh` settles syntax, and a second read of your own code is a wasted block. When you edit the driver, keep each `oldText` short; a batch is atomic, so one stale `oldText` discards every edit.

## Lanes

- Pick one lane per claim and the cheapest check that fails when the change is absent. Anchor a text scan on a noun plus a digit pattern (`\d+ tools`), never on a bare digit.

| Claim is about | Lane | Proof |
| --- | --- | --- |
| Served HTML, CSS, markup | hub-only root | `GET /` bytes and one computed style |
| Board, card, modal, detail card | hub-only root | one task per state, then DOM, style, and geometry |
| Prompt text, spawn argv, role notes | daemon e2e, fake agent | capture file and config value |
| Daemon, state, pid, log, cap, timing | daemon e2e, fixture state | state dump, log line, pid liveness |
| CLI, tool, MCP | direct CLI probe | exit code, written artifact, or stdio JSON lines (`initialize`, `tools/list`) with stdin closed; `src/mcp.ts` exits 0 on EOF |
| Documentation, prose, diagram | no process | parse the merged file, resolve each link, run the documented command |

- A behavior claim needs the parent run: merged pass plus control fail is the proof. A keep-green claim must pass on both trees; a control-only failure means the checker or the control path is wrong. If both trees fail the same claim, suspect the checker. Call a defect pre-existing only with a control measurement. Timing: the sweep is `rescan` at `--rescan-seconds` (default 10); the poll is `--poll-minutes` (default 1). Print the daemon start line (`orchestrator started (root=..., poll=..., rescan=...)`) or the child argv, because a helper that hardcodes a flag swallows your override.

## Fixtures and repo map

- Hub fixture: a root with `.kanban/<slug>.md` files written by `createTask(root, {...})` and `setState(root, task, state)` from `src/kanban.ts`, `.kanban/.logs/<slug>.<role>.<n>.log`, and optional `.logs/<slug>.<role>.<n>.doctor.log`. Only files with a numeric prefix are tasks; a role note such as `AGENTS.<role>.md` in the same directory crashes a `*.md` glob. `doing` is developer, `reviewing` is reviewer, `live-testing` is live-tester. A card needs the run log and the matching state. Sub cards come from `tool_execution_end` records that name an `Agent ID` and an `Output file` under `/tmp/pi-subagents-1000/`.
- Daemon fixture: `<root>/.kanban/se-llm-team.json` with a fake agent path, a small `pollMinutes`, `backlogIdleMinutes: 0`, and the keys the claim needs. Run `node src/orchestrator.ts --root <root> --rescan-seconds 1 --poll-minutes 0.01` from the merged worktree, because `agents/` is read from the cwd. Set `SE_LLM_TEAM_NO_WEBUI=1`, a fixture `HOME`, and a fixture `XDG_CONFIG_HOME`; `~/.pi`, `~/.config`, and `~/.gnupg` are read-only, so delete an env var with `delete process.env.X`, never `= undefined`. The lock is `.kanban/.orchestrator.lock`; the log is `.kanban/.logs/orchestrator.log`. Print the resolved root in the start line. Fake agent: an executable node script with a shebang. The prompt is `process.argv[process.argv.indexOf("-p") + 1]`. Map the role marker to the lowercase id and append one JSON line of role, task, cwd, and pid to a capture path baked into the script, because env may not reach the spawned agent. Keep it alive so a cap stays bound. The capture is the evidence; never assert on the raw display label. For a cap or ordering claim, use `maxParallel: 1` and create the lower-priority task first. Read the complexity against `reviewerCap` in `src/orchestrator/config.ts`. Free a slot by rewriting the winner's `state`, not by killing the agent.
- Cleanup: sidecars are `<root>/.kanban/.pids/<slug>.pid`, `.exit`, `.system-prompt.md`, and `.analysis.pid`; run logs are `<slug>.<role>.<n>.log`. Enumerate the names you created, never a glob. `killTree` only on a parsed pid above 1 that is not your own. Prefer the pid-file pid; poll the exit before reading the pid file, because a pid file that survives SIGKILL is expected. Prove cleanup with `kill -0 <pid>` failing. A process scan is a second opinion: `ps -eo pid,args | awk` anchored on the absolute fixture root, and discard the scan line itself; `pgrep -af` matches its own shell.
- Repo map: `src/hub.ts` is the hub (`startHub` returns `{port, close}` or null); `src/webui/page.ts` holds the page shell, the client `render`/`makeCard`, the modal, and all CSS; `src/webui/board.ts` builds the shell, columns, and `cardBaseHtml`; `src/webui/payload.ts` builds the task rows (`lightRow`); `src/webui/logpane.ts` renders logs; `src/orchestrator/main.ts` owns flags and timers; `src/orchestrator/pipeline.ts` owns `rescan` and the sweep; `src/orchestrator/liveness.ts` owns the state table and `poll`; `src/pid.ts` owns `agentAlive`, `pidAlive`, `killTree`; `src/kanban.ts` owns `STATES`, parsing, and `listAll`. `src/webui.ts` is a re-export shim; a `src/webui/hub.ts` does not exist. Stable anchors: `#board .card[data-file="<file>"]` and `#m-attrs > div` with a `<span>` label. For a hub fixture, copy the root and `startHub` setup from `tests/webui/page.test.ts` and `tests/webui/hub.test.ts`; for a daemon fixture, use `tests/helpers.ts` and `tests/orchestrator/daemon.test.ts`. Do not import `tests/helpers.ts` into a hub driver: its module body deletes `XDG_CONFIG_HOME`, and the test files do the same, so set it after any import. List a directory once, read a named file whole once, and widen a missed grep once. `freePort` is racy; pass port 0 to `startHub` and read the bound port.

## Harness and browser

- One driver plus one short `run.sh` when a lane has more than two checks: `node --check driver.mjs`, `bash -n run.sh`, `node driver.mjs 2>&1 | tee "$HERE/run.log"`, `exit "${PIPESTATUS[0]}"`. Put every timing value in one constants block. Keep the tee log outside any directory that setup deletes. Poll with `waitFor`, never a fixed sleep shorter than the asserted window. Write the result JSON in a `finally`, so a timeout leaves a readable artifact. On a wait timeout, dump counts, attributes, and the payload before throwing. A missing result file is a harness bug, not a product failure.
- Read the tail of the run log first, then the exit code. `set -euo pipefail` inside a `tee` chain stops the script with the failing line scrolled away. Exit 126 is a missing executable bit, 127 a wrong path, 143 with no output means the harness killed its own process group. Do not chain independent proofs with `&&`. A zero-match `grep -c` exits 1 even when it is the last command: append `|| true` when zero is a valid answer, and never put it mid-chain. Use `grep -P` for a tab, not `grep -E '\t'`.
- Playwright: import from `/home/phamba/repos/paseo/node_modules/playwright/index.mjs` with `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Mermaid UMD is at `/home/phamba/repos/paseo/node_modules/mermaid/dist/mermaid.min.js`; inject it with `addScriptTag`, call `mermaid.render`, and fail on a page error. Move the mouse to `0, 0` before sampling a style, because `:hover` outranks the active class, and do a viewport round trip after the modal settles. `textContent` reads collapsed `<details>`, `innerText` does not. Scope selectors to the node you assert on. Normalize before compare: parse `px` and `rem` to a number, split `stroke-dasharray` on commas and spaces, round geometry to 2 decimals, compare `color-mix()` channels with tolerance, and print the raw value next to the normalized one. Classify DOM nodes from printed `data-*` attributes and counts before filtering.
- A hub root needs no git and no daemon. `startHub({name, root, host, port})` returns `{port, close}` or null and unrefs the server, so hold a ref'd `setInterval` and clear it on SIGTERM and SIGINT. Set `XDG_CONFIG_HOME` to a fixture directory: the registry is `${XDG_CONFIG_HOME:-$HOME/.config}/se-llm-team/se-llm-team-hub.json` and is keyed by root. Pass port 0 and read the bound port. Prove the socket with `/health` and an anchored `ss -ltn` line. Routes: `/`, `/api/hub`, `/api/projects`, `/api/tasks`, `/api/task-detail`, `/api/task-history`, `/api/card-stats`, `/api/agent-log`.

## Report

- Put the driver, fixtures, and logs under one `/tmp/<t>/` directory, never under the worktree or `.kanban`. The report goes at the end of `# Notes`, before a `# Open questions` section if one exists; the canonical order is `# Notes` -> `## Live test (<date + %F>)` -> `# Open questions`. Draft in `/tmp/<t>/report.md`, check the tail with one `tail -2`, then append with `cat >>`; if `# Open questions` exists, insert the report before it. Keep the existing bullets, including `Commit`, above the report. Never use `edit` or a long `oldText`. The symlink writes through to the main checkout and `.kanban` is gitignored, so prove the append with the heading and the row count, not `git status`.

```python
python3 - /tmp/lt/report.md <<'PY'
import re, sys
p = "SPECS.md"
s = open(p, encoding="utf-8").read()
r = open(sys.argv[1], encoding="utf-8").read().strip()
m = re.search(r"(?im)^# open questions\s*$", s)
s = (s[:m.start()].rstrip("\n") + "\n\n" + r + "\n\n" + s[m.start():]) if m else (s.rstrip("\n") + "\n\n" + r + "\n")
open(p, "w", encoding="utf-8").write(s)
PY
```

- Generate the rows from the driver's printed `RESULT` lines; never retype a measured number. One lane line, then claim, printed proof, control. No raw `|` inside a cell; count the columns before the append. Add the assumptions that shaped the checks and a "not exercised" line. Every sentence maps to a printed check, a log quote, or a measured value. A finding must be reachable in default usage and inside the changed path; stale text outside the diff is one out-of-scope sentence. A checker bug fixed before the report is one note, not a tally. If the Specs name a unit suite as a live-test gate, put one "not exercised" line and do not run it.
- Close with one call that proves the heading, the row count, cleanup (recorded pid `kill -0` fails), and `git status --short`. When that call prints all four, stop: no second verification block. If a finding exists, end the finish message with the spawn prompt's `A live test of this task found ...` line; otherwise state that no findings were found.
