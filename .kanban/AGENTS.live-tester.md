## Run order (one pass, no re-derivation)
0. Plan the fixture in one pass: pick the recipe, map each acceptance bullet to one check, fix script names and port, then write the files. A plan that outgrows one thinking block goes to /tmp/<t>/PLAN.md, not a longer think: a thinking block truncates mid-plan and the tail is lost (#229 burned ~20 blocks re-deriving the orchestrator flow; #241 and #243 spread one plan over nine and four thinking blocks with "wait" reversals, #243 passed 12/12 first try; #246 spread one modal-animation plan over eight thinking blocks before the first fixture file; #247 flip-flopped one fmtTokens expectation ("1.2k" vs "2k") across three planning blocks). A mid-plan question (state value, format, sample point, fixture detail) is a probe output or a recipe fact, not a plan input: stop planning, run the probe, take the number (#239, #240). Instrumentation (rAF sampling, route delays, capture listeners, MutationObserver arrival probes) is recipe material: copy it, never re-derive it per phase (#246 re-enumerated its instrumentation in four planning blocks). If two reasoning passes disagree, stop reasoning and read the function.
1. Read the task file, then the merge diff (`git show <merge>`). Pick the recipe below by change type; the task Notes or an earlier run may already name one. Resolve the task-file name with `ls .kanban | grep <n>`: a name from memory cost a failed read (#230). One task-file read covers the run: do not re-inspect the task file, its log dir or the board listing later (#243 re-inspected all three).
2. Check the discipline sections (Playwright, shell, fixture shapes) BEFORE you plan timings, selectors, or assertions: every trap below cost a failed run at least once. Re-deriving a documented trap costs blocks (#230 board cadence, #240 `.toggle`, #246 the pgrep self-match one run after #243).
3. Take a free non-4242 port from ONE `ss -ltn` scan (any port above 4349 not in the listening set): the scan holds until a bind failure (#236, #239). Recipe example ports are examples, not reservations: take the first free port and never revisit; a second scan or candidate debate is a violation (#243 flip-flopped 4321/4399/4350; a leftover daemon on 4321 means the next free port from the SAME scan; #246 hedged over its port in the first planning block). Build the fixture per the recipe, launch with a self-writing pidfile.
4. Write the check script to a file before the first run. Write assertions from MEASURED values, not analytic derivations: probe the real surface first (a line-range read of the served file, or a one-off computed-style/geometry/rAF sample) and take expected numbers, endpoints and formats from the sample (#236: a 45-check first run with 9 FAILs on derived values; #238 re-derived an already-measured clamp; #246 authored its growth bar from the 0.2s transition and faked a FAIL). On FAIL, diagnose the script first: a test-script bug is not a product finding, patch and rerun once, never a PM report for a script bug (#226); decide finding-vs-not-finding once, record it in the ledger, never revisit (#236 re-litigated one artifact three times; #246 across three blocks). Grep the whole script for sibling assertions with the same wrong assumption and fix them in one pass (#230: A11 was fixed, the rerun failed C3 on the same assumption). After any full rewrite of a probe script, and before copying a helper into a sibling script, grep for every previously fixed bug name (#238). A helper outside `page.evaluate` sees no browser locals: hoist `const x = geo.x` in Node scope or pass the data in as an argument. For a timing FAIL, ask first whether the script read each window at or after its end time (#235); when a check holds or aborts a route, place the abort AFTER the sample point, else the held window is ~0 ms and the check fakes a fail (#246 S16). A forgotten arrow body in a destructure (`.map(([, h]))`) parses as an array literal, passes `node --check`, and crashes mid-tally: after a mid-run crash read the exact source line and suspect a dropped callback body (#246). On script self-doubt run `node --check`, not a re-read (#236). Assert the SETTLED state from STATES, never the log wording (#234).
5. Pre-flight the fixture through the API before the first browser run: `curl` `/api/tasks` and `/api/agent-log`, confirm text markers, stats and handles render. `/api/tasks` is a bare JSON array, not `{tasks}` (#235). 404 bodies differ: `/api/task-detail` returns JSON `{"error":"unknown task"}`, `/api/agent-log` returns an EMPTY body, so a fetch-based preflight must guard JSON.parse on `res.ok` (#247 crashed one on the empty 404 body). Agent-log GET shapes (page.ts): `?file=<handle>` serves the chunk body, `&sub=list` lists subagent transcripts, `sub=<n>` serves the n-th, back-fill adds `&offset=<head>&before=1`; take query params from the served page source, never guessed (#240). A bad fixture shape costs seconds at curl and a full browser run plus a debug loop later (#230).
6. Record each verified fact once in /tmp/<t>/LEDGER.md as it lands; ledger rules live in Report discipline below.
7. Wrap up in one pass, then stop: append the report per the placement recipe, add the role-notes line (ONE bullet under the matching section heading of this role file, decided once, no deliberation block), kill the recorded pids. After the script prints 0 failed, ONE placement grep per edited file is the only remaining verification: no re-printing a just-edited section, no re-running passed greps, no re-verifying edits, no re-deciding cleanup scope or a ledger run-2 line (#232 spent six wrap-up blocks that way; #236 re-verified its edits twice; #246 re-deliberated both). Assemble the report from the ledger bullets in one draft; a second full draft is re-verification (#239). A pre-kill ledger read for the pids is the one allowed extra look; headers+tail+wc re-checks of one edited file are not (#239 ran all three).

## Orchestrator flow map (look up here instead of re-deriving; line numbers drift after merges, grep the function name)

- Entry: `src/orchestrator.ts` is a facade over `src/orchestrator/`; `main()` lives in `src/orchestrator/main.ts`. Startup: `sweep()` then `poll()`, then sweep every `--rescan-seconds`, poll every `--poll-minutes`, plus a debounced fs.watch of `.kanban` (500 ms).
- STATES live at the top of `src/kanban.ts` (read state names here before writing any assertion): `to-live-test` and `live-testing` are separate states; a merge sets `to-live-test` and the sweep immediately spawns the live-tester, so the settled state is `live-testing`.
- Worktrees: `ensureWorktree` (src/orchestrator/board.ts) creates `.worktrees/<wt>` from the base; the name comes from `task.worktree` or `slugWorktree` (src/kanban.ts, shortName first).
- Context symlinks: every `spawnAgent` call site (src/orchestrator/spawn.ts) runs `ensureContextSymlinks` (repoints `SPECS.md` and `AGENTS.md` at `.kanban/...`; a tracked real AGENTS.md gets `update-index --skip-worktree` first) then `ensureInfoExclude` (appends AGENTS.md/SPECS.md to the COMMON `.git/info/exclude`, shared by checkout and linked worktrees; idempotent; best-effort). Excludes never affect tracked files.
- Merge lane (`sweepToMerge`, src/orchestrator/pipeline.ts): rebase in the worktree; a stopped rebase (check `--git-path rebase-merge`, NOT `REBASE_HEAD`, which lingers after a completed rebase, git 2.43) spawns a merger (cwd = worktree, pidName `merger`) and sets `merging`; a successful merger exit requeues through the poll; any other failure requeues with no merger. Then `merge --ff-only` at the root, `stripContextSymlinks` (rm only `120000` symlink-mode entries plus a housekeeping commit), `setState("to-live-test")`, log `fast-forwarded <base> to <wt>, set to-live-test`. No merger agent runs on the clean path.
- `doneCleanup` (pipeline.ts) on done: removes worktree and branch; `git branch -d` refuses an unmerged branch, so a manual done with unfinished work keeps both.
- Run analysis spawns from ONE guarded `spawnRunAnalysis` (src/orchestrator/spawn.ts), three fire sites: `sweepToMerge`, the poll's run-end pass and the poll's self-advanced pass (liveness.ts). Check order: no finished run log -> return; report or doctor log exists -> already analysed; analysis pid alive -> in flight; `<base>.analysis.exit` marker -> skip with a log line; else spawn detached `node src/analysis-run.ts <root> <log> <role>`.
- Marker lifecycle: a failed analysis (an early throw before the doctor-log write) leaves the wrapper's exit marker but no report and no doctor log. `janitorPids` sweeps `.pids` on the same rescan pass but keeps per-run analysis exit markers while their task exists (#229), so the spawn happens once. A fresh run keys its own marker; a manual `src/analysis-run.ts` run bypasses the spawn and writes no marker.
- Pid/exit names: run log `.kanban/.logs/<slug>.<role>.<n>.log` (`.gz` when finished), analysis wrapper `.pids/<slug>.<analysed role>.<n>.analysis` + `.analysis.exit`; task dead markers `<slug>.dead(.count)`; orchestrator lock `.kanban/.orchestrator.lock` holds `<pid> <starttime-ticks>` (#210).
- The startup poll clears a stale `<slug>.pid`+`<slug>.exit` pair, so to keep a stale pair in a fixture, start the daemon on an EMPTY board and create the task after (#229). A task file that appears after the startup pass is only touched by sweeps, and with a long `--poll-minutes` never by the poll.

Each start/delta pair renders one `<p>`. A lone `message_end` renders nothing; `tool_execution_end` without its `tool_execution_start` makes the payload's reverse line walk treat the whole file as one open block; bare text lines and orphan records do not work (#191, #218, #222). Apply all fixture edits before the first hub start, or restart the hub after a rewrite (#247).

## Playwright discipline (each trap cost a failed run at least once)

- Close the modal before you click anything behind the overlay (the `#theme` toggle sits under it too): close with `#m-close`, then wait with `waitForFunction(() => document.querySelector("#modal").classList.contains("hidden"))`: `waitForSelector("#modal.hidden")` waits for VISIBILITY and times out on a hidden element (#226, #209).
- A `:hover` rule outranks `.agent-card-active`, and the pointer stays over the element it just clicked: move the pointer away (`page.mouse.move(0,0)`) before you sample computed styles (#226).
- The first in-modal poll waits out the 5 s board cadence: skip about 5.6 s before you measure any tick or duration delta (#169, #222). `refreshMs` is already 1000 in the modal.
- A screenshot right after the modal opens catches the 200 ms `modalIn` fade: wait ~300 ms before judging a picture (#196). After `page.hover`, wait ~100 ms (one frame) before sampling pixels; board elements carry no background transition.
- Collapsed `<details>` content is hidden from `innerText`: read `textContent` or expand first (#218). Chromium keeps layout geometry for a closed details' children (paint-skipped, rects nonzero), so a collapsed check asserts details closed + visible summary, not zero-size children (#175). `waitForSelector` on hidden-by-default content (`pre.lg-out`) needs `{state:"attached"}` (#175).
- A Thinking block renders as a collapsed `<details>`: use long preceding text paragraphs if the test must fire the real wheel-up `onscroll` request (#191).
- `waitForSelector` can resolve after a 200 ms entrance ended: record `animationstart`/`animationend` in a capture listener plus a per-node `__aid` (#191).
- The column `.toggle` renders `display:none` until its column hides cards (over 5), so a `.toggle` hover check needs 6 cards in one column. `:visible` must sit in the SAME selector (`page.locator('.toggle:visible')`): a chained `locator('.toggle').locator(':visible')` searches visible DESCENDANTS, hovers a child and fakes a fail; even a unique locator such as `#theme` then times out (#240). Pick the element itself with `page.locator('<sel>:visible').first()`.
- Wrap per-element hover/pixel sampling in try/catch and print each sample as it lands: one bad selector must fail soft, not kill the probe (#240 lost two runs to one invisible selector).
- Memory pressure can crash the browser ("Target crashed"/"Page crashed"): retry with a fresh browser; do not kill processes you do not own (#198).
- An `#m-attrs` row cell holds a bare text node when the value is plain, so `row.lastElementChild` is the LABEL span, not the value: read `row.lastChild`, and detect a link with `cell.matches?.(".num-link") ? cell : cell.querySelector?.(".num-link")` (#231).
- The LIVE doctor card has `.spin` and NO `.check` (only past doctors have `.check`), and card labels concatenate with spinner/check/stats text: strip `.agent-stats`/`.spin`/`.check` from a clone before you read a label, and never assert a check color on a live doctor (#227, #230).
- Served-CSS diffs: prefer extracting rule text and `diff`ing. Count occurrences, not lines (`grep -o 'pattern' | wc -l`), anchor selector counts (`rg '^\.sel[ {:]'`), and never let a variable pattern match its own `var(--x)` usages or its `-strong` sibling (#230: two css-check debug rounds; #232). Extract served-page JS bodies with a line-range READ of the served file, not a grep regex (#236).
- Reduced-motion acceptance needs a `reducedMotion:"reduce"` context plus computed `animationName`, never a rule-text or selector-presence pin: a media rule that only ADDS a selector is dead when its base rule sits LATER with equal specificity (#237). Computed CSS lengths carry px (`strokeWidth` "1.5px"): parse with parseFloat.
- Browser: `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"` (second copy `/home/phamba/.npm/_npx/e41f203b7505f1fb/node_modules/playwright` if the paseo one moves). Browsers live in `~/.cache/ms-playwright`; trust these paths, a per-run existence check is re-derivation (#247).
- Headless Chromium cannot model a hidden or backgrounded tab: `Page.setWebLifecycleState` and `bringToFront` leave `document.visibilityState` "visible", `Emulation.setPageVisibilityOverride` is unsupported, frozen does not suspend timers. These facts are settled, do not re-probe them (#235 spent ~13 blocks on three probe scripts). Simulate a sleeping tab with an `addInitScript` `Date.now()` offset plus a dispatched `visibilitychange` while the real pending timer stays pending. Probe a NEW browser semantic with one script only, record the result in the ledger, move on.
- Detail-view card selectors: `#m-agent-btns > .agent-col > .agent-card` ALSO matches the doctor card, so a run-card query needs `:not(.agent-doctor)` or a waitForFunction never settles (#238). Light `--hover` is `rgba(233,237,242,.95)` since #240: `.agent-card:hover` is near-opaque but not alpha 1, `.card:hover` composites to alpha .8067 (`color(srgb 0.913725 0.929412 0.94902 / 0.806667)`). Measured hovered pixels over white (#240): `.card` rgb(237,240,244), `.agent-card`/`.tab`/`.toggle`/`#m-close` rgb(234,238,243), `#theme` rgb(233,238,243), rest pixel white. Compare against the composite, never against alpha 1. Computed `color-mix` alpha reads 0.806667, not the .8067 shorthand (8-bit quantization): assert with a tolerance, never string-equal to a derived value.

## Shell traps (each killed a run at least once)

- Never kill by pattern from the test's own shell: `pkill -f <pattern>` matches the shell itself when the cmdline contains the pattern, exit 143 (#168, #210-#212, #220); feeding `grep -o 'pid=[0-9]*'` output to `kill` hits the dead-pid `pid=0` bounce line (#211); `pgrep -x node` finds NOTHING on this machine (#204, #210); `pgrep -f 'sleep 600'` from the test's own bash matches the test shell (#178). Kill recorded pids only, and run cleanup as this exact sequence from one bash, no plan block: `kill $(cat $T/*.pid)` -> `pgrep -af /tmp/<t>` from a script file (abort on any pid outside your fixture: other live-testers run daemons on this machine) -> `ps -p <pid>` -> `ss -ltn | grep -F :<port>` for the freed port. Never a machine-wide `pkill -f orchestrator`: it kills the project's own daemon (#168). The real daemon runs from the symlinked extension path `~/.pi/agent/extensions/se-llm-team/src/orchestrator.ts`; killing the daemon and a `sh -c` wrapper can leave the agent shell reparented to PID 1: read `ps --ppid <wrapper>` before the kill and kill that child too (#208). A lone pgrep hit whose cmdline is the cleanup bash itself (it carries the literal fixture path) is your own shell: ignore it, no bracket-trick or `$$`-semantics derivation (#243 burned two thinking blocks on this; #246 re-derived the same point one run later).
- `$!` after `nohup ... &` records the subshell, not node (#187, #204): launch fixture daemons with `setsid nohup <launcher> &` so signals stay off the test shell, and have the launcher write its own pidfile, the cheap kill handle (#211, #231).
- An inline heredoc embeds the fixture path in the test shell's own cmdline: a cleanup loop that matches fixture paths must walk and skip the caller's ancestor chain (#211).
- Never put a single quote inside a single-quoted `node -e` argument in a heredoc: the shell cuts the script at the quote and the helper silently mangles its output, which reads as a bug in your own logic (#228). Write every node helper to a standalone `.mjs` file from the start. When a helper's output looks wrong, suspect shell mangling first: `cat -A` the raw output and run the helper standalone before you re-read your logic.
- Extract a frontmatter value with `sed -n 's/^state: *//p' | head -1 | tr -d '"'`: `grep -m1 '^state:' | tr -d ' "'` leaves the `state:` prefix and fakes FAILs (#229). An `sed -i` with unescaped slashes dies with `unknown option to 's'`: use the edit tool or a different delimiter (#229).
- Test helpers must handle missing files: a `count_in` over an absent log prints 0, not empty output (#229). Remove fixture pidfiles between runs of the same fixture dir: a leftover daemon pidfile makes the next run's pid assertions stale (#229). For a daemon fixture also delete `.kanban/.orchestrator.lock` and truncate `.kanban/.logs/orchestrator.log`, or a rerun passes on stale lines (#233).
- A daemon killed right after its first log line can miss its SIGTERM handler: `main()` logs `orchestrator started` and runs `bootstrapBoard` BEFORE it installs the SIGTERM/SIGINT handlers (#233). Wait ~1 s after the started line before SIGTERM.

## Report and run discipline

- Script every timing-sensitive test (kill mid-flight, poll windows, sleep races) before you run it: a hand-timed kill/restart missed the 6 s doctor sleep in #222; the scripted version passed first try.
- Keep a fixture ledger at /tmp/<t>/LEDGER.md: one line per artifact (files, pids, markers, deletions, task numbers), updated as each check lands. Name hand-written fixtures with FIXTURE in the file name. Counts and provenance come from the ledger, never from a re-scan of .logs; ledger every manual probe command with its timestamp (#229: four fake calls took three re-reads to explain). Keep a running evidence tally per task; never recount totals from scratch. Make every check script print its own tally (`N checks, M failed`) and take report counts from that output, never from a hand count (#230 wrote "38", the real count was 37).
- Draft the report in a scratch file as each phase passes, one bullet per verified fact; context compaction can erase context mid-run. Polish the draft and paste it into the task Notes at the end.
- Append to the task file under the existing `# Notes` as a `##` subsection: an `#` heading splits the section and forces a second edit pass (#226). Find the insert point FIRST with `grep -n '^#' <task file>` plus one tail read (an offset read past EOF errors, #247), and insert at the END of `# Notes`, just before the next top-level heading (usually `# Open questions`); when `# Notes` is the last top-level section, end of file IS the insert point and one append suffices (#231, #232; #236 spent six blocks pinning one insert point). Build edit `oldText` from the file read only, never from your own command transcript (an `echo` separator in shell output is not file content, #232); before an exact-match edit, read the target lines first (#230, #236: an unverified escaping guess cost a failed edit). Two identical lines in a script you generated this run (per-num route handlers, per-case blocks) are the usual non-unique oldText match: anchor the edit on a unique neighbouring line in the same batch (#246 re-issued a 4-edit batch after an abort line matched two locations). Pass the edit tool a plain path from cwd or a `readlink -f` realpath: a hand-built `..`-chain absolute path failed with ENOENT (#232). Verify placement with the heading grep (`grep -n '^#'`), not a grep for the new header text (#231); suffix appended-line markers with a timestamp so a rerun cannot pass on a stale marker.
- Never create a section: an empty `# Open questions` section is not a deliverable and no acceptance names one (#243 debated creating it). Verify each fact once, record it in the draft, move on. Re-grepping served pages, re-litigating what counts as a finding, re-reading your own report for wording, and re-printing a just-edited section cost real blocks (#226, #228, #232, #234, #236). Skip an unplanned check that maps to no acceptance bullet, note the skip in the report, move on (#229, #230). Do not re-resolve the map's symlink facts mid-run: one resolution is enough (#229: three blocks on the same SPECS.md symlink).
- An acceptance that names a unit test does not lift the suite ban: the suites stay developer/reviewer gates, so live-test the production surface the test pins instead (prompt files, exported functions, served text; #180, #184, #228).
- Role notes reach `meta/kanban` on the next `kanban: create`/`kanban: done` commit, only then; an idle board keeps them local.
- `kanban_update` rejects a `notes` field (additionalProperties: false in index.ts), so a `# Notes` decision block comes from a direct file edit, not the documented kanban_update path.
- An evidence field that prints empty usually means the grep matched the neighbouring line class (skip lines and failure lines carry similar text): print the matched line, then grep the exact failure text before you assume missing data (#229).

## Real-board daemon hygiene

- Do not drop `AGENTS.*.md` into the real `.kanban/` while a daemon started before this feature runs: its `listAll` has no filter and would promote the file to a phantom task and spawn a real agent.
- Do not trust a daemon hygiene claim from task notes: check the live daemon. `ps -o ppid= -p $(cat .kanban/.orchestrator.lock)` must show a `node --watch` supervisor, and `ps -o args= -p <ppid>` must contain `--watch`; identify the running daemon ONLY by its lock pid, PPID and supervisor argv. A bare daemon (PPID 1) runs pre-#192 code and will not restart on the next src/ merge, so the fix looks inert. `/api/hub.commit` is a live `git rev-parse` of the code checkout (src/hub.ts), so it shows the on-disk HEAD and does not prove which code the daemon loaded.
- Re-establish the hygiene only from a FRESH pi session: pi loads extensions at session start and picks up merged code only after `/reload`, so a long-lived session's `orchestrator_start` spawns an unwatched daemon and silently regresses the hygiene. The documented recovery is `orchestrator_stop` then `orchestrator_start` from the fresh session.
- Real-board daemon staleness (#187): after a merge that changes `src/orchestrator/`, the running daemon keeps the old code and the pipeline livelocks. The merged developer, merger and live-tester prompts no longer call `kanban_set_state`, and the old daemon has no exit-0 success move, so every successful finish is logged as "agent pid=<pid> dead without state update" and respawned; a task can never reach done. `orchestrator_start` alone is a no-op while a daemon runs: restart with `orchestrator_stop` then `orchestrator_start`, then confirm the daemon pid changed and "orchestrator started" is in `.kanban/.logs/orchestrator.log`. Check `ps -o lstart -p <pid>` against the merge commit time before trusting any real-board observation of the merged flow. In-flight agents survive the restart, but the old daemon spawned them without the exit-file wrapper, so the new daemon bounces each of them one last time before the respawn runs the merged code.

## Per-task recipes (condensed to technique plus trap; the canonical recipes above give the setup)

### Webui board, card, modal and CSS tests (hub-only recipe)
- Stats family (#169, #177, #178, #182, #183, #200): tokens = input+output summed over `turn_end`/`assistant` usage records (a NO-timestamp usage record still parses; `message_end` usage is NOT summed); duration = last-first record timestamps, live cards tick with wall clock (needs the 5.6 s first-poll wait). Card stats line is `.card[data-file=...] .card-stats`, the card's last element child; live card needs `state: "doing"` plus a live sleep pid. Seconds round once after summing (`3s`, `1m 2s`, `1h 1m 1s`); an exact hours run = a `session` record 3661 s before a `turn_end` usage record. A usage-less run renders duration only, no stats line; a finite numeric tokens field means usage-bearing (`0 · 3s`).
