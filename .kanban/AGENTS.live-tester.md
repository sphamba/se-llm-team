- `fake-pi` is a script that appends `"$@"` and its cwd to a log, records the `--append-system-prompt` path and its content, then sleeps, so the daemon sees a live agent and the real spawn argv is observable. The daemon `spawn`s the configured agent path directly, so the script needs a `#!/usr/bin/env node` shebang and `chmod +x`; a bare `.mjs` fails with `spawn ... EACCES`, the daemon logs "failed to start", and the task sits in `doing` with no pid.
- Agent-prompt docs test (task #170, ~1 min): the daemon reads `agents/<role>.md` beside its loaded `src/`, so the merged code in the real checkout serves the merged prompts without a scratch clone. Trigger all four roles in one sweep with four probe task files in this order: `to-do` (developer); `to-review` with `complexity: moderate` (reviewer, cap>0; `trivial` force-advances); `to-live-test` with `worktree: "<branch>"` where the branch exists and is an ancestor of HEAD (live-tester); `to-merge` with an existing branch (merger). Create both branches at HEAD, `ensureWorktree` reuses them. The to-live-test file must come before the to-merge one: the live-tester defers while a merger is alive. Then check each recorded `-p` payload against the shipped file with `{{ROOT}}` rendered and other placeholders as `.*`, so the rest of the text must match line for line.
- Never `pkill -f <pattern>` in the test's own `bash -c` command when the cmdline contains the pattern: it matches the shell itself and kills the test mid-run. Kill recorded pids only, or run from a script file.
- Never start a daemon without `--no-webui` or `SE_LLM_TEAM_NO_WEBUI=1`: it reads the global config and binds the production webui port (4242).
- The daemon loads its code at start: a merged orchestrator change is inert until the daemon restarts. Restarting does not kill running agents.
- Do not drop `AGENTS.*.md` into the real `.kanban/` while a daemon started before this feature runs: its `listAll` has no filter and would promote the file to a phantom task and spawn a real agent.
- Clean up: kill the scratch daemon and every fake-pi process when the test ends.

- Cleanup rule (learned the hard way in #168): kill only the pids you recorded (`kill $(cat $T/*.pid)`), then `pgrep -af /tmp/<t>`. Never run a machine-wide `pkill -f orchestrator` or `pkill -P 1 -f orchestrator.ts`: it also kills the project's own daemon (the one running the pipeline), and that outage is invisible until the next board poll. If it happens anyway, run `orchestrator_start` before any state transition.
- Kanban tool / createTask live test (#174, ~1 min, no daemon, no git, no scratch origin): the kanban_* tools use `ctx.cwd` as the board root, so `pi -p --no-session --no-context-files --approve --no-mcp --mode json "<prompt>"` with cwd in a fixture root runs the merged extension (symlinked to the real checkout) against `<fixture>/.kanban/`. The JSONL records `tool_execution_start` (args) and `tool_execution_end` (result) per call, so one pass proves the tool call and its result. Plain hand-written `NNNNNN_*.md` files are valid fixtures. True concurrency needs separate processes: 8 parallel `pi -p` sessions x 3 creates took ~20 s on 8 cores and gave 24 unique numbers, no lock failures. Lock branches: a `.create.lock` backdated 60 s is stolen and the create succeeds; a fresh lock held by a sleeping process for more than ~1 s makes the tool fail with `could not lock "<dir>" for task creation` (the wait loop is 100 x 10 ms, the steal threshold is 10 s).
