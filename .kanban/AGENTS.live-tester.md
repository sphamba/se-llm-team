# live-tester: role guidance

Live-test the merged diff: real usage paths on an isolated fixture, never the unit-test suites (developer/reviewer gates) and never the real board.

## Run order

- Plan once, then write the fixture: read the task, verify its Notes' merge hashes with ONE `git show --stat <h1> <h2>`; if no hash is named or it is absent (rebased fix), HEAD at task start IS the merge. For a removal/refactor the diff IS the surface spec — derive old-behavior asserts from the removed hunk.
- Ledger each verified fact once in `/tmp/<t>/LEDGER.md` as it lands. Every check script prints its own tally: quote tallies verbatim, never hand-sum. On FAIL diagnose the check script first — a script bug is not a product finding; right DOM with empty/offset measurement is a read-timing race — patch the read. Doubt about a written file is `node --check` in the next bash.

## Codebase map

- All `/api/*` routes register in `src/hub.ts` (never grep `src/webui*` for routes). `src/webui/page.ts` serves the whole client (PAGE template + all CSS); `board.ts` cards/chips/relations; `logpane.ts` log rendering; `payload.ts` /api/tasks, /api/task-detail (light), /api/task-history (heavy), /api/agent-log. `index.ts` registers every TOOLS entry — a new tool also needs a LABELS entry.
- `src/orchestrator.ts` is a facade (`main()` in `main.ts`). STATES sit atop `src/kanban.ts`; `to-live-test` vs `live-testing` are separate — a merge sets `to-live-test` and the sweep spawns you immediately, so the settled state is `live-testing`. Merge lane: rebase in the worktree (conflict spawns a merger), then `merge --ff-only` at the root. No `baseBranch` symbol: the base is the root checkout's current branch, resolved at runtime.
- Artifacts: run log `.kanban/.logs/<slug>.<role>.<n>.log` (`.gz` when finished), per-task pid `.kanban/.pids/<slug>.pid`, analysis wrapper `.pids/<slug>.<role>.<n>.analysis.pid/.exit`, PM reports `.kanban/.reports/<ts>.md` (oldest first).

## Canonical fixtures

- Hub-only (webui/CSS/modal): fixture root = `.kanban` files only, no git repo. Launch via a launcher file that writes its own pidfile (`setsid nohup … &`), importing `startHub` from the merged checkout. Isolated HOME mandatory (hub lock/registry per-HOME) plus `PLAYWRIGHT_BROWSERS_PATH=/home/phamba/.cache/ms-playwright`. Never production port 4242: pick the first free port above 4349 from one `ss -ltn` scan; if taken, take the next from it. Preflight `/api/hub` (match pid + commit) before any data curl.
- Daemon e2e: scratch origin = bare clone with BOTH `meta/kanban` refs deleted before every re-clone; fresh clone with `git config commit.gpgsign false`. Root config `{"agent": "<fake-pi>", "pollMinutes": 0.05, "autoScheduleMinutes": 0.05}`; the fake agent is an executable node script (shebang + `chmod +x`) logging argv+cwd, acting the role keyed on the prompt's first line (`-p` payload = shipped `agents/<role>.md` verbatim). Start merged code with `SE_LLM_TEAM_NO_WEBUI=1` and an isolated HOME; run the lifecycle from one teed run.sh in one bash call. Scope checks to fixture slugs; pair state with pid-alive checks (the daemon sets state before spawning — a broken agent path still passes). Leave fixture task files UNTRACKED so the to-merge rebase never refuses.
- Differential control (old vs merged, same fixture): `git archive <parent-commit> | tar -x -C /tmp/<t>/oldcode` (+ symlink node_modules if src imports externals), second hub on a second port, own isolated HOME. For negative assertions and no-behavior refactors; skip when the acceptance names only merged behavior.
- pi session probes need the REAL HOME (isolated HOME = no API key/symlink); always prefix `SE_LLM_TEAM_NO_WEBUI=1`. JSONL recipe: `pi -p --no-session --no-context-files --approve --no-mcp --mode json "<prompt>"` with cwd = a fixture git root; the extension loads from the main checkout, which must be at the merged commit. `tool_execution_start` carries args; `tool_execution_end` carries `result.content[0].text` + `durationMs`; filter tool records by name prefix, never count or index.
- Synthetic run logs: one JSON record per line, real shapes. pi: `session` (ISO ts), `turn_end` (numeric ms ts, `message.usage`), `message_update.assistantMessageEvent.text_start`/`text_delta`, `tool_execution_start`/`end` pairs. Claude: init, assistant thinking/text/tool_use, user tool_result, result record; tool records need a non-empty `toolCallId` on both. A live card needs state `doing` + a live sleep pid in `.kanban/.pids/<slug>.pid` (SIGKILL and reap your own child — a zombie answers `kill(pid,0)` too).

## Playwright discipline

- `import { chromium } from "/home/phamba/repos/paseo/node_modules/playwright/index.mjs"`. The modal overlay intercepts clicks: close with `#m-close`, wait for `#modal.hidden` with waitForFunction on classList (waitForSelector times out on hidden elements). `:hover` outranks active classes — `page.mouse.move(0,0)` before sampling styles. Board cadence 5 s, modal 1 s: skip ~5.6 s before measuring a tick or duration delta; wait out entrance fades/transforms before pixel and geometry reads.
- `:visible` must sit in the SAME selector string; hidden-by-default content needs `waitForSelector(..., {state:"attached"})`; collapsed `<details>` content is invisible to `innerText` (use `textContent` or expand). Computed `color-mix()` backgrounds come back as `color(srgb r g b / a)` with quantized alpha: parse channels with tolerance, never string-equal. Reduced-motion needs a `reducedMotion:"reduce"` context plus computed `animationName`, never a rule-text pin.
- Hold route responses to sample spinners/animations mid-flight; abort AFTER the sample point; a route-interception mode flag left in hold hangs every later fetch. Wrap per-element samples in try/catch; one probe per question. Headless Chromium cannot model a hidden/backgrounded tab (`visibilityState` stays "visible"): simulate with an `addInitScript` `Date.now()` offset plus a dispatched `visibilitychange` with `bubbles: true`.

## Shell traps

- Never kill by pattern: `pkill -f` matches your own shell (exit 143), `pgrep -x node` finds nothing here, machine-wide `pkill -f orchestrator` kills the project daemon. Cleanup: kill pidfile pids, then `pgrep -af /tmp/<t>` from a script file (abort on foreign pids), verify with `ps`/`ss`. A daemon's `sh -c` wrapper can reparent children — check `ps --ppid` first.
- Launch background helpers with `setsid nohup <launcher> &`; the launcher writes its own pidfile with a trailing newline (`$!` after nohup records the subshell). Kill pidfiles individually, and redirect every background helper's stdout or the `| tee` pipe hangs.
- Write node helpers as standalone `.mjs` files (no single quotes inside a single-quoted `node -e`). Recursive search is `rg -n` (`rg -r` is REPLACE). Never nest a grep inside a sed expression or use `sed -i` with unescaped slashes — use the edit tool. `diff` exits 1 on any difference and an exit-code check prints nothing: chain with `;`, judge by `$?`.
- Scope port checks to the fixture pid and anchor the port (`grep -E ':<port>( |$)')` — a bare `:42` substring-matches the project daemon's `:4242`. `git init` fixtures need `.kanban/.logs` and `-c commit.gpgsign=false`. Once the daemon's ensureInfoExclude names a path, a blanket `git add -A` silently skips it — commit with explicit paths. Daemon log lines are UTC ISO, fixture mtimes are local: never compare them directly.

## Report and board hygiene

- Report placement: append `## Live test (<date +%F>)` under the existing `# Notes`, before the next top-level heading; plain bullets, one per finding. Insert point from ONE `grep -n '^#' <task file>`; build `oldText` from the file read, never the command transcript; the edit tool takes an array of `{oldText, newText}`; verify with the heading grep in a later turn. `kanban_update` rejects a `notes` field — `# Notes` edits are direct file edits.
- Identify a running daemon only by its lock pid + `ps` (ppid/argv); `/api/hub` returns `{pid, root, commit}` (root = the serving checkout). To pick up merged code: `orchestrator_stop` then `orchestrator_start` from a fresh session.
