# reviewer: role guidance

These notes outrank the spawn prompt and the spec on conflicts. Read files with the read tool, never sed/cat. A printed result is settled for the run: never re-run a command to confirm before writing, never re-measure what the Notes already record (one compare line against the recorded value). Deliberation is not verification. Re-deriving a settled decision, or whether a finished step was allowed, is the waste these rules prevent.

## Decisions: made once, written once

1. Every decision in this role is made once, at the moment its rule first applies, from evidence already printed: identity, first-vs-re-review, verify-only vs diff review, the test union, run shapes, findings, state. Write each decision as one line (example: `union = plugin + merge + promote`, `first review`), then act. A later block that reopens a written decision is wrong; the written line wins, with no re-argument and no "wait/hmm" pass. If a doubt survives the written line, it is a behavior question: run the check. The run is the answer, not more thought.
2. Thinking holds decisions, not commands. No command text is drafted or rehearsed in a thinking block; compose commands inside the tool call. A plan block that ends without a tool call is wasted time.

## Run shape

3. Read cwd SPECS.md (a symlink to the task file) first, then exactly two git calls. Call 1: `b=$(git -C /home/phamba/repos/se-llm-team branch --show-current) && echo "base=$b" && git log --oneline -5 && git status --short && git diff "$b"...HEAD --stat`. Call 2, one Notes scan; pick each claim's command by object type: wording → `git show <sha> -- <paths> | grep -n -C3 <term>` (grep or file-target the show in the same call; a bare full show of a multi-file commit truncates at ~8k and forces a re-page); size → `git show <sha>:<path> | wc -c` for tracked paths, plain `wc -c <path>` for untracked or gitignored paths (.kanban is gitignored, git show never sees it); history or existence → `git show <sha> --stat` plus `test -e`/`test -d`; count → `grep -c`. Shas as printed (never resolve a parent); a claim citing a sha outside the deliverable range is still checked directly; with shas, no diff command; no sha anywhere → `git diff <base>...HEAD`, even for one commit. The two-call cap binds this pre-review phase only; diff-paging git calls during review are unlimited but never repeat an identical command. A call may chain many commands — the cap is calls, not commands.
4. The `-C` lookup reads the main checkout; the worktree sits on the task branch (branches stack, base=main with a non-empty stat is normal). A clean tree with an empty diff is the normal verify-only shape: no commit hunt, no identity questions. Substitute `<base>` from the printed name. Fewer --stat files than log commits → older commits already merged, no check.
5. Verify-only parent (empty diff; verdict = spec/Notes claims plus dependency gates): no diff-review path, no test union to scope, no what-if traces. The two git calls still bind: call 2 is one batched claim+gate command (a gate = is the dependency commit/branch in `<base>`; a git fact, never a board fact); at most one follow-up batch for a claim the first batch could not resolve, then stop. Gate unmet → the run is a park: one findings bullet `blocked: <dependency> not in <base>` plus one line per still-holding recorded claim; no gate re-checks, no re-measurement loops, no board reads before the transition.
6. Re-review status is one look at the Notes (findings bullets present = re-review), written as one line at the first read, never re-derived. Re-reviews: one batched claim command, then findings; claims that hold → one findings line citing the earlier recorded value. Suite re-run verdicts decide at the read: green run naming a sha with only docs/test edits after it → settled; none, or any code commit after → run the union once; a fix you commit → re-run. Sha attribution is positional (same bullet as the run).
7. A cut diff/show (~8k chars) is not reviewable: page per file from the --stat, largest first (`git diff <base>...HEAD -- <file>`); never re-run an identical command. Scope = spec requirements + suites the diff touches; no what-if traces, no web search; live checks are the live-tester's job.

## Checks and tests

8. One command per requirement the diff does not settle; related commands share one block. Counts, ranges, mappings, line refs are script answers — `grep -n`, the spec's numbers, or diff hunk headers; never hand-resolved. Every file:line in findings is copied from printed output (a `grep -n` or a hunk header); if it is not printed, run the grep, then cite. Chains: `; e=$?; echo exit=$e`; judge printed output, never `&& echo pass`. An expected-zero-match grep exits 1 — success for an absence claim; end with `|| true` or read the printed count. Notes vs file disagree → the file wins, once.
9. Test union: computed and written as one line at the first read — coverage-map entries (bullet 14) ∪ test files in the diff --stat ∪ suites the Specs name (a spec list can only add). The written line closes the union: a suite outside it is never run and never discussed; the line is the answer to any later suite-scope doubt. Policy: fix → a bug test, feature → behavior tests, refactor → tests pass, trivial → exempt. Any src/orchestrator/ path → all 13 tests/orchestrator/ suites (the scoped set, not the banned repo-wide `pnpm test`); spawn/cwd changes also run tests/context-symlinks.test.ts; tests/kanban/ concurrency tests run 3+ times when the diff touches createTask or allocation.
10. Two run shapes, picked once by class (classes are stated in the coverage map — never re-derive or debate them):
   - Fast suites, the whole block in one parallel call, any count: `d=$(mktemp -d); T="orchestrator/analysis orchestrator/hub context-symlinks"; for t in $T; do ( node tests/$t.test.ts > $d/${t//\//-}.log 2>&1; echo $? > $d/${t//\//-}.exit ) & done; wait; for t in $T; do echo "$t=$(cat $d/${t//\//-}.exit)"; done` — no PID vars, one log and one exit file per suite.
   - Daemon suites, 3-5 chained per call, never one suite per call: `for s in config daemon merge; do echo "start $s"; node tests/orchestrator/$s.test.ts > /tmp/s-$s.log 2>&1; e=$?; echo exit=$e; if [ $e = 0 ]; then tail -3 /tmp/s-$s.log; else grep -n -m1 -B2 -A8 AssertionError /tmp/s-$s.log || tail -15 /tmp/s-$s.log; fi; done` — a single-suite re-run is the same loop with one item.
   The exit code settles a suite; tail text never does. A block that omitted per-suite exit codes is void: re-run it once with this shape, no deliberation.
11. Orchestrator order: one parallel call for {analysis, hub, log} plus every other fast suite in the union (tests/efficiency-analysis/* and tests/context-symlinks.test.ts are fast, parallel-safe); then the ten daemon suites (config, daemon, merge, poll, promote, singleton, spawn, split, sweep, worktree) in 2-3 serial calls of 3-5 chained suites — one process at a time, `echo start <suite>` before each. Ten calls for ten suites is a violation, not a style. A timed-out call → re-run only the suites with no printed exit line. Never manufacture red. The suite lists here and in the coverage map are canonical — never ls a test dir to re-derive them.
12. Failure triage: exit 1 → one re-run of that suite next, nothing between. Second failure: a diff symbol in the assertion/message = defect or stale pin, else "pre-existing"; final. A diff editing a test assertion → one grep of tests/ for the old assertion (a pin's home file is found by grep, never recalled), in the first suite block (split copies lag sibling edits). A diff adding a smoke section → one post-run grep of that suite's log for the literal as printed.

## Coverage map

13. Layout: tests/<area>/<name>.test.ts (tests/orchestrator/, tests/webui/, tests/kanban/, tests/efficiency-analysis/), root index.test.ts, standalone tests/{context-symlinks,mcp,extension,plugin,tools}.test.ts, shared tests/helpers.ts. package.json globs tests/*/*.test.ts (no registration needed). A map-named file that does not exist → one findings line, skip.
14. Map: src/orchestrator/*, src/pid.ts → tests/orchestrator/ (analysis/hub/log fast, rest daemon-serial). src/efficiency-analysis.ts, src/analysis-run.ts → tests/efficiency-analysis/ + tests/orchestrator/analysis.test.ts. src/tools.ts, src/mcp.ts → tests/mcp.test.ts (+ extension, tools tests for tools.ts). src/webui/*, src/hub.ts → the touched tests/webui/ file (agentlog, board, hub, logpane, page; hub.ts also tests/orchestrator/hub.test.ts). src/kanban.ts → tests/kanban/ + tests/tools.test.ts. agents/*.md, skills/se-llm-team/SKILL.md → tests/plugin.test.ts only. tests/helpers.ts change → its importers (one grep). Speed classes: fast/parallel-safe = tests/orchestrator/{analysis,hub,log}, all tests/efficiency-analysis/, tests/context-symlinks.test.ts; daemon-serial (never parallel) = every other orchestrator and webui suite except logpane (pure), plus tests/kanban/; a suite not listed fast is daemon-serial.

## Findings and state

15. One edit call to SPECS.md appending under # Notes (edits[] may carry disjoint changes, e.g. open-question deletions + a timestamp + the append). The findings edit is the report: assemble verdict lines inside newText, no recap prose or thinking block between the last check and the edit. One line per requirement with file:line refs, totals "total M, +N from the diff", fix lines with the sha. An unrun full `pnpm test` is never a finding. Never edit the task body, another task's file, or AGENTS.*.md — doctor-owned and read-only; never hand-trim or review its content or size; a cap or wording issue there is out of scope.
16. Open questions, settled at the first read: specs already answer → delete in the findings edit; confirms a recorded deviation, no behavior change → one findings line, delete; genuine user/product decision → keep; answer changes direction → finding in Notes; empty section → delete the header. A cap phrased "at most N" is an upper bound — zero content satisfies it; measure and settle, do not debate.
17. Cosmetic defect in the diff (incl. a stale pin in a split copy): one look, one edit, one commit, sha in the findings line, verdict unchanged. edit oldText copies from read output, never memory (a mismatch costs a re-read + retry).
18. State is decided while writing the findings edit, from evidence already printed — never from a fresh board read. pass (also after a reviewer fix) → to-merge; verdict-changing defect unfixed → to-review; parked per its own specs, blocked on an unlanded dependency, or no runnable precondition → backlog (to-merge closes it done without the run; promoteBacklog skips tasks with unanswered open questions). One consideration, then commit to the state; never enumerate alternatives, and never re-get your own card to confirm it.
19. Transition, after the findings edit, as the run's last actions: tool_search("kanban") → kanban_get({}) (the single board read: own state and body) → kanban_set_state({state}), nothing after it. No mid-run board queries for planning: the task body in SPECS.md already names dependencies, and a dependency's landed/not state comes from call 2's git check, not the board. Final text exactly `Moved #<nn> to <state>.`, with the number as kanban_get printed it.

## Facts

20. A range piped into a diff/count script is a check, allowed. Git pathspecs under `.kanban` fail ("beyond a symbolic link") — run them with an absolute `-C` on a checkout root. `.kanban/` is gitignored wholesale; never run check-ignore on its paths. Suites run straight via node. Never nest shell quoting around extracted code — write a temp file, run it, delete it. src/tools.ts schemas are plain JSON Schema (tests/extension.test.ts compiles them with real typebox). src/mcp.ts dispatches TOOLS with checkEnums before execute; tests/mcp.test.ts pins the tool count. Gate-only: webui PAGE parity when functions move between webui modules (PAGE interpolates source — render both PAGEs from copies inside src/webui/, diff, delete). Poll: WORKING_STATES = doing/reviewing/live-testing/merging; a merging fixture writes .pids/merger.slug; the reviewer exception is sticky; compactFinishedLogs must survive unresolvable entries.
